Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

毎朝、接続済みのサンプルリポジトリで新しい Issue を要約させたいものの、ファイルの変更やプルリクエストの作成はまだ許可したくない状況を扱います。You want a connected sample repository to summarize new issues every morning, but you are not ready to let the automation change files or open pull requests yet.

担当者像Persona

繰り返し作業を自動化する担当者として、ローカルautomationsとトリガー設定を扱います。As someone automating repetitive work, this lab covers local automations and trigger configuration.

なぜ重要かWhy it matters: トリガー条件と最小権限を誤ると、意図しない大量実行や過剰な権限を持つ自動化が生まれます。Misconfigured trigger conditions and privileges create either unintended mass runs or an over-privileged automation.

Goals

学習目標Learning objectives

  • 繰り返しpromptをlocal automationとして保存するSave a repeatable prompt as a local automation
  • on-demand runとschedule runの境界を比較するCompare on-demand and scheduled local runs

Prepare

前提条件Prerequisites

  • ラボ01 に沿って GitHub Copilot App をインストールし、サインインして、変更してよいプロジェクトを1つ接続済みであること。The GitHub Copilot app is installed and signed in, and you have connected one project you are allowed to change, as covered in lab 01.
  • 接続したプロジェクトに Git リポジトリとしての履歴があり、.github/copilot-instructions.md などのプロジェクト個別の指示があれば内容を把握していること。The connected project has Git history, and you know the contents of any per-project instructions, such as .github/copilot-instructions.md, if present.
  • 自動化のスケジュールを機能させたい時間帯に、アプリと端末を起動したままにできること。ローカル自動化は端末とアプリのプロセスが動作しているときにしか実行されません。You can keep the app and machine running during the hours you want the schedule to fire. Local automations only run while the app process and machine are active.
  • 組織管理アカウントの場合、GitHub Copilot App ポリシーが有効になっており、自動化機能がブロックされていないこと。For organization-managed accounts, the GitHub Copilot app policy is enabled so the automations feature is not blocked.

Availability

公式な提供状況とスコープOfficial availability and scope

提供状況Availability

v1.1.4 版として再公開。中核フローは v1.1.2 で検証され、v1.1.3 / v1.1.4 差分と情報源を source-check しています。ローカル自動化はアプリを使えるすべての Copilot プランで利用でき、v1.0.14 以降は対話セッションと同じ Settings とプロジェクト個別の指示を使用します。Republished for v1.1.4. The core flow was verified for v1.1.2; v1.1.3/v1.1.4 deltas and source provenance were checked. Local automations are available to any Copilot plan that can run the app, and since v1.0.14 they use the same Settings and per-project instructions as an interactive session.

対象範囲Feature boundary

このガイドは GitHub Copilot App の「Automations」タブで作成するローカル自動化（「Run in the cloud」をオフのまま）を扱います。同じ画面から作成できるクラウド自動化はラボ17の隣接領域として扱い、GitHub Actions のスケジュール実行や Copilot CLI 独自の定期実行の仕組みはこのガイドの対象外です。This guide covers local automations created from the GitHub Copilot app's Automations tab with Run in the cloud left off. Cloud automations created from the same screen are treated as the adjacent surface covered in lab 17; GitHub Actions scheduled workflows and Copilot CLI's own recurring-task mechanisms are out of scope here.

時間の見積もりTime estimate

hands-on操作の目安は約45分です。schedule到来、cloud session start、service latencyは含まず、検証を複数回に分ける場合があります。Hands-on work is estimated at about 45 minutes. This excludes schedule windows, cloud-session startup, and service latency, so verification may span multiple sittings.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: 自動化のプロンプトやフィルターにシークレットや個人情報を含めないでください。ローカル自動化は対話セッションと同じ権限で実行されるため、破壊的な操作を許可する前に低リスクな読み取り専用プロンプトで検証してください。Never put secrets or personal data in an automation's prompt or filters. Local automations run with the same permissions as an interactive session, so validate with a low-risk, read-only prompt before allowing destructive actions.

Hands-on

手順Steps

  1. 1. プロジェクトの指示とスケジュールの前提を確認するConfirm project instructions and scheduling assumptions

    自動化は対話セッションと同じ Settings とプロジェクト個別の指示を使います（v1.0.14 以降）。まず接続済みプロジェクトに指示ファイルがあるか確認します。Automations use the same Settings and per-project instructions as an interactive session, since v1.0.14. First confirm whether the connected project has an instructions file.

    プロジェクトの指示ファイルを確認Verify the project instructions file 
    git ls-files .github/copilot-instructions.md
    この段階で期待される状態Expected state after this phase: コマンドの出力でファイルの有無が分かり、自動化が参照する指示の内容を把握できます。The command output shows whether the file exists, so you know what instructions the automation will draw on.

  2. 2. Automations タブを開くOpen the Automations tab

    サイドバーの Automations を開くか、下のランチャーで安全に開きます。保存済みの自動化には名前、スケジュール、対象リポジトリ、最終実行ステータスが表示されます。Open Automations from the sidebar, or use the launcher below to open it safely. Saved automations show their name, schedule, associated repository, and last run status.

    この段階で期待される状態Expected state after this phase: Automations 画面が開き、まだ何も保存していない場合は一覧が空です。The Automations screen opens, showing an empty list if you have not saved anything yet.

  3. 3. 新しいローカル自動化を作成するCreate a new local automation

    New automation をクリックし、名前を付けます。Run in the cloud はオフのままにして、ローカル自動化として作成します。Click New automation and give it a name. Leave Run in the cloud off so it is created as a local automation.

    この段階で期待される状態Expected state after this phase: 作成ダイアログでローカル実行が選択された状態になっています。The creation dialog shows local execution selected.

  4. 4. トリガーとプロンプトを設定するConfigure the trigger and prompt

    トリガーを Manual または On a schedule（hourly/daily/weekly）から選び、下のプロンプトのように読み取り専用の指示を入力します。シークレットは入力しません。Choose Manual or On a schedule (hourly, daily, or weekly) as the trigger, and enter a read-only instruction like the prompt below. Do not enter any secrets.

    ローカル自動化の読み取り専用プロンプトLocal automation's read-only prompt 
    Draft a short summary of new issues opened in the last 24 hours. Do not push changes or open a pull request.
    ローカル自動化の読み取り専用プロンプト（日本語）Local automation's read-only prompt (Japanese) 
    過去24時間に作成された新しい Issue の要約を短くまとめてください。変更のプッシュやプルリクエストの作成は行わないでください。
    この段階で期待される状態Expected state after this phase: トリガーとプロンプトが保存内容に反映されています。The trigger and prompt are reflected in what you are about to save.

  5. 5. 保存して手動で1回テストするSave it and test it manually once

    Create and run を選び、保存と同時に手動実行してテストします。端末とアプリが起動していることを確認してから実行してください。Choose Create and run to save and immediately trigger a manual test. Confirm the machine and app are running before you run it.

    この段階で期待される状態Expected state after this phase: テスト実行のセッションが開始され、ファイル変更なしで要約が返ってきます。A test-run session starts and returns a summary without changing any files.

  6. 6. Recent runs で実行状況を確認するCheck run status in Recent runs

    実行中は Recent runs に running インジケーターが表示され、Running でフィルターできます（v1.0.25 以降）。完了後はステータスと実行時間を確認します。While running, the run shows a running indicator in Recent runs and can be filtered by Running status, since v1.0.25. After it finishes, check its status and duration.

    この段階で期待される状態Expected state after this phase: 実行履歴に成功ステータスが記録されています。The run history records a successful status.

  7. 7. スケジュールと端末の起動状態の関係を確認するConfirm how the schedule depends on the machine being on

    アプリまたは端末を閉じた状態で予定時刻を1回迎えさせ、次にアプリを開いたときに実行が行われていないことを確認します。ローカル自動化は端末が起動している間しか動きません。電源が切れていても実行させたい場合はラボ17のクラウド自動化を検討してください。Let one scheduled time pass while the app or machine is closed, then confirm on your next launch that the run did not happen. Local automations only run while the machine is on; if you need it to run while your computer is off, consider the cloud automation in lab 17.

    この段階で期待される状態Expected state after this phase: 端末オフ中の予定時刻はスキップされ、次回の予定時刻に正常に実行されます。The scheduled time while the machine was off is skipped, and the next scheduled time runs normally.

Decide

判断点Decision points

  • 今すぐon demandで実行するか、daily / weekly scheduleにするか。Run on demand now, or use a daily/weekly schedule?
  • local machineに置けるdataだけを扱っているか、cloud automationへ移す必要があるか。Is all data safe for local execution, or should the workflow move to cloud automation?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: on-demand runが新しいsessionを開始し、期待したoutputを残す。Checkpoint 1: the on-demand run starts a session and produces the expected output.
  • チェックポイント2: scheduleとlast-run statusを確認し、computer / App停止中の制約を説明できる。Checkpoint 2: you inspect the schedule and last-run status and can explain the computer/App availability constraint.

Verify

完了時の確認Completion checks

  • Automations 一覧に名前・スケジュール・対象プロジェクト・最終実行ステータスを持つローカル自動化が表示される。The Automations list shows the local automation with its name, schedule, target project, and last run status.
  • 手動テスト実行が Changes に変更を残さず完了し、プロンプトにシークレットが含まれていない。The manual test run completes without leaving changes in Changes, and the prompt contains no secrets.
  • 実行中は Recent runs に running インジケーターが表示され、Running でフィルターできる。While running, Recent runs shows a running indicator and can be filtered by Running status.
  • 端末やアプリが起動していない予定時刻には実行されず、次にアプリを開いたときにその欠落を確認できる。The automation does not run at a scheduled time while the machine or app is off, and you can confirm the miss the next time you open the app.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

local automationはこのmachineに保存されたpromptとscheduleからlocal sessionを開始します。repository eventを受けるcloud automationとは違い、local environmentとAppの稼働状態に依存します。A local automation starts a local session from a prompt and schedule stored on this machine. Unlike a cloud automation that reacts to repository events, it depends on the local environment and app availability.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

予定した時刻に自動化が実行されなかったThe automation did not run at the scheduled time

端末がスリープ状態だったか、アプリが終了していた可能性があります。ローカル自動化は端末とアプリが動作している間だけ実行されるため、電源が切れていても実行したい場合はラボ17のクラウド自動化に切り替えてください。The machine may have been asleep, or the app may have been closed. Local automations only run while the machine and app are active, so switch to the cloud automation in lab 17 if you need it to run while your computer is off.

自動化がプロジェクト個別の指示を無視しているように見えるThe automation seems to ignore per-project instructions

v1.0.14 より前は、ローカル自動化が Settings とプロジェクトの指示を正しく参照しない不具合がありました。v1.1.4（最新版） に更新し、指示ファイルがプロジェクトルートの想定パスにあるか確認してください。Before v1.0.14, local automations had a bug where they did not correctly use Settings and project instructions. Update to the latest version (v1.1.4) and confirm the instructions file is at the expected path in the project root.

権限プロンプトに答えた後もセッションが応答しなくなったThe session stopped responding after answering a permission prompt

拡張機能フックなどの権限プロンプトに答えた後、セッションが固まる不具合が v1.1.0 で修正されています。v1.1.4（最新版） に更新し、再現する場合はアプリを再起動してください。A bug where a permission prompt, such as one for enabling extension hooks, could leave a session unresponsive after being answered was fixed in v1.1.0. Update to the latest version (v1.1.4) and restart the app if it recurs.

自動化から始まったセッションにレビューパネルや Create PR ボタンが表示されないA session started by an automation shows no review panel or Create PR button

自動化開始のセッションでレビューパネルやパネル切り替え、Run / Open in / Create PR ボタンがアプリ再起動まで欠落する不具合が v1.1.0 で修正されました。v1.1.4（最新版） に更新し、直っていない場合はアプリを再起動してください。A bug where sessions started by an automation could get stuck with no review panel, panel toggle, or Run / Open in / Create PR buttons until the app restarted was fixed in v1.1.0. Update to the latest version (v1.1.4) and restart the app if the panel is still missing.

Recovery path

明示的な復旧手順Explicit recovery path

runが始まらない場合はautomationがenabledか、scheduleとtimezoneが正しいか、Appとmachineが稼働していたかを確認し、まずon-demand runでprompt自体を切り分けます。If a run does not start, check whether the automation is enabled, verify schedule and time zone, confirm the app and machine were running, and use an on-demand run to isolate whether the prompt itself works.

Reset

クリーンアップとリセットCleanup and reset

  1. テスト用のローカル自動化はコンテキストメニューから無効化するか削除します（v1.0.24 以降、一覧から直接切り替え可能です）。Disable or delete the test local automation from its context menu; since v1.0.24 you can toggle it directly from the list.
  2. テスト実行で作成されたセッションをアーカイブまたは削除し、必要な会話や変更がないことを確認します。Archive or delete the sessions created by test runs after confirming they contain no conversation or changes you need.
  3. テストのために作成したブランチや worktree が残っていれば削除します。Delete any branch or worktree that was created only for this test, if one remains.
  4. スケジュールを本番向けに切り替える前に、テストのために短縮した hourly トリガーなどを意図した間隔に戻します。Before treating the schedule as production-ready, revert any trigger you shortened for testing, such as an hourly interval, back to its intended interval.

発展課題Stretch exercise

変更ファイルパスの条件を追加し、条件に一致しない変更では自動化が起動しないことを確認してください。Add a changed-file-path condition and confirm the automation does not fire for a change that does not match it.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows では x64/ARM64 のセットアップ実行ファイルでアプリ本体を実行します。WSL 内のリポジトリを対象にする場合でも、スケジュールを機能させるにはアプリ自体が起動している必要があります。On Windows, the app itself runs from the x64/ARM64 setup executable. Even when the target repository lives inside WSL, the app process itself must stay running for the schedule to fire.

macOS

macOS ではエナジーセーバーの設定でアプリがスリープ後に終了しないよう確認してください。予定時刻の直前にスリープしていると実行がスキップされます。On macOS, check your Energy Saver settings so the app is not terminated after sleep; if the machine is asleep at the scheduled time, the run is skipped.

Linux

Linux では AppImage 版を使う場合、ログイン後にアプリを自動起動する設定をしておくと、再起動後もスケジュールが継続しやすくなります。On Linux, if you use the AppImage build, configure it to auto-start after login so the schedule keeps working across reboots.

WSL

WSL リモート環境を対象にする場合でも、ローカル自動化を動かす GitHub Copilot App のプロセス自体は Windows ホスト側で起動している必要があります。v1.1.2 では WSL リモート環境に GitHub の Issue/PR ワークフロースキルも追加されています。Even when targeting a WSL remote environment, the GitHub Copilot app process that runs the local automation still runs on the Windows host. In v1.1.2, WSL remote environments also gained GitHub pull request and issue workflow skills.
