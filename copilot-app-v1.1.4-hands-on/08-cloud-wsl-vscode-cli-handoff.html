Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

WSL内のサンプルリポジトリでAppから調査セッションを開始し、途中でVS Codeに切り替えてコードを詳しく読み、最後はCopilot CLIのターミナルから同じリポジトリで作業を続けます。合わせてクラウドサンドボックスでの実行も比較します。Start an investigation session from the app against a sample repository inside WSL, switch to VS Code partway through to read the code more closely, then continue the same repository's work from a Copilot CLI terminal. Along the way, compare this with running a session in a cloud sandbox.

担当者像Persona

複数OSとWSLをまたいで作業するエンジニアとして、プラットフォーム差を確認します。As an engineer working across multiple OSes and WSL, confirm platform-specific differences.

なぜ重要かWhy it matters: プラットフォームごとの差異を知らないと、WSLやVS Code handoffで想定と異なる挙動に遭遇し、原因調査に時間がかかります。Not knowing platform-specific differences leads to unexpected behavior in WSL or VS Code handoff, wasting time on root-cause investigation.

Goals

学習目標Learning objectives

  • WSLリモート環境でセッションを実行するRun a session in a WSL remote environment
  • VS Codeへのhandoffを行うPerform a handoff to VS Code
  • Copilot CLIとの境界（隣接製品）を区別するDistinguish the boundary from Copilot CLI as an adjacent product

Prepare

前提条件Prerequisites

  • Windows上でWSLが有効になっており、対象のサンプルリポジトリがWSL側のファイルシステムにクローンされていること。WSL is enabled on Windows and the sample repository is cloned inside the WSL filesystem.
  • VS Codeがインストールされ、ターミナルから起動できること。VS Code is installed and can be launched from a terminal.
  • Copilot CLIがインストール・サインイン済みで、隣接する製品サーフェスとして利用できること。Copilot CLI is installed and signed in, available as an adjacent product surface.
  • クラウドサンドボックスを試す場合、組織またはエンタープライズでCloud Sandbox accessポリシーが有効であること。If you want to try a cloud sandbox, the Cloud Sandbox access policy is enabled for your organization or enterprise.

対象範囲Feature boundary

このガイドは GitHub Copilot App のセッション実行先の切り替えと、VS Codeで開く・別ターミナルで続けるという受け渡し操作を扱います。Copilot CLI自体のインストールやログイン、CLI固有のスラッシュコマンドの詳細は隣接する製品サーフェスの機能であり、App自体はこのCopilot CLI上に構築されていますが、CLIの導入手順はここでは扱いません。SDKでの自動化も対象外です。This guide covers switching where a GitHub Copilot app session runs, and handing off to VS Code or a separate terminal. Installing and signing in to Copilot CLI itself, and CLI-specific slash command details, are an adjacent product surface — the app is built on top of Copilot CLI, but its installation steps are out of scope here. SDK-based automation is also out of scope.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: WSLやクラウドサンドボックスでの作業を切り替える際、資格情報やAPIキーをターミナル履歴やプロンプトにそのまま貼り付けないでください。クラウドサンドボックスは従量課金のため、使い終わったセッションは削除して不要な費用を避けます。When switching between WSL and cloud sandbox work, never paste credentials or API keys directly into terminal history or prompts. Cloud sandboxes are billed by usage, so delete sessions you're done with to avoid unnecessary charges.

Hands-on

手順Steps

  1. 1. WSLプロジェクトの接続を確認するConfirm the WSL project connection

    Settingsのプロジェクト一覧を開き、WSL上のリポジトリが接続されていることを確認します。Open the project list in Settings and confirm the WSL-hosted repository is connected.

    この段階で期待される状態Expected state after this phase: プロジェクトがWSLリモート環境として表示され、Appそのものは引き続きWindows側にインストールされています。The project shows as a WSL remote environment, and the app itself remains installed on the Windows side.

  2. 2. WSLのリポジトリでセッションを開始するStart a session against the WSL repository

    要約プロンプトを使ってセッションを開始します。Start a session using the summary prompt.

    WSLセッション用の要約プロンプトWSL session summary prompt 
    Summarize this repository's build and test commands so I can continue the same investigation later from Copilot CLI or VS Code, without changing any files.
    WSLセッション用の要約プロンプト（日本語）WSL session summary prompt (Japanese) 
    後でCopilot CLIやVS Codeから同じ調査を続けられるように、このリポジトリのビルドコマンドとテストコマンドを要約してください。ファイルは変更しないでください。
    この段階で期待される状態Expected state after this phase: セッションがWSLリモート接続経由でリポジトリを調査し、v1.1.2のGitHub PR/Issueワークフロースキルが利用可能です。The session investigates the repo through the WSL remote connection, and v1.1.2's GitHub PR/issue workflow skills are available.

  3. 3. 同じセッションをVS Codeで開くOpen the same session in VS Code

    「Open in VS Code」の操作を使います。Use the "Open in VS Code" action.

    この段階で期待される状態Expected state after this phase: VS Codeが常に新しいウィンドウで開き、そのセッションのブランチが表示されます（既存ウィンドウは再利用されません）。VS Code opens in a new window at the session's branch, instead of reusing an existing window.

  4. 4. VS Codeでコードを確認するRead and cross-check code in VS Code

    エージェントが変更したファイルをVS Codeで開いて確認します。Open a file the agent changed and inspect it in VS Code.

    この段階で期待される状態Expected state after this phase: ファイルの内容が、Appの Changes タブに表示されていた内容と一致します。The file matches what the app's Changes tab showed for that session.

  5. 5. Copilot CLIへのハンドオフを理解するUnderstand the handoff to Copilot CLI

    App自体がCopilot CLI上に構築されていることを踏まえ、同じブランチに対してcopilotターミナルからも同等の作業を続けられることを確認します。Given that the app is built on Copilot CLI, confirm you could continue equivalent work against the same branch from a copilot terminal.

    この段階で期待される状態Expected state after this phase: CLIは別の製品サーフェスであり、同じエージェント基盤を共有するため、切り替えは自動同期ではなく意図的なハンドオフであると理解できます。You understand that the CLI is a separate surface sharing the same underlying agent runtime, so switching between them is a deliberate handoff, not automatic sync.

  6. 6. クラウドサンドボックスと比較するCompare with a cloud sandbox session

    同じリポジトリでAppのCloud sandbox（Public preview）を選んだ新しいsessionを開始して、WSL/local machineとは別のGitHub-hosted environmentであることを確認します。組織管理アカウントではCloud Sandbox access policyが必要です。Start a new app session for the same repository using Cloud sandbox (public preview) and confirm it is a GitHub-hosted environment distinct from WSL or the local machine. Organization-managed accounts require the Cloud Sandbox access policy.

    隣接するCopilot CLIで同等のcloud-backed sessionを開始する場合はexperimental featuresを有効にした copilot --cloud --experimental が必要です。これはAppの実行先selectorとは別のCLI操作です。For the adjacent Copilot CLI, starting an equivalent cloud-backed session requires experimental features via copilot --cloud --experimental. This is a CLI operation, separate from the app's run-location selector.

    クラウドサンドボックスをCLIから起動Start a cloud sandbox from the CLI 
    copilot --cloud --experimental
    この段階で期待される状態Expected state after this phase: クラウドサンドボックスセッションはWSLやローカルマシンとは別の、GitHubがホストする隔離されたLinux環境で動作し、別のデバイスから再開できます。The cloud sandbox session runs in an isolated GitHub-hosted Linux environment rather than WSL or your local machine, and remains resumable from another device.

  7. 7. CLI専用のローカルサンドボックス化を確認するNote the CLI-only local sandboxing option

    Copilot CLIのlocal sandboxingはexperimental featureです。CLI sessionで/experimental onを実行してから/sandbox enableを使います。macOS、Linux、Windows Insiders buildsで利用でき、Appの実行先selectorとは別物です。Copilot CLI local sandboxing is experimental. Run /experimental on in the CLI session before /sandbox enable. It is available on macOS, Linux, and Windows Insiders builds and is distinct from the app's run-location selector.

    CLIのローカルサンドボックス化を有効にするEnable CLI local sandboxing 
    /experimental on
/sandbox enable
    この段階で期待される状態Expected state after this phase: これがCopilot CLIの機能であり、Appのメニュー操作ではないことを説明できます。You can explain that this is a Copilot CLI capability, not an app UI toggle.

  8. 8. WSL接続とWindows terminal環境を別々に確認するVerify WSL connectivity and Windows terminal environment separately

    ネットワークを一時的に切ってから再接続し、WSLセッションが復旧することを確認します。Briefly disconnect and reconnect your network, then confirm the WSL session recovers.

    Windowsを使っている場合は、WSL sessionとは別に新しいWindows integrated terminalを開き、既存のPowerShell profileで設定済みのPATHや環境変更（例えばfnm管理のNode）が反映されるか確認します。profile自体をこの演習のために変更する必要はありません。これはv1.1.4のWindows terminal改善で、WSL接続とは別の実行境界です。On Windows, separately from the WSL session, open a new Windows integrated terminal and check whether PATH or environment changes already configured by your PowerShell profile (for example an fnm-managed Node version) are present. Do not edit the profile just for this exercise. This v1.1.4 Windows-terminal improvement is a separate execution boundary from WSL connectivity.

    この段階で期待される状態Expected state after this phase: WSL remote sessionの再接続を確認し、Windowsでは別途、integrated terminalが既存のPowerShell profile環境を読み込むことを観察できる。You confirm the WSL remote session reconnects and, separately on Windows, observe the integrated terminal loading the existing PowerShell-profile environment.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

WSLリモートセッションはWindows側のアプリ本体からLinuxサブシステム内のリポジトリへ接続を張り、VS Code handoffはセッションのworktreeパスをそのままエディターに渡します。A WSL remote session connects from the Windows-hosted app into a repository inside the Linux subsystem, and VS Code handoff passes the session's worktree path directly to the editor.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

VS Codeを開くと既存のウィンドウが再利用されて混乱するOpening VS Code seems to reuse an existing window and gets confusing

v1.1.4 現在、セッションを VS Code で開くと常に新しいウィンドウが開きます。古いVS Code版やキャッシュされた設定が残っている場合はVS Codeとアプリを両方更新してください。As of v1.1.4, opening a session in VS Code always opens a new window. If it still reuses one, update both VS Code and the app in case an older cached setting is involved.

WSLリモートセッションの接続が不安定The WSL remote session connection feels unstable

v1.1.2の接続信頼性の改善を反映するため、Appを最新版に更新してください。改善後も続く場合は、WSLディストリビューションを再起動してから再接続します。Update the app to the latest version to pick up v1.1.2's connection reliability improvements. If it persists, restart the WSL distribution and reconnect.

クラウドサンドボックスの選択肢が出ない、またはCopilot CLIから--cloudが使えないThe cloud sandbox option doesn't appear, or --cloud isn't available from Copilot CLI

組織またはエンタープライズ管理者にCloud Sandbox accessポリシーの有効化を依頼してください。Copilot CLI自体のサインイン状態も確認します。Ask an organization or enterprise admin to enable the Cloud Sandbox access policy, and confirm Copilot CLI itself is signed in.

Recovery path

明示的な復旧手順Explicit recovery path

WSL接続が不安定な場合は、v1.1.2 以降へ更新してアプリを再起動し、WSL distribution の状態を確認してから再接続します。Windows integrated terminal の PowerShell profile 反映は別の実行境界であり、WSL接続の診断には使いません。If the WSL connection is unstable, update to v1.1.2 or later, restart the app, verify the WSL distribution is running, and reconnect. PowerShell-profile pickup in the Windows integrated terminal is a separate execution boundary and is not a WSL connectivity diagnostic.

Reset

クリーンアップとリセットCleanup and reset

  1. WSLとクラウドサンドボックスの両方で作成したテストセッションをアーカイブまたは削除します。Archive or delete the test sessions you created in both WSL and the cloud sandbox.
  2. クラウドサンドボックスセッションは削除するとスナップショットも失われ復元できないため、必要な変更がないか確認してから削除します。Deleting a cloud sandbox session also removes its snapshot and cannot be recovered, so confirm you don't need any of its changes before deleting.
  3. VS Codeで開いた追加のウィンドウを閉じ、Copilot CLIのターミナルセッションも終了します。Close the extra VS Code window you opened and end the Copilot CLI terminal session.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows本体にAppをインストールし、WSL内のリポジトリはリモート接続経由で扱います。VS Codeも通常はWindows側から起動します。Install the app on Windows itself and work with WSL-hosted repositories through the remote connection. VS Code is also normally launched from the Windows side.

macOS

macOSにはWSLはありませんが、クラウドサンドボックスとVS Code、Copilot CLIへのハンドオフは同様に機能します。macOS has no WSL, but handoff to a cloud sandbox, VS Code, and Copilot CLI works the same way.

Linux

Linuxでも同様にクラウドサンドボックスとVS Code、Copilot CLIへのハンドオフができます。WSLの手順はWindows固有です。Linux supports the same handoff to a cloud sandbox, VS Code, and Copilot CLI. The WSL steps are Windows-specific.

WSL

v1.1.2のWSLリモート環境にはGitHub プルリクエスト/Issueワークフロースキルと接続信頼性の改善が含まれます。App自体はWindows側にインストールしたままにしてください。v1.1.2's WSL remote environments include GitHub pull request/issue workflow skills and connection reliability improvements. Keep the app itself installed on the Windows side.
