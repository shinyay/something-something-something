Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

プライベートなサンプルリポジトリで、毎晩 main ブランチの失敗テストを確認し、安全な修正案を下書き PR として提案させたい状況を扱います。You want a private sample repository to check for failing tests on main every night and propose a safe fix as a draft pull request.

担当者像Persona

繰り返し作業を自動化する担当者として、cloud automationsとポリシー依存の可用性を扱います。As someone automating repetitive work, this lab covers cloud automations and their policy-dependent availability.

なぜ重要かWhy it matters: トリガー条件と最小権限を誤ると、意図しない大量実行や過剰な権限を持つ自動化が生まれます。Misconfigured trigger conditions and privileges create either unintended mass runs or an over-privileged automation.

Prepare

前提条件Prerequisites

  • 対象リポジトリがプライベートまたは内部であること。クラウド自動化はパブリックリポジトリでは利用できません。The target repository is private or internal. Cloud automations are not available in public repositories.
  • その組織で Copilot cloud agent ポリシーが有効になっており、Business/Enterprise の場合は管理者が有効化していること。The Copilot cloud agent policy is enabled for the organization, and an administrator has enabled it for Business or Enterprise plans.
  • 対象リポジトリに書き込み権限（write access）があること。自動化を作成できるのは書き込み権限を持つユーザーだけです。You have write access to the target repository. Only users with write access can create automations.
  • Copilot Pro、Pro+、Max、Business、Enterprise のいずれかのプランを利用していること。You are on the Copilot Pro, Pro+, Max, Business, or Enterprise plan.

対象範囲Feature boundary

このガイドは GitHub Copilot App の Automations 画面で「Run in the cloud」を有効にして作成するクラウド自動化を扱います。同じ自動化はリポジトリの GitHub.com 上の Agents タブからも作成できますが、それは App とは別のクライアント面として触れるにとどめます。ローカル自動化（ラボ16）や GitHub Actions のスケジュール実行（ラボ14 の CI とは別物）は対象外です。This guide covers cloud automations created from the GitHub Copilot app's Automations screen with Run in the cloud enabled. The same automations can also be created from a repository's Agents tab on GitHub.com, which is only mentioned as an adjacent client surface. Local automations (lab 16) and GitHub Actions scheduled workflows (distinct from the CI in lab 14) are out of scope.

hands-on操作の目安は約60分です。schedule到来、cloud session start、service latencyは含まず、検証を複数回に分ける場合があります。Hands-on work is estimated at about 60 minutes. This excludes schedule windows, cloud-session startup, and service latency, so verification may span multiple sittings.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: プロンプトや検索クエリにシークレットを含めないでください。クラウド自動化が開始するセッションのログとプロンプトは、そのリポジトリにアクセスできる全員に見えます。機密値は Copilot cloud agent のリポジトリシークレットとして渡してください。 automation definition は作成者だけに見えますが、それが開始した session、log、pull request は repository access を持つ人に見えます。automation PR は作成者に帰属するため、その作成者自身は承認できません。Never include secrets in a prompt or search query. The prompt and session logs started by a cloud automation are visible to everyone with access to the repository. Pass sensitive values as Copilot cloud agent repository secrets instead. The automation definition is visible only to its creator, while the sessions, logs, and pull requests it starts are visible to people with repository access. Automation pull requests are attributed to the creator, who therefore cannot approve them.

Hands-on

手順Steps

  1. 1. リポジトリの公開設定と権限を確認するConfirm repository visibility and permissions

    クラウド自動化はプライベートまたは内部リポジトリでのみ有効です。下のコマンドで対象リポジトリの visibility を確認し、自分に書き込み権限があることも確認します。Cloud automations only work on private or internal repositories. Use the command below to confirm the target repository's visibility, and confirm you have write access.

    リポジトリの公開設定を確認Verify repository visibility 
    gh repo view OWNER/REPO --json visibility
    この段階で期待される状態Expected state after this phase: visibility が private または internal と表示され、書き込み権限があることが分かります。The visibility shows private or internal, and you confirm you have write access.

  2. 2. Automations 画面を開くOpen the Automations screen

    アプリの Automations タブを開くか、下のランチャーで開きます。同じ画面はリポジトリの GitHub.com 上の Agents タブの Automations パネルからも開けますが、ここではアプリから進めます。Open the app's Automations tab, or use the launcher below. The same screen is also reachable from the Agents tab's Automations pane on the repository's GitHub.com page, but continue from the app here.

    この段階で期待される状態Expected state after this phase: Automations 画面が開き、New automation ボタンが見えます。The Automations screen opens and the New automation button is visible.

  3. 3. New automation でトリガーを選ぶ（スマート検索を利用）Choose a trigger in New automation, using smart search

    Manual、On a schedule、When an issue is created、When a pull request is opened/synchronized から1つ以上選びます。v1.1.2 では、クエリ欄を持つトリガーが Issue トリガーと同じスマート検索の入力になり、修飾子のオートコンプリートとヒントテキストが使えます。Choose one or more triggers from Manual, On a schedule, When an issue is created, and When a pull request is opened or synchronized. In v1.1.2, triggers with a query field use the same smart search input as issue triggers, with qualifier autocomplete and hint text.

    この段階で期待される状態Expected state after this phase: 選んだトリガーにクエリ欄がある場合、入力に応じてオートコンプリートの候補が表示されます。If the chosen trigger has a query field, autocomplete suggestions appear as you type.

  4. 4. Run in the cloud を有効にし、ツールを最小権限で選ぶEnable Run in the cloud and select least-privilege tools

    Run in the cloud を有効にします。Tools では、このタスクに必要な操作だけを選びます。迷う場合は Suggest tools でプロンプトに基づく候補を確認してから絞り込みます。Enable Run in the cloud. In Tools, select only the actions this task actually needs. If unsure, use Suggest tools to get prompt-based suggestions, then narrow them down.

    この段階で期待される状態Expected state after this phase: Run in the cloud が有効になり、選んだツールだけがハイライトされています。Run in the cloud is enabled, and only the tools you selected are highlighted.

  5. 5. 書き込み権限のない実行者を無視する設定を確認するConfirm the setting that ignores actors without write access

    既定では、書き込み権限のないユーザーが起こしたイベントは無視され、プロンプトインジェクションのリスクを減らします。外部コントリビューターのイベントでも動かしたい場合だけ、Copilot cloud agent のリポジトリ設定で「Only allow automations to be triggered by users with write access」を無効にします（v1.1.0 以降で切り替え可能）。By default, events from users without write access are ignored, reducing the risk of prompt injection. Only disable “Only allow automations to be triggered by users with write access” in the Copilot cloud agent repository settings, toggleable since v1.1.0, if you specifically want external-contributor events to trigger it.

    この段階で期待される状態Expected state after this phase: 設定を変更しない限り、書き込み権限のない実行者のイベントは自動化を起動しません。Unless you change the setting, events from actors without write access do not start the automation.

  6. 6. プロンプト、モデル、推論の強さを設定して保存するConfigure the prompt, model, and reasoning effort, then save

    下のプロンプトのようにシークレットを含まない指示を入力し、モデルと推論の強さを選びます（v1.0.13 以降、編集時も選択が保持されます）。Create and run で保存とテスト実行を同時に行います。Enter a secret-free instruction like the prompt below, and choose a model and reasoning effort, which are remembered when you edit the automation later, since v1.0.13. Use Create and run to save and test in one step.

    夜間のテスト修正プロンプトNightly test-fix prompt 
    Check for failing tests on the main branch, attempt a safe fix, and open a draft pull request for review. Do not merge or force-push.
    夜間のテスト修正プロンプト（日本語）Nightly test-fix prompt (Japanese) 
    main ブランチで失敗しているテストを確認し、安全な修正を試みて、レビュー用の下書きプルリクエストを作成してください。マージや force-push は行わないでください。
    この段階で期待される状態Expected state after this phase: テスト実行のセッションが開始し、Recent runs にクラウド自動化として表示されます。A test-run session starts and appears in Recent runs marked as a cloud automation.

  7. 7. セッションログと使用量を確認するReview the session log and usage

    作成したセッションはリポジトリへのアクセス権を持つ全員に見えます。プロンプトと差分を確認し、想定外のツール実行がないことを確かめます。あわせて、この実行が GitHub Actions の分数と AI クレジットを消費していることも確認します。The session you created is visible to everyone with access to the repository. Review the prompt and diff to confirm no unexpected tool use occurred, and confirm this run consumed GitHub Actions minutes and AI credits.

    この段階で期待される状態Expected state after this phase: セッションログが公開範囲内のメンバーに見え、想定したツールだけが使われ、使用量に記録が残っています。The session log is visible to members within the sharing scope, only the intended tools were used, and the usage is recorded.

Decide

判断点Decision points

  • このトリガーは手動に留めるか、定期実行にするか。Keep this trigger manual, or make it scheduled?
  • 最小権限のツールセットで十分か、追加権限が必要か。Is the least-privilege toolset enough, or is more access needed?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: トリガー条件どおりに自動化が起動する。Checkpoint 1: the automation fires according to its trigger condition.
  • チェックポイント2: 最終実行状態を確認し、一時的ネットワーク障害のretryはscheduled workflowのsession start時に内部で短時間行われ、run historyに表示されるとは限らないと説明できる。Checkpoint 2: you inspect the latest run status and can explain that brief retry after a transient network error is internal to scheduled-workflow session startup and may not be visible in run history.

Verify

完了時の確認Completion checks

  • Automations 一覧でこの自動化が cloud として表示され、対象リポジトリがプライベートまたは内部である。The automation appears marked as cloud in the Automations list, and the target repository is private or internal.
  • テスト実行のセッションログがリポジトリへのアクセス権を持つメンバーに見え、プロンプトにシークレットが含まれていない。The test-run session log is visible to members with repository access, and the prompt contains no secrets.
  • 選んだツールだけが実行時に使われ、書き込み権限のない実行者のイベントは既定で無視される。Only the selected tools are used at runtime, and events from actors without write access are ignored by default.
  • 実行が GitHub Actions の分数と AI クレジットの使用量に反映されている。The run is reflected in GitHub Actions minutes and AI credit usage.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

automationは保存したprompt、trigger、filter、tool permissionsからsessionを開始します。cloud automationはcloud agentを使い、plan、policy、private/internal repository、write accessなどの条件に依存します。v1.1.4ではscheduled workflowのsession start時に一時的なnetwork errorが起きると短時間retryしますが、retryの内部詳細やrun history上の表示は公式ソースで説明されていません。An automation starts a session from its saved prompt, trigger, filters, and tool permissions. Cloud automation uses the cloud agent and depends on plan, policy, a private/internal repository, write access, and related conditions. In v1.1.4, a scheduled workflow briefly retries a transient network error while starting its session, but official sources do not describe internal retry details or a run-history indicator.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

Run in the cloud のトグルが無効（グレーアウト）になっているThe Run in the cloud toggle is disabled (greyed out)

リポジトリがパブリックである、または組織で Copilot cloud agent ポリシーが無効になっている可能性があります。プライベート/内部リポジトリであることを確認し、管理者にポリシーの有効化を依頼してください。The repository may be public, or the organization's Copilot cloud agent policy may be disabled. Confirm the repository is private or internal, and ask an administrator to enable the policy.

外部コントリビューターが Issue を開いても自動化が起動しないThe automation does not start when an external contributor opens an issue

これは既定の安全な挙動です。書き込み権限のない実行者のイベントは無視されます。意図的に許可したい場合のみ、Copilot cloud agent のリポジトリ設定でその制限を無効にしてください。This is the default, safer behavior — events from actors without write access are ignored. Only disable that restriction in the Copilot cloud agent repository settings if you intentionally want to allow it.

クエリトリガーの検索フィルターが期待した Issue や PR にマッチしないThe query trigger's search filter does not match the expected issues or pull requests

v1.1.2 のスマート検索は Issue トリガーと同じ修飾子オートコンプリートを使います。プレースホルダーとヒントテキストを確認しながら is: や label: などの修飾子を入力し直してください。The v1.1.2 smart search uses the same qualifier autocomplete as issue triggers. Re-enter qualifiers such as is: or label: while checking the placeholders and hint text.

自動化から始まったセッションにレビューパネルや Create PR ボタンが表示されないA session started by the automation shows no review panel or Create PR button

この不具合は v1.1.0 で修正済みです。v1.1.4（最新版） に更新し、直っていない場合はアプリを再起動してください。This bug was fixed in v1.1.0. Update to the latest version (v1.1.4) and restart the app if the panel is still missing.

Recovery path

明示的な復旧手順Explicit recovery path

自動化が実行されない場合は、まずトリガー条件とリポジトリ権限を確認し、cloud automationの場合はポリシーで無効化されていないかを管理者に確認してください。If an automation does not run, first check its trigger condition and repository permissions; for a cloud automation, confirm with an administrator that policy has not disabled it.

Reset

クリーンアップとリセットCleanup and reset

  1. テスト用のクラウド自動化はコンテキストメニューから無効化するか削除します。Disable or delete the test cloud automation from its context menu.
  2. テスト実行で作成された下書き PR やブランチを確認し、不要であればクローズ・削除します。Review any draft pull request or branch created by the test run, and close or delete it if it is not needed.
  3. テストのために緩めたツール選択や「書き込み権限が必要」設定は、本番運用前に元の最小権限に戻します。Restore any tool selection or the write-access requirement you loosened for testing back to least privilege before relying on this in production.
  4. Actions の分数や AI クレジットの使用状況を確認し、想定外の消費がないか見ておきます。Check Actions minutes and AI credit usage to confirm there was no unexpected consumption.

Success rubric

成功の基準Success rubric

  • 少なくとも1種類のトリガーを実際に発火させた。You actually fired at least one kind of trigger.
  • Recent runsで成功または失敗の状態を確認し、内部retryが表示されるとは断定していない。You inspected success or failure in Recent runs without claiming internal retries are displayed.
  • 最小権限のツールセットを意図的に選んだ。You deliberately chose a least-privilege toolset.

Go further

発展課題Stretch exercise

変更ファイルパスの条件を追加し、条件に一致しない変更では自動化が起動しないことを確認してください。Add a changed-file-path condition and confirm the automation does not fire for a change that does not match it.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows のアプリからでもクラウド自動化の作成・管理は同じ画面で行えます。実行自体は GitHub がホストするクラウド環境で行われるため、Windows 端末の電源状態は実行に影響しません。Creating and managing cloud automations from the Windows app uses the same screen. Execution itself happens in a GitHub-hosted cloud environment, so the Windows machine's power state does not affect the run.

macOS

macOS でも同様に、作成後は端末をスリープさせても実行は継続します。通知が必要な場合はアプリの通知設定を確認してください。On macOS, the run continues even if you let the machine sleep after creating the automation. Check the app's notification settings if you want to be notified.

Linux

Linux の AppImage 版でも作成フローは同じです。テスト実行の結果を確認するためにアプリを開き続ける必要はありません。The creation flow is the same on the Linux AppImage build. You do not need to keep the app open to see the result of a test run.

WSL

WSL リモート環境のプロジェクトでもクラウド自動化を作成できますが、実行はそのリポジトリに対して GitHub がホストする環境で行われ、ローカルの WSL ディストリビューションには依存しません。You can create cloud automations for a project in a WSL remote environment, but execution happens in a GitHub-hosted environment for that repository and does not depend on your local WSL distribution.
