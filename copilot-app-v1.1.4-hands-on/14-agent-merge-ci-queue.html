Agent Merge で CI とマージキューを管理するManage CI and the merge queue with Agent Merge

Agent Merge を有効にして、CI のブロック要因の解消からマージ条件を満たすまでをバックグラウンドで進めます。ブランチ保護や必須レビューを回避するものではありません。Enable Agent Merge to resolve CI blockers and carry a PR to merge conditions in the background, without ever bypassing branch protection or required reviews.

Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

レビューが完了した PR を Agent Merge に任せ、必須チェックの失敗を修正させながら他の作業を進めます。ブランチ保護と必須承認は Agent Merge が有効な間も常に適用されることを確認します。You hand a reviewed PR to Agent Merge so it can fix failing required checks while you move on to other work, while confirming that branch protection and required approvals still apply even with Agent Merge enabled.

担当者像Persona

関連するプルリクエストを束ねて着地させる担当者として、Agent MergeとCIブロッカーへの対応を中心に扱う回です。As the person landing a set of related pull requests together, this round focusing on Agent Merge and responding to CI blockers.

なぜ重要かWhy it matters: stack、merge queue、Agent Mergeの状態を見誤ると、意図せず途中のPRだけをマージしたり、待機理由が分からないまま長時間ブロックされたりします。Misreading stack, merge-queue, or Agent Merge state risks merging only a partial PR unintentionally, or being blocked for a long time with no visible reason.

Prepare

前提条件Prerequisites

  • ラボ 13 のレビュー手順を完了し、対象 PR が必要なレビューを受けている、または受けられる状態であること。Lab 13's review steps are complete and the target PR either has or can receive the required reviews.
  • 対象リポジトリに CI チェックが設定されており、あなたに PR をマージする権限があること。The target repository has CI checks configured and you have permission to merge the PR.
  • リポジトリのブランチ保護ルール (必須チェック、必須承認、マージキューの有無) を把握していること。You understand the repository's branch protection rules, including required checks, required approvals, and whether a merge queue is used.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: Agent Merge は GitHub が許可した時点でのみマージを実行し、ブランチ保護ルールや必須レビュー、必須チェックを回避することはありません。機密性の高いリリースブランチでは、無人でマージが進まないよう Agent Merge を無効にしておいてください。Agent Merge only merges once GitHub allows it, and it never bypasses branch protection rules, required reviews, or required checks. On sensitive release branches, keep Agent Merge disabled so merges don't proceed unattended.

Hands-on

手順Steps

  1. 1. レビュー済みの PR を開くOpen a reviewed pull request

    ラボ 13 でレビューを終えた PR を開き、Overview で現在の CI とレビュー状況を確認します。Open the PR you finished reviewing in lab 13 and check its current CI and review status in Overview.

    この段階で期待される状態Expected state after this phase: 必要なレビューと CI の現状が Overview から確認できます。You can see the required reviews and current CI state from Overview.

  2. 2. アプリ上部で Agent Merge を有効にするEnable Agent Merge at the top of the app

    アプリ上部の Agent Merge トグルを有効にします。Turn on the Agent Merge toggle at the top of the app.

    この段階で期待される状態Expected state after this phase: トグルがオンになり、ワークスペースの Copilot セッションがバックグラウンドで PR を読み込み始めます。The toggle turns on and the workspace's Copilot session starts reading the PR in the background.

  3. 3. 現在のブロック要因を確認するCheck current merge blockers

    変更を加える前に、何がマージをブロックしているかをエージェントに説明してもらいます。Before any change is made, ask the agent to explain what is blocking the merge.

    現在のブロック要因の説明を依頼するプロンプトPrompt to explain current merge blockers 
    Explain what is currently blocking this pull request from merging, including failing checks and outstanding review requirements, without making any changes yet.
    この段階で期待される状態Expected state after this phase: 失敗しているチェックや未承認のレビューなど、ブロック要因が一覧で説明されます。The agent lists blockers such as failing checks and outstanding reviews.

  4. 4. 失敗しているチェックを修正させるHave the agent fix a failing check

    無関係なファイルには触れず、失敗している必須チェックの最小限の修正を依頼します。Ask the agent for the smallest possible fix to the failing required check, without touching unrelated files.

    失敗しているチェックの修正を依頼するプロンプトPrompt to fix failing checks 
    Investigate why the failing required check is failing and propose the smallest fix, without touching unrelated files or configuration.
    この段階で期待される状態Expected state after this phase: エージェントが最小限の修正を提案し、チェックが再実行されます。The agent proposes a minimal fix and the check reruns.

  5. 5. マージキューのステータスを確認するCheck merge queue status

    リポジトリがマージキューを使っている場合、バッジ、サイドバー、My Work の一覧など各所で PR のステータスを確認します。If the repository uses a merge queue, check the PR's status across surfaces such as badges, the sidebar, and the My Work list.

    この段階で期待される状態Expected state after this phase: マージキュー使用時は、オープンやマージ準備完了ではなく Queued ステータスが一貫して表示されます。When a merge queue is used, the PR consistently shows a Queued status instead of open or merge-ready.

  6. 6. 必須承認が引き続き適用されることを確認するConfirm required approvals still apply

    Agent Merge は自己承認したりレビュー担当者の要件を回避したりしないことを、承認が不足した状態のまま確認します。While approvals are still missing, confirm that Agent Merge does not self-approve or bypass reviewer requirements.

    この段階で期待される状態Expected state after this phase: 必須承認が満たされるまで、Agent Merge は実際のマージを実行しません。Agent Merge does not perform the actual merge until required approvals are satisfied.

  7. 7. マージ完了とトグルの自動オフを確認するConfirm the merge completes and the toggle turns off

    必須チェックと必須承認がすべて満たされた後、GitHub がマージを許可した時点で完了するのを見届けます。Watch the merge complete once GitHub allows it, after all required checks and approvals are satisfied.

    この段階で期待される状態Expected state after this phase: PR がマージされ、Agent Merge のトグルが自動的にオフになります。The PR merges and the Agent Merge toggle turns off automatically.

Decide

判断点Decision points

  • stackごとまとめてマージするか、1つのPRだけをマージするか。Merge the whole stack together, or only a single PR?
  • Agent Mergeを有効にするか、必須チェック完了後に人手でマージするか。Enable Agent Merge, or merge by hand once required checks pass?

チェックポイントCheckpoints

  • チェックポイント1: stack menuで別のPRへ移動できる。Checkpoint 1: the stack menu navigates to another PR.
  • チェックポイント2: マージドロワーに含まれるPR一覧とqueue positionが表示される。Checkpoint 2: the merge drawer shows the included PR list and queue position.

Verify

完了時の確認Completion checks

  • Agent Merge のトグルが有効になり、バックグラウンドで動作し続ける。The Agent Merge toggle is enabled and continues running in the background.
  • 失敗していた必須チェックが修正され、再実行後に成功する。The previously failing required check is fixed and passes on rerun.
  • 必須承認とブランチ保護ルールが満たされるまで、実際のマージは行われない。The actual merge does not happen until required approvals and branch protection rules are satisfied.
  • マージ完了後、Agent Merge のトグルが自動的にオフになる。After the merge completes, the Agent Merge toggle turns off automatically.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

direct mergeは現在のbaseへ1件のPRを直ちに着地させます。GitHub merge queueはPRと最新baseを一時的なmerge groupで組み合わせてrequired checksを再実行し、順番に安全に着地させます。check failureやconflictではqueueから外れる場合があります。merge-as-stackはbase branchが連鎖する関連PR群をまとめて扱う別操作です。Agent Mergeはさらに別で、workspaceのCopilot sessionにPRを読ませ、blocking conditionを修正し、GitHubが許可した時点でマージします。v1.1.4ではcommit status check待ちで一時停止している理由を表示します。A direct merge lands one PR against the current base immediately. GitHub merge queue combines a PR with the latest base in a temporary merge group, reruns required checks, and lands queued changes safely in order; a check failure or conflict can remove an entry. Merge-as-stack is a separate operation for related PRs whose base branches form a chain. Agent Merge is separate again: it asks the workspace's Copilot session to read the PR, fix blocking conditions, and merge when GitHub allows. In v1.1.4 it explains a pause while waiting on a commit status check.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

1 つのチェックが成功しても、別のチェックが失敗したままだと Agent Merge が停止して見えるAgent Merge appears stuck when one check passes but another is still failing

この再プロンプトの不具合は v1.0.20 で修正済みです。v1.1.4（最新版） に更新し、Agent Merge の状態パネルで進行状況を確認してください。This re-prompting issue was fixed in v1.0.20. Update to the latest version (v1.1.4) and check the Agent Merge status panel for progress.

Agent Merge を有効にしても実際にはマージされないEnabling Agent Merge doesn't actually merge the pull request

この不具合は v1.1.1 で修正されています。v1.1.1 より前のビルドでは有効化してもマージが実行されないため、v1.1.4（最新版） に更新してください。This bug was fixed in v1.1.1. Builds before v1.1.1 could enable Agent Merge without it actually merging, so update to the latest version (v1.1.4).

Agent Merge をオフにしたのにステータスが active のまま表示されるThe status still shows active after turning Agent Merge off

この表示上の不具合は v1.0.16 で修正済みです。表示が古いままの場合はセッションを再読み込みしてください。This display bug was fixed in v1.0.16. If the status still looks stale, reload the session.

Recovery path

明示的な復旧手順Explicit recovery path

マージドロワーが確認中のまま止まって見える場合は、ドロワーを閉じて再度開き、それでも変わらなければPRを再読み込みし、Agent Mergeが一時停止中なら表示された理由に沿って対応してください。If the merge drawer appears stuck in a checking state, close and reopen it; if that does not change, reload the PR, and if Agent Merge is paused, act on the reason shown rather than re-toggling blindly.

Reset

クリーンアップとリセットCleanup and reset

  1. 演習で有効化した Agent Merge を、実際にマージする意図がなければオフにします。Turn off Agent Merge if you enabled it only for this exercise and don't intend to actually merge.
  2. マージ後、不要になったローカルブランチや worktree を削除します。Delete the local branch or worktree once it's no longer needed after the merge.
  3. バックグラウンドで動作したセッションをアーカイブし、消費したクレジットを Session spend の Agent merge 行で確認します。Archive the session that ran in the background, and check the Agent merge line in Session spend to see the credits it used.

成功の基準Success rubric

  • マージドロワーのstack summaryとqueue positionを確認した。You inspected the merge drawer's stack summary and queue position.
  • Agent Mergeの一時停止理由を実際に読んだ。You actually read an Agent Merge pause reason.

発展課題Stretch exercise

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows でもバックグラウンド動作はアプリの再起動をまたいで継続します。タスクバーの通知でステータス変化を確認できます。Background operation continues across app restarts on Windows too. Watch the taskbar notification for status changes.

macOS

macOS ではメニューバーのアイコンから Agent Merge の進行状況を確認できます。On macOS, you can check Agent Merge progress from the menu bar icon.

Linux

Linux でもバックグラウンド動作の挙動は同一です。トレイアイコンがない環境では、アプリを開いた状態でステータスを確認してください。Background behavior is identical on Linux. In environments without a tray icon, keep the app open to check status.

WSL

WSL 内のリポジトリでも、Agent Merge を実行するのはワークスペースの Copilot セッションであり、状態は Windows 側アプリから確認します。Even for repositories inside WSL, Agent Merge is driven by the workspace's Copilot session, and you check its status from the Windows-side app.
