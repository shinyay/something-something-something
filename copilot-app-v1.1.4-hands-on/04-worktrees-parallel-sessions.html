Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

サンプルリポジトリで、README の誤字修正とサンプルスクリプトの小さな改善という2つの独立したタスクを、同時に別々のセッションとして進めます。1つは新しい working tree、もう1つはローカルリポジトリで実行し、両方が互いのファイルを壊さないことを確認します。In a sample repository, run two independent low-risk tasks — fixing a README typo and making a small script improvement — as two separate sessions at the same time. Run one in a new working tree and the other against the local repository, and confirm neither session disturbs the other's files.

担当者像Persona

複数の変更を同時並行で進めるエンジニアとして、セッションの実行場所を分離します。As an engineer running several changes concurrently, isolate where each session executes.

なぜ重要かWhy it matters: working tree/ローカルリポジトリ/cloud sandboxの違いを理解しないと、並列セッションが互いのuncommitted changesを壊す可能性があります。Without understanding the difference between a working tree, the local repository, and a cloud sandbox, parallel sessions can clobber each other's uncommitted changes.

Goals

学習目標Learning objectives

  • 新しいworking treeでセッションを実行するRun a session in a new working tree
  • ローカルリポジトリ実行との違いを説明するExplain the difference from running against the local repository
  • cloud sandboxがパブリックプレビューであることを認識するRecognize that cloud sandbox sessions are public preview

Prepare

前提条件Prerequisites

  • Git がインストールされ、git worktree list をターミナルで実行できること。Git is installed and git worktree list works from a terminal.
  • GitHub Copilot App v1.1.4 で、変更してよいサンプルリポジトリがプロジェクトとして接続済みであること（ラボ01を参照）。GitHub Copilot app v1.1.4 with a sample repository you are allowed to change already connected as a project (see lab 01).
  • クラウドサンドボックスを試す場合は、組織またはエンタープライズで Cloud Sandbox access ポリシーが有効になっていること。If you want to try a cloud sandbox, the Cloud Sandbox access policy is enabled for your organization or enterprise.

対象範囲Feature boundary

このガイドは GitHub Copilot App のセッション実行先（新しい working tree、ローカルリポジトリ、クラウドサンドボックス）を扱います。ローカルサンドボックス化（Copilot CLI の /sandbox enable）やクラウドサンドボックスの CLI 起動（copilot --cloud）は隣接する Copilot CLI/サンドボックス機能であり、App 自体の UI 操作ではないため、参考情報としてのみ扱います。This guide covers where a GitHub Copilot app session runs — a new working tree, the local repository, or a cloud sandbox. Local sandboxing (Copilot CLI's /sandbox enable) and launching a cloud sandbox from the CLI (copilot --cloud) are adjacent Copilot CLI/sandbox capabilities, not App UI controls, and are mentioned here only as background.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: ローカルリポジトリモードは既存のチェックアウトを直接変更します。エディターや別のターミナルで同じフォルダーを同時に編集しないでください。まずは変更してよいサンプルリポジトリで試し、資格情報やシークレットをプロンプトに含めないでください。Local repository mode edits your existing checkout directly. Do not edit the same folder in an editor or another terminal at the same time. Start with a sample repository you are allowed to change, and never put credentials or secrets in a prompt.

Hands-on

手順Steps

  1. 1. worktree の基準状態を確認するConfirm the worktree baseline

    セッションを開始する前に、ターミナルで既存の worktree を確認しておきます。Before starting any session, check existing worktrees from a terminal.

    Git worktree の確認Check Git worktrees 
    git worktree list
    この段階で期待される状態Expected state after this phase: メインの worktree だけが表示され、セッション用の worktree はまだ存在しません。Only the main worktree entry appears; no session worktree exists yet.

  2. 2. セッションAを新しい working tree で開始するStart Session A in a new working tree

    新しいセッションを作成し、プロンプト欄下の実行先ドロップダウンで「新しい working tree」を選び、セッションA用のプロンプトを送ります。Create a new session, choose "New working tree" from the run-location dropdown below the prompt field, and send the Session A prompt.

    セッションA: working tree 用プロンプトSession A: working tree prompt 
    Fix an obvious typo in this repository's README and explain the diff. Do not touch any other file.
    この段階で期待される状態Expected state after this phase: セッションAが専用のブランチで開始され、エージェントが変更するまで Changes タブは空のままです。Session A starts on its own dedicated branch, and the Changes tab stays empty until the agent edits the README.

  3. 3. セッションBをローカルリポジトリで開始するStart Session B in the local repository

    同じプロジェクトで2つ目のセッションを作成し、今度は「ローカルリポジトリ」を選んでセッションB用のプロンプトを送ります。ローカルリポジトリモードは既存のチェックアウトを直接変更するため、同じフォルダーを他で同時編集しないでください。Create a second session in the same project, this time choosing "Local repository", and send the Session B prompt. Because local repository mode edits your existing checkout directly, avoid editing the same folder elsewhere at the same time.

    セッションB: ローカルリポジトリ用プロンプトSession B: local repository prompt 
    Suggest and apply one small readability improvement to the smallest script in this repository, and explain the diff. Do not touch the README.
    この段階で期待される状態Expected state after this phase: セッションBは既存のチェックアウトに対して直接作業し、ファイルエクスプローラーで見ても変更がその場に反映されます。Session B works directly against your existing checkout, and the change is visible immediately if you look at the folder in a file explorer.

  4. 4. 読み取り専用プロンプトで違いを比較するCompare the difference with a read-only prompt

    どちらかのセッション（または新しい Quick chat）で比較プロンプトを送り、実行先ごとの影響範囲をエージェントに説明させます。In either session (or a new Quick chat), send the comparison prompt and have the agent explain the impact of each run location.

    実行先を比較するプロンプトPrompt to compare run locations 
    Explain the practical difference between running this session in a new working tree versus the local repository, and tell me which files or branch would be affected either way.
    実行先を比較するプロンプト（日本語）Prompt to compare run locations (Japanese) 
    新しい working tree で実行する場合と、ローカルリポジトリで実行する場合の実務上の違いを説明してください。どちらの場合もどのファイルやブランチが影響を受けるか教えてください。
    この段階で期待される状態Expected state after this phase: working tree セッションは専用のブランチ/フォルダーに隔離され、ローカルリポジトリセッションは既存のチェックアウトを共有するという説明が返ります。The agent's answer confirms the working tree session is isolated on its own branch/folder, while the local repository session shares your existing checkout.

  5. 5. git worktree list で衝突がないことを確認するVerify no collisions with git worktree list

    再び git worktree list を実行し、セッションA用のworktreeだけが追加されていることを確認します。Run git worktree list again and confirm only Session A added a new worktree entry.

    Git worktree の確認Check Git worktrees 
    git worktree list
    この段階で期待される状態Expected state after this phase: セッションA用の新しいディレクトリとブランチが表示され、セッションBには対応するworktreeエントリがありません。A new directory and branch appear for Session A, while Session B has no corresponding worktree entry.

  6. 6. 任意: クラウドサンドボックスと比較するOptional: compare with a cloud sandbox

    Cloud Sandbox access ポリシーが有効な場合は、3つ目のセッションを「クラウドサンドボックス」で開始し、GitHubがホストする隔離環境で動くことを確認します。これはパブリックプレビュー機能です。If the Cloud Sandbox access policy is enabled, start a third session choosing "Cloud sandbox" and confirm it runs in a GitHub-hosted isolated environment. This is a public preview feature.

    この段階で期待される状態Expected state after this phase: セッションのラベルがクラウドサンドボックスであることを示し、ローカルの worktree やチェックアウトには一切変更がありません。The session's label indicates a cloud sandbox, and no local worktree or checkout files change for that session.

  7. 7. サイドバーのグループ表示を確認するReview the sidebar grouping

    サイドバーで、セッションAとBが同じリポジトリの下にグループ化され、それぞれ別のブランチ名で表示されていることを確認します。In the sidebar, confirm Session A and Session B are grouped under the same repository, each showing a distinct branch name.

    この段階で期待される状態Expected state after this phase: サイドバーに両方のセッションが同じプロジェクトグループ内で、別々のブランチとして表示されます。The sidebar lists both sessions under the same project group, each with its own branch.

Decide

判断点Decision points

  • 新しいworktreeで分離するか、ローカルリポジトリで直接進めるか。Isolate in a new worktree, or proceed directly against the local repository?
  • クラウドサンドボックスを使うか、ローカル実行に留めるか。Use a cloud sandbox, or stay with local execution?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: 新しいブランチとworktreeが作成されている。Checkpoint 1: a new branch and worktree were created.
  • チェックポイント2: 他のセッションのuncommitted changesに影響がない。Checkpoint 2: other sessions' uncommitted changes are unaffected.

Verify

完了時の確認Completion checks

  • 少なくとも2つのセッションが同じリポジトリで同時に実行され、互いのブランチやファイルを上書きしていない。At least two sessions ran at the same time in the same repository without overwriting each other's branch or files.
  • git worktree list の出力から、working tree セッションが専用のディレクトリとブランチを持つことを確認した。The git worktree list output confirmed the working tree session has its own directory and branch.
  • ローカルリポジトリセッションが既存のチェックアウトを直接変更したことを確認した。You confirmed the local repository session changed your existing checkout directly.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

worktreeは同じGitリポジトリを共有しつつ独立した作業ディレクトリとブランチを持つ仕組みで、アプリはセッションごとに専用のworktreeとブランチを自動管理します。A worktree is an independent working directory and branch that shares the same Git repository, and the app automatically manages a dedicated worktree and branch per session.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

ローカルリポジトリセッションの変更がエディターに反映されないChanges from the local repository session don't show up in your editor

エディターでフォルダーを再読み込みするか、ファイルウォッチャーの設定を確認してください。ローカルリポジトリモードは実際のチェックアウトを変更するため、外部エディターがファイル変更通知を見逃していないか確認します。Reload the folder in your editor or check its file watcher settings. Local repository mode edits the real checkout, so confirm your external editor isn't missing file-change notifications.

新しい working tree セッションを開始すると低ディスク容量の警告バナーが出るStarting a new working tree session shows a low disk space warning banner

サイドバーの低ディスク容量バナーを確認し、不要な古いセッションやworktreeを削除してから再試行してください。Check the low disk space warning banner in the sidebar and remove old, unneeded sessions or worktrees before retrying.

クラウドサンドボックスの選択肢が実行先ドロップダウンに出ないCloud sandbox doesn't appear as a run-location option

組織またはエンタープライズの管理者に Cloud Sandbox access ポリシーの有効化を依頼してください。このポリシーが無効だとクラウドサンドボックスはApp上で選択できません。Ask an organization or enterprise admin to enable the Cloud Sandbox access policy; without it, the cloud sandbox option isn't selectable in the app.

Recovery path

明示的な復旧手順Explicit recovery path

worktreeが壊れた、または削除に失敗した場合は、セッションを閉じてからGitのworktreeコマンドで手動整理し、必要ならブランチだけを復元してください。If a worktree becomes corrupted or fails to delete, close the session and manually clean it up with Git worktree commands, restoring only the branch if needed.

Reset

クリーンアップとリセットCleanup and reset

  1. 両方のテストセッションをアーカイブまたは削除します。削除は元に戻せないため、必要な変更がPRになっているか確認します。Archive or delete both test sessions. Deletion cannot be undone, so confirm any change you want to keep is already in a pull request.
  2. git worktree list で残っている不要なworktreeを確認し、git worktree remove で片付けます。Check git worktree list for leftover worktrees you no longer need and clean them up with git worktree remove.
  3. クラウドサンドボックスセッションを試した場合は、使わなくなったら削除して従量課金の使用を止めます。削除するとスナップショットも復元できなくなります。If you tried a cloud sandbox session, delete it when you're done to stop metered usage. Deleting it also removes its snapshot, which cannot be recovered.

Success rubric

成功の基準Success rubric

  • working tree、ローカルリポジトリ、cloud sandboxの違いを説明できる。You can explain the difference between a working tree, local repository, and cloud sandbox.
  • 並列セッションが互いのuncommitted changesに影響していない。Parallel sessions do not affect each other's uncommitted changes.
  • 使用後にworktreeとブランチを片付けた。You cleaned up the worktree and branch after use.

Go further

発展課題Stretch exercise

同じリポジトリに対して2つのworktreeセッションを同時に開き、片方をコミットしてからもう片方のdiffが独立していることを確認してください。Open two worktree sessions on the same repository simultaneously, commit in one, and confirm the other session's diff stays independent.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows では worktree とローカルリポジトリの両方がネイティブファイルシステム上で動作します。WSL内のリポジトリを扱う場合はラボ08のWSLハンドオフを参照してください。On Windows, both worktree and local repository sessions run on the native filesystem. For repositories inside WSL, see the WSL handoff in lab 08.

macOS

macOSではDMGビルドのAppがローカルgit worktreeを作成します。初回起動時にGatekeeperの確認が表示される場合があります。On macOS, the DMG build of the app creates local git worktrees. You may see a first-launch Gatekeeper confirmation.

Linux

LinuxのAppImageビルドでは、worktreeはユーザーのホームディレクトリ配下に作成されます。実行権限とディスク容量を確認してください。On the Linux AppImage build, worktrees are created under your home directory. Check execute permission and available disk space.

WSL

WSL内のリポジトリを使う場合、デスクトップアプリ自体はWindows側にインストールしたまま、リモート接続経由でセッションを実行します。v1.1.2ではWSLリモート環境の接続信頼性が改善されています。For repositories inside WSL, keep the desktop app installed on Windows and run sessions through the remote connection. v1.1.2 improves connection reliability for WSL remote environments.
