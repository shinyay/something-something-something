Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

チケット管理ツールや Slack から特定の issue へ直接ジャンプできるボタンを用意したいが、URL にプロンプトや機密情報を埋め込まずに、安全な形式のディープリンクだけを共有したい。You want a button in a ticket tool or Slack that jumps straight into a specific issue, while sharing only safely shaped deep links that never embed secrets or sensitive prompts.

担当者像Persona

複数リポジトリを横断して働くメンテナーとして、Issueのdeep linkとセッションコンテキストの受け渡しを扱います。As a maintainer working across multiple repositories, this lab focuses on issue deep links and carrying session context.

なぜ重要かWhy it matters: Issueの作成先リポジトリを誤ると、無関係な購読者に通知が飛び、後から修正するのが難しくなります。Creating an issue in the wrong repository notifies unrelated watchers and is hard to correct after the fact.

Goals

学習目標Learning objectives

  • Issue作成前に対象リポジトリを確認するConfirm the target repository before creating an issue
  • ホスト型ランチャー経由でdeep linkを安全に開くOpen a deep link safely through the hosted launcher
  • マイルストーンをIssue/PRに表示・編集するView and edit milestones on issues/PRs

Prepare

前提条件Prerequisites

  • ラボ 01 と 11 を完了し、対象の issue を含むリポジトリが接続済みであること。Labs 01 and 11 are complete, and the repository containing the target issue is connected.
  • ディープリンク先の issue 番号とリポジトリの OWNER/REPO を把握していること。You know the target issue number and the repository's OWNER/REPO.
  • encodeURIComponent など、URL エンコードの基本を理解していること。You understand the basics of URL encoding, such as encodeURIComponent.

対象範囲Feature boundary

このガイドは issue を開くディープリンクと、issue コンテキストを引き継いだセッション開始を扱います。プルリクエストのレビューや Agent Merge に関するディープリンクは対象外です。This guide covers deep links that open an issue and starting a session that carries issue context. Pull request review and Agent Merge deep links are out of scope.

時間の見積もりTime estimate

hands-on操作の目安は約30分です。download、network、service latencyは含みません。Hands-on work is estimated at about 30 minutes, excluding downloads, network delay, and service latency.

Docs + Release-noteDocs + release-note 情報源の裏付けSource provenance

Issue のディープリンクという概念は GitHub の URL・検索ドキュメントに一部 docs-grounded な裏付けがありますが、安全なホスト型 ghapp:// ランチャーという具体的な仕組みはこのアプリ固有であり release-note-grounded です。 手順内の正確なメニュー名・ボタン名・クリック順は変更履歴（changelog）に基づく記述であり、スクリーンショット付きの公式ウォークスルーで検証されたものではありません。実際の画面がここと異なる場合は、画面に表示されている表記を優先してください。The concept of deep-linking to an issue has partial docs-grounded support in GitHub's URL/search documentation, but the specific safe hosted ghapp:// launcher mechanism is app-specific and release-note-grounded. Exact menu names, button labels, and click order in the steps are grounded in changelog entries, not an illustrated official walkthrough. If your running build's UI differs from this text, follow what the screen actually shows instead.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: prompt パラメーターに機密情報や資格情報を含めないでください。共有前に必ず公式ホスト型ランチャー (https://github.com/copilot/app/launch?open=...) 経由の URL であることを確認し、ghapp:// を直接貼り付けたリンクは信頼できる内部ツールに限定します。Never put secrets or sensitive content in the prompt parameter. Always confirm the shared URL goes through the official hosted launcher (https://github.com/copilot/app/launch?open=...) before sharing, and limit raw ghapp:// links to trusted internal tools.

Hands-on

手順Steps

  1. 1. My Work から対象 issue を開くOpen the target issue from My Work

    ラボ 11 の絞り込みを使って対象の issue を見つけ、クリックして詳細ペインを開きます。Use the filtering from lab 11 to find the target issue, then click it to open the detail pane.

    この段階で期待される状態Expected state after this phase: issue の詳細ペインにタイトル、本文、コメントが表示されます。The issue detail pane shows the title, body, and comments.

  2. 2. New session をクリックしてコンテキストを引き継ぐClick New session to carry over context

    issue 詳細ペインの New session をクリックし、issue のコンテキストが読み込まれた状態でセッションが作成されることを確認します。Click New session in the issue detail pane and confirm the session is created with the issue's context already loaded.

    この段階で期待される状態Expected state after this phase: 会話の冒頭に issue のタイトル・本文・コメントを踏まえた文脈が読み込まれます。The conversation starts with context drawn from the issue's title, body, and comments.

  3. 3. issue 用のアプリリンクを組み立てるBuild the app link for the issue

    対象の OWNER、REPO、issue 番号を使って ghapp:// の生アプリリンクを組み立てます。Assemble the raw ghapp:// app link using the target owner, repo, and issue number.

    issue 用のアプリリンクApp link for an issue 
    ghapp://github.com/OWNER/REPO/issues/NUMBER
    この段階で期待される状態Expected state after this phase: ドキュメント通りの形式のアプリリンク文字列ができあがります。You have an app link string matching the documented shape.

  4. 4. 安全なランチャー URL にエンコードするEncode it into the safe launcher URL

    アプリリンクを encodeURIComponent でエンコードし、open パラメーターとしてホスト型ランチャー URL に埋め込みます。Encode the app link with encodeURIComponent and embed it as the open parameter in the hosted launcher URL.

    エンコードされたランチャー URLEncoded launcher URL 
    https://github.com/copilot/app/launch?open=ghapp%3A%2F%2Fgithub.com%2FOWNER%2FREPO%2Fissues%2FNUMBER
    この段階で期待される状態Expected state after this phase: https://github.com/copilot/app/launch?open=... の形式に一致する URL ができあがります。You have a URL matching the https://github.com/copilot/app/launch?open=... shape.

  5. 5. ブラウザーまたはターミナルからリンクを開いてみるTest opening the link from a browser or terminal

    作成したランチャー URL をブラウザーのアドレスバーやターミナルで開き、アプリへのハンドオフを確認します。Open the launcher URL you built in a browser address bar or a terminal and confirm the hand-off to the app.

    この段階で期待される状態Expected state after this phase: ブラウザーがアプリに制御を渡すか、渡せない場合はフォールバックページが表示されます。意図しないリポジトリや issue が開くことはありません。The browser hands off to the app, or shows the fallback page if it cannot. No unintended repository or issue opens.

  6. 6. issue を参照する新規セッションのリンクを作るBuild a new-session link that references the issue

    ghapp://session/new には issue 専用のパラメーターがないため、prompt に issue 番号を含めて参照します。ghapp://session/new has no dedicated issue parameter, so reference the issue number inside the prompt value instead.

    issue を参照する新規セッションを開くOpen a new session that references an issue 
    ghapp://session/new?repo=OWNER%2FREPO&prompt=Investigate%20issue%20%23NUMBER%20and%20propose%20a%20fix&mode=plan
    この段階で期待される状態Expected state after this phase: 指定したリポジトリと Plan モードで、issue 番号を含むプロンプトが入力済みの新規セッションが開きます。A new session opens in the specified repository and Plan mode, with the prompt pre-filled to reference the issue number.

Decide

判断点Decision points

  • プロンプトでエージェントに対象リポジトリ名を復唱・一時停止させてから続行を許可するか。Have the prompt make the agent echo the target repository name and pause before granting permission to continue?
  • 生のghapp://を直接開くか、ホスト型ランチャーだけを使うか。Open a raw ghapp:// directly, or use only the hosted launcher?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: エージェントが復唱したowner/repoが意図した値と一致している。Checkpoint 1: the owner/repo the agent echoed back matches the intended value.
  • チェックポイント2: deep linkが意図した画面をそのまま開く。Checkpoint 2: the deep link opens exactly the intended screen.

Verify

完了時の確認Completion checks

  • issue のディープリンクが My Work を経由せず issue 詳細を直接開いた。The issue deep link opened the issue detail directly without going through My Work.
  • New session をクリックすると issue のタイトル・本文・コメントがセッションのコンテキストに読み込まれた。Clicking New session loaded the issue's title, body, and comments into the session context.
  • 組み立てたホスト型ランチャー URL が、ブラウザーまたは共有ツールから正しくアプリを起動した。The hosted launcher URL you built correctly launched the app from a browser or a sharing tool.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

アプリはIssue作成リクエストをセッションのリポジトリとは独立したAPI呼び出しとして送信できます。アプリ自体に専用の確認UIがあるかどうかはこのガイドでは断定しないため、対象の復唱と一時停止をプロンプトの指示として人間が求め、最終承認します。deep linkはホスト型ランチャーURLを経由することで、任意のghapp://をそのまま実行しないようにしています。The app can send an issue-creation request as an API call independent of the session's own repository. This guide does not assert whether the app itself has a dedicated confirmation UI, so a human instead requests — via the prompt — that the target be echoed back and paused on, then gives final approval. Deep links route through a hosted launcher URL so an arbitrary ghapp:// is never executed directly.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

リンクをクリックしてもアプリが開かず、フォールバックページが表示されるClicking the link shows a fallback page instead of opening the app

アプリが ghapp:// プロトコルハンドラーとして登録されていない可能性があります。アプリを一度手動で起動し、OS の既定アプリ設定を確認してください。The app may not be registered as the ghapp:// protocol handler. Launch the app manually once and check your OS's default app settings.

誤ったリポジトリや issue が開いてしまうThe wrong repository or issue opens

OWNER%2FREPO のエンコードや issue 番号の桁を確認します。パラメーター値は encodeURIComponent でエンコードしてから open パラメーターに埋め込む必要があります。Check the encoding of OWNER%2FREPO and the issue number digits. Parameter values must be encoded with encodeURIComponent before being embedded in the open parameter.

New session を押しても issue のコンテキストが空に見えるNew session appears to start without issue context

issue 詳細ペインから直接 New session を押しているか確認します。ghapp://session/new は issue 専用パラメーターを持たないため、prompt に手動で issue 番号を含める必要があります。Confirm you clicked New session from the issue detail pane itself. ghapp://session/new has no dedicated issue parameter, so you must reference the issue number manually in the prompt.

Recovery path

明示的な復旧手順Explicit recovery path

誤ったリポジトリにIssueを作成してしまった場合、リポジトリ間移動はできないため、正しいリポジトリに新規作成し直し、誤って作成したIssueをクローズしてください。If an issue lands in the wrong repository, it cannot be moved between repositories — create a new one in the correct repository and close the mistaken one.

Reset

クリーンアップとリセットCleanup and reset

  1. テストで開いた issue 由来のセッションをアーカイブまたは削除します。Archive or delete the session you opened for this test.
  2. 共有ツールやメモに残した一時的なディープリンクを削除します。Remove any temporary deep links left in shared tools or notes.
  3. ブラウザーの履歴にエンコード済み URL が残っている場合、機密情報を含んでいないか確認して削除します。If the encoded URL remains in your browser history, confirm it contains no sensitive information and delete it.

Success rubric

成功の基準Success rubric

  • Issue作成先が意図したリポジトリと一致することを確認した。You confirmed the issue landed in the intended repository.
  • マイルストーンの表示・編集を少なくとも1回行った。You viewed or edited a milestone at least once.
  • deep linkをホスト型ランチャー経由でのみ開いた。You opened deep links only through the hosted launcher.

発展課題Stretch exercise

同じ変更に対して、Issueのリポジトリとは異なるリポジトリのマイルストーンにPRを紐づけてみてください。For the same change, try associating the pull request's milestone with a repository different from the issue's.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows では ghapp:// の関連付けはインストーラーが自動登録します。関連付けが外れた場合はアプリを再インストールしてください。On Windows, the installer automatically registers the ghapp:// association. Reinstall the app if the association is lost.

macOS

macOS では初回のプロトコルハンドラー確認ダイアログを許可する必要があります。On macOS, you must allow the first protocol-handler confirmation dialog.

Linux

Linux では xdg-open の既定アプリ設定が ghapp:// を認識している必要があります。AppImage の場合は手動登録が必要な場合があります。On Linux, xdg-open's default-app configuration must recognize ghapp://; AppImage builds may need manual registration.

WSL

WSL 内のターミナルから開く場合、リンクは Windows 側のブラウザーまたはアプリで処理されます。WSL 固有のハンドオフはラボ 08 を参照してください。Links opened from a WSL terminal are handled by the Windows-side browser or app. See lab 08 for WSL-specific handoff details.
