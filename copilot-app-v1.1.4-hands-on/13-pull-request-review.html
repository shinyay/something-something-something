Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

チームメイトが出した PR をレビューし、diff を確認しながらエージェントに指摘を手伝わせ、コメントの言い回しを一度書き直してから正式にレビューを提出します。You review a teammate's PR, use an agent to help spot issues while reading the diff, revise the wording of one staged comment, and then formally submit the review.

担当者像Persona

人の判断でレビューを送信するレビュアーとして、Copilot code reviewを併用します。As a reviewer who submits review with human judgment, combine it with Copilot code review.

なぜ重要かWhy it matters: Copilot code reviewの要求・再要求を理解しないと、フィードバック後の再レビューで古いコメントが重複したり、レビューが人の確認なしに送信されたと誤解したりします.Without understanding how to request and re-request Copilot code review, re-review after feedback can duplicate stale comments or be mistaken as submitted without human confirmation.

学習目標Learning objectives

Prepare

前提条件Prerequisites

  • ラボ 11 を完了し、My Work から少なくとも 1 件のオープンなプルリクエストを見つけられること。Lab 11 is complete and you can find at least one open pull request from My Work.
  • 対象リポジトリで PR にコメントできる権限 (Write 以上、または Triage としてのコメント権限) を持っていること。You have permission to comment on PRs in the target repository (Write or higher, or comment permission as a triager).
  • レビュー対象の PR に、少なくとも 1 つのファイル変更と CI チェックが設定されていること。The PR under review has at least one file change and configured CI checks.

Before you start

開始前の安全確認Before-you-start safety check

安全・データ・コスト・権限への影響Safety, data, cost, and permission implications: エージェントの要約だけで承認しないでください。認証・権限・シークレットの扱いに関わる変更は必ず自分で diff を確認します。レビューコメントに社外秘の情報を書き込まないでください。Do not approve based only on the agent's summary. Always personally check diffs touching authentication, authorization, or secret handling. Never write confidential information into review comments.

Hands-on

手順Steps

  1. 1. My Work から PR を開くOpen the pull request from My Work

    レビュー対象の PR をクリックし、Overview を表示します。Click the PR you're reviewing to display its Overview.

    この段階で期待される状態Expected state after this phase: Overview に PR の要約、CI チェックの結果、レビュー活動が表示されます。The Overview shows the PR summary, CI check results, and review activity.

  2. 2. Overview で CI とレビュー活動を確認するCheck CI and review activity in Overview

    必須チェックの成否と、既に付いているレビュー担当者やコメントを確認します。Check whether required checks pass and see any reviewers or comments already attached.

    この段階で期待される状態Expected state after this phase: レビューを始める前に、CI の状態とこれまでのレビュー履歴を把握できます。You understand the CI state and review history before you start reviewing.

  3. 3. Files changed で diff を確認するReview the diff in Files changed

    Files changed タブに切り替え、変更されたファイルの差分を一通り読みます。Switch to the Files changed tab and read through the diff of the changed files.

    この段階で期待される状態Expected state after this phase: 変更内容の全体像が把握できます。You have an overall picture of what changed.

  4. 4. PR 用のセッションを開始するStart a session for the pull request

    New session をクリックし、リスクの高い領域を要約するようエージェントに依頼します。Click New session and ask the agent to summarize the highest-risk areas.

    リスク領域の要約を依頼するプロンプトPrompt to summarize risk areas 
    Before I review this pull request, summarize the areas of highest risk (auth, data handling, migrations) and any tests that are missing.
    この段階で期待される状態Expected state after this phase: エージェントが認証・データ処理・マイグレーションなどのリスク領域と、不足しているテストを要約して返します。The agent summarizes risk areas such as auth, data handling, and migrations, and flags any missing tests.

  5. 5. diff にレビューコメントを残すLeave a review comment on the diff

    セッション内から diff の該当行にレビューコメントを追加します。Add a review comment on the relevant diff line from within the session.

    この段階で期待される状態Expected state after this phase: コメントが保留中レビューの下書きに追加されます。The comment is added to the pending review draft.

  6. 6. ステージ済みコメントの文言を修正するRevise a staged comment's wording

    先ほど追加したコメントの言い回しをより具体的にするよう、エージェントに依頼します。Ask the agent to make the wording of the comment you just added more specific.

    ステージ済みコメントの文言修正を依頼するプロンプトPrompt to revise a staged comment's wording 
    Revise the wording of the review comment you staged on line 42 of auth.go to be more specific about the missing null check, without creating a duplicate comment.
    この段階で期待される状態Expected state after this phase: 同じコメントが編集され、重複するコメントは作られません。The same comment is edited in place and no duplicate comment is created.

  7. 7. PR 詳細に戻ってレビューを提出するReturn to the PR detail view and submit the review

    PR 詳細ビューに戻り、上部の Review をクリックしてレビューを提出します。Go back to the PR detail view and click Review at the top to submit the review.

    この段階で期待される状態Expected state after this phase: Approve、Request changes、Comment のいずれかでレビューが正常に提出されます。The review submits successfully as Approve, Request changes, or Comment.

Decide

判断点Decision points

  • Copilotのコメントをそのまま受け入れるか、人が追加コメントするか。Accept Copilot's comment as-is, or add a human comment?
  • 修正後すぐに再要求するか、他のコメントも待つか。Re-request immediately after a fix, or wait for other comments too?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: Copilot code reviewのコメントがinlineに表示される。Checkpoint 1: Copilot code review comments appear inline.
  • チェックポイント2: 修正後の再要求で古いコメントが重複しない。Checkpoint 2: re-requesting after a fix does not duplicate stale comments.

Verify

完了時の確認Completion checks

  • PR の Overview に CI チェックとレビュー活動が表示される。The PR Overview shows CI checks and review activity.
  • diff へのコメントが保留中レビューの下書きとして蓄積される。Comments on the diff accumulate in the pending review draft.
  • 文言を修正したコメントが重複せず、同じ場所で更新される。The comment you revised updates in place without creating a duplicate.
  • レビューが正常に提出され、PR のステータスに反映される。The review submits successfully and is reflected in the PR's status.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

Copilot code reviewはPRの差分をレビューエージェントとして解析し、pending reviewとしてコメントをステージングします。人が送信するまでコメントは公開されず、エージェントは既存の保留コメントを編集できるため重複作成を避けられます。Copilot code review analyzes a PR's diff as a review agent and stages comments as a pending review. Comments are not published until a human submits, and the agent can edit an existing pending comment instead of duplicating it.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

CI のステータスが更新されないCI status doesn't update

GitHub Actions 側の実行状況を確認し、アプリの Overview を再読み込みします。ネットワーク接続も確認してください。Check the run status on the GitHub Actions side and reload the Overview in the app. Also verify network connectivity.

コメントを修正したのに重複したコメントが作られるRevising a comment creates a duplicate instead

v1.1.0 より前のビルドではこの挙動になります。Settings でバージョンを確認し、v1.1.0 以降に更新してください。This happens on builds older than v1.1.0. Check the version in Settings and update to v1.1.0 or later.

Review ボタンを押しても提出できないClicking Review doesn't let you submit

ブランチ保護ルールで必要なレビュー担当者や却下条件を満たしていない可能性があります。リポジトリの権限とブランチ保護設定を確認してください。Required reviewers or dismissal conditions from branch protection rules may not be satisfied. Check your repository permissions and branch protection settings.

Recovery path

明示的な復旧手順Explicit recovery path

レビューコメントに対するFixアクションが止まって見える場合は、PRを再読み込みしてから再度Fixを要求し、それでも解決しなければコメントに直接返信して人手で対応してください。If a Fix action on a review comment appears stuck, reload the PR and re-request the fix; if it still fails, reply to the comment directly and resolve it by hand.

Reset

クリーンアップとリセットCleanup and reset

  1. レビュー用に作成したセッションをアーカイブまたは削除します。Archive or delete the session you created for this review.
  2. テストのために残した未提出の保留中レビューがあれば、破棄するか提出します。Discard or submit any unsubmitted pending review left over from testing.
  3. レビューで使ったローカルブランチや worktree が不要になったら削除します。Remove the local branch or worktree used for the review once it's no longer needed.

Success rubric

成功の基準Success rubric

  • Copilot code reviewを少なくとも1回要求した。You requested a Copilot code review at least once.
  • 修正後の再要求で重複コメントが発生しないことを確認した。You confirmed re-requesting after a fix produced no duplicate comments.
  • 最終的なレビュー送信を人の判断で行った。You submitted the final review with human judgment.

Go further

発展課題Stretch exercise

同じPRに2回連続でCopilot code reviewを要求し、2回目の要求で扱いがどう変わるかを観察してください。Request Copilot code review twice in a row on the same PR and observe how the second request is handled.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows では大規模な PR の diff を開く際に一時的な遅延が出る場合があります。この遅延は v1.1.1 で改善されました。On Windows, opening large PRs' diffs could show a brief delay; this was improved in v1.1.1.

macOS

macOS ではトラックパッドのスクロールジェスチャーで Files changed の差分をスムーズにスクロールできます。On macOS, trackpad scroll gestures scroll smoothly through the Files changed diff.

Linux

Linux でも Overview と Files changed の挙動は同一です。外部リンクを開く際は既定ブラウザーの設定を確認してください。Overview and Files changed behave the same on Linux. Check your default browser setting when opening external links.

WSL

WSL リモート環境では、v1.1.2 で追加されたプルリクエストと issue ワークフロースキルにより、レビュー関連の提案が改善されています。In WSL remote environments, the pull request and issue workflow skills added in v1.1.2 improve review-related suggestions.
