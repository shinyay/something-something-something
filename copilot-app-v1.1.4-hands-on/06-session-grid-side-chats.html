Scenario & persona

シナリオと担当者像Scenario and persona

具体的なシナリオConcrete scenario

3つの独立した小さな修正セッションを同時に走らせながらSession Gridで進捗を横並びに確認し、そのうち1つのセッションからプルリクエストを作成してセッション名がタイトルに合わせて変わることを確認します。さらにそのPRのレビューパネルでサイドチャットを開き、差分について質問します。Run three independent small-fix sessions at once, watch their progress side by side in Session Grid, create a pull request from one of them and confirm its session name updates to match the PR title, then open a side chat in that PR's review panel to ask a scoped question about the diff.

担当者像Persona

複数セッションを監督するオーケストレーターとして、Session GridとSide chatを扱う回を担当します。As an orchestrator supervising multiple sessions, this round focuses on working with the Session Grid and side chats.

なぜ重要かWhy it matters: セッションが増えるほど、どれが承認待ちでどれが完了したかを一目で把握できないと、並列作業の利点が失われます。As the number of sessions grows, losing at-a-glance visibility into what is waiting for approval versus complete erases the benefit of parallel work.

Goals

学習目標Learning objectives

  • Session Gridで複数の独立セッション状態を比較するCompare multiple independent session states in Session Grid
  • main conversationを中断せずside chatで差分を確認するInspect a diff in a side chat without interrupting the main conversation
  • quick chatのGrid追加と非破壊的なbulk actionsを観察するObserve a quick chat joining the Grid and inspect non-destructive bulk actions

Prepare

前提条件Prerequisites

  • 同時に進行できる独立した小さなタスクが3つ以上あること（サンプルリポジトリの軽微な修正で構いません）。At least three independent small tasks you can run at the same time (minor sample-repository fixes are fine).
  • プルリクエストを作成できるサンプルリポジトリがプロジェクトとして接続済みであること。A sample repository where you can open pull requests is already connected as a project.
  • Settingsでこの機能がオフになっていないこと（デフォルトはオン）。This feature isn't turned off in Settings (it's on by default).

Hands-on

手順Steps

  1. 1. Session Gridが有効になっていることを確認するConfirm Session Grid is enabled

    Settingsを開き、Session Grid/サイドチャット/自動リネームのトグルがオンになっていることを確認します。Open Settings and confirm the Session grid/side chats/auto-rename toggle is on.

    この段階で期待される状態Expected state after this phase: トグルが既定の有効状態（オン）で表示されます。The toggle shows its default enabled state.

  2. 2. 3つのセッションを開始するStart three sessions

    同じプロジェクトで、修正セッションA・B・Cのプロンプトを使って3つの独立したセッションを開始します。In the same project, start three independent sessions using the fix A/B/C prompts.

    修正セッションAFix session A 
    Fix an obvious typo in this repository's README and open a small, focused diff. Do not touch other files.
    修正セッションBFix session B 
    Add one missing punctuation mark or fix one broken link in this repository's docs, and keep the diff minimal.
    修正セッションCFix session C 
    Improve one unclear code comment in the smallest source file in this repository, without changing behavior.
    この段階で期待される状態Expected state after this phase: サイドバーのプロジェクトの下に3つのセッションが表示されます。Three sessions appear in the sidebar under the project.

  3. 3. Session Gridを開くOpen Session Grid

    複数セッションを同時に表示するグリッドビューの操作を使い、少なくとも2つのセッションを並べて表示します。Use the control that shows multiple sessions at once, and display at least two sessions side by side.

    この段階で期待される状態Expected state after this phase: 少なくとも2つのセッションがグリッドレイアウトで同時に表示されます。At least two of the three sessions are visible simultaneously in a grid layout.

  4. 4. セッションからプルリクエストを作成するCreate a pull request from a session

    3つのうち1つのセッションで「Create PR」を実行します。In one of the three sessions, run "Create PR".

    この段階で期待される状態Expected state after this phase: PRが作成され、そのセッションの名前がPRタイトルに合わせて自動的に変わります。The PR is created, and the session's name automatically updates to match the PR title.

  5. 5. レビューパネルでサイドチャットを開始するStart a side chat in the review panel

    作成したPRのレビューパネルを開き、サイドチャットを開始します。Open the review panel for the pull request you created and start a side chat.

    この段階で期待される状態Expected state after this phase: サイドチャットがレビューパネル内に開き、メインのセッション会話とは別の文脈として扱われます。The side chat opens within the review panel, treated as a separate context from the main session conversation.

  6. 6. サイドチャットで差分について質問するAsk about the diff in the side chat

    side-chat-questionのプロンプトを送り、差分のどこが実際の動作変更でどこが書式変更かを尋ねます。Send the side-chat-question prompt asking which lines are behavior changes versus formatting only.

    サイドチャットでの質問Side chat question 
    In this pull request's diff, which lines changed behavior versus which are purely formatting? Do not suggest new changes yet.
    サイドチャットでの質問（日本語）Side chat question (Japanese) 
    このプルリクエストの差分のうち、どの行が実際の動作を変えていて、どの行が書式だけの変更ですか。まだ新しい変更は提案しないでください。
    この段階で期待される状態Expected state after this phase: エージェントがサイドチャット内で回答し、レビューパネルを離れたり新しいトップレベルセッションを作成したりしません。The agent answers within the side chat, without leaving the review panel or creating a new top-level session.

  7. 7. トグルのオン/オフを確認するConfirm the on/off toggle

    Settingsで機能をいったんオフにし、新しいPRを作成してもセッション名が変わらないことを確認してから、再度オンに戻します。Turn the feature off in Settings and confirm a new PR no longer renames the session, then turn it back on.

    この段階で期待される状態Expected state after this phase: オフの間はセッション名が自動で変わらず、オンに戻すとリネームが再開します。While off, the session name doesn't auto-rename; turning it back on resumes renaming.

  8. 8. quick chatとGrid bulk actionsを観察するObserve quick chats and Grid bulk actions

    v1.1.4の変更履歴に従い、使い捨てのquick chatをサイドバーでCmd/Ctrl+clickしてSession Gridへ追加できるか観察します。次に複数の使い捨てセッションを選択して右クリックし、send、mark read/unread、archive、deleteのbulk actionsが表示されるか確認します。この段階では破壊的なarchive/deleteを実行しません。正確な画面配置は変更履歴以外で網羅的に文書化されていないため、現在のビルド表示を優先してください。Following the v1.1.4 changelog, Cmd/Ctrl-click a disposable quick chat in the sidebar and observe whether it joins sessions in the Session Grid. Then select multiple disposable sessions, right-click, and observe whether bulk actions for send, mark read/unread, archive, and delete appear. Do not activate destructive archive/delete actions in this phase. Exact placement is not comprehensively documented outside the changelog, so follow the current build.

    この段階で期待される状態Expected state after this phase: quick chatをGrid内で観察し、選択した使い捨てセッションに対するbulk actionsの一覧を、破壊的操作なしで確認できる。You observed the quick chat in the Grid and inspected the bulk-action list for selected disposable sessions without performing a destructive action.

Decide

判断点Decision points

  • 短い並列質問をside chatで扱うか、独立したsessionを作るか。Use a side chat for a short parallel question, or create an independent session?
  • 選択sessionへsend / mark readを行うか、archive / deleteの破壊的操作を避けるか。Send or mark selected sessions, or avoid destructive archive/delete actions?

Checkpoints

チェックポイントCheckpoints

  • チェックポイント1: Gridに複数sessionが同時表示され、それぞれの状態を区別できる。Checkpoint 1: multiple sessions appear together in the Grid with distinguishable states.
  • チェックポイント2: quick chatをGridで確認し、選択sessionのbulk action一覧を実行せずに読める。Checkpoint 2: the quick chat appears in the Grid and you inspect the selected-session bulk-action list without activating it.

Verify

完了時の確認Completion checks

  • 少なくとも2つのセッションをSession Gridで同時に表示できた。At least two sessions were visible at once in Session Grid.
  • プルリクエストを作成したセッションの名前がPRタイトルに自動的に変わった。The session's name automatically changed to match the pull request title after creating it.
  • レビューパネルのサイドチャットで質問しても、メインのセッション会話には影響しなかった。Asking a question in the review panel's side chat did not affect the main session conversation.

Mental model

Under the hood: 内部で何が起きているかUnder the hood: what happens internally

各sessionは独立したconversation stateと、local sessionなら独立したworktreeを持ちます。Session Gridはそれらを同時表示する監督面です。side chatはreview contextの短い並列会話、quick chatは専用worktreeを作らない相談面であり、Gridへ追加されても通常のcoding sessionと同じ実行境界にはなりません。Each session has independent conversation state and, for local sessions, an isolated worktree. Session Grid is the supervision surface that displays them together. A side chat is a short parallel conversation in review context, while a quick chat does not create a dedicated worktree; adding it to the Grid does not turn it into a normal coding session.

Recover

トラブルシューティング（症状から探す）Troubleshooting (start from your symptom)

Session Gridの表示切り替えが見当たらないCan't find the control to switch to Session Grid

Settingsでこの機能がオフにされていないか確認してください。v1.1.0以降は全ユーザーに提供されていますが、個別にオフにできます。Check whether the feature was turned off in Settings — it's available to all users since v1.1.0, but can be disabled individually.

PR作成後もセッション名が変わらないThe session name doesn't change after creating a PR

自動リネームがSettingsでオフになっていないか確認します。オンでも一度手動でリネームした後は自動更新されない場合があります。Confirm automatic renaming isn't disabled in Settings. Also note that once you manually rename a session, it may no longer auto-update.

サイドチャットの内容がメインセッションに紛れ込んだように見えるSide chat content seems to bleed into the main session

サイドチャットはレビューパネル専用の会話です。メインのセッションタブに戻り、会話が分離されているか確認してください。混同する場合はサイドチャットを開き直します。A side chat is a conversation scoped to the review panel. Switch back to the main session tab to confirm the conversations are separate, and reopen the side chat if it seems mixed up.

Recovery path

明示的な復旧手順Explicit recovery path

Grid表示やside chatが不整合に見える場合は対象sessionを個別に開いて状態を確認し、破壊的bulk actionを避けてから再読み込みします。If Grid or side-chat state looks inconsistent, open the affected session individually, avoid destructive bulk actions, and reload after confirming its state.

Reset

クリーンアップとリセットCleanup and reset

  1. 3つのデモセッションのうち不要なものをアーカイブまたは削除します。Archive or delete any of the three demo sessions you no longer need.
  2. デモ用に作成したプルリクエストは、必要なければクローズしてブランチを削除します。Close the demo pull request and delete its branch if you don't need to keep it.
  3. Settingsで意図せずオフにした機能を元の状態に戻します。Restore any setting you toggled off during the exercise back to its original state.

Success rubric

成功の基準Success rubric

  • 2つ以上のsession状態をGridで比較した。You compared at least two session states in the Grid.
  • side chatの回答がmain conversationと分離されていることを確認した。You confirmed the side-chat response remained separate from the main conversation.
  • quick chatとbulk actionsを安全に観察し、archive/deleteを誤実行しなかった。You safely observed quick chat and bulk actions without accidentally archiving or deleting anything.

Go further

発展課題Stretch exercise

3つ以上のセッションを同時に起動し、Gridの一括操作（bulk actions）で一部だけをアーカイブしてください。Launch three or more sessions at once and use the Grid's bulk actions to archive only a subset.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windowsでは複数セッションをSession Gridで並べるとウィンドウサイズによってタイル数が変わります。高解像度ディスプレイだと見やすくなります。On Windows, the number of tiles Session Grid shows depends on your window size; a high-resolution display makes it easier to read.

macOS

macOSでも同様にウィンドウサイズに応じてグリッドのタイル数が変わります。フルスクリーンで使うと複数セッションが見やすくなります。On macOS, the grid's tile count also scales with window size; using full screen makes multiple sessions easier to read.

Linux

LinuxのAppImageビルドでも同じグリッド機能が使えます。ウィンドウマネージャーによっては最大化のショートカットが異なります。The same grid feature works on the Linux AppImage build; the maximize shortcut may differ depending on your window manager.

WSL

WSL上のリポジトリでもSession Gridとサイドチャットは同じUIで動作します。App自体はWindows側にインストールされたままです。Session Grid and side chats work the same way for repositories inside WSL. The app itself remains installed on the Windows side.
