インストールとプロジェクト接続Install and connect projects

GitHub Copilot App を導入し、GitHub リポジトリまたはローカルフォルダーを最初のプロジェクトとして接続します。Install the GitHub Copilot app and connect a GitHub repository or local folder as your first project.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

小さなサンプルリポジトリを接続し、実務リポジトリに触れる前にアプリのオンボーディングとプロジェクト境界を確認します。Connect a small sample repository so you can verify onboarding and project boundaries before touching a production repository.

機能の境界Feature boundary

このガイドは GitHub Copilot App のインストールとプロジェクト接続を扱います。Copilot CLI のインストールは別の製品サーフェスであり、ここでは必須手順として扱いません。This guide covers GitHub Copilot app installation and project connection. Installing Copilot CLI is an adjacent product surface and is not treated as a required step here.

安全上の注意Safety note: 最初は公開サンプルまたは変更してよいローカルフォルダーを使ってください。URL、プロンプト、フォルダー名にシークレットや資格情報を含めないでください。Start with a public sample or a local folder you are allowed to change. Never put secrets or credentials in URLs, prompts, or folder names.

Prepare

前提条件Prerequisites

  • Git がインストールされ、ターミナルから git --version を実行できること。Git is installed and git --version works from a terminal.
  • GitHub アカウント。Copilot プラン、または後で設定する独自モデルプロバイダーの資格情報。A GitHub account, plus either a Copilot plan or credentials for a model provider you will configure later.
  • 組織アカウントでは GitHub Copilot App ポリシーが有効であること。このポリシーは Copilot CLI ポリシーとは別です。For organization-managed accounts, the GitHub Copilot app policy is enabled. This policy is separate from the Copilot CLI policy.

Hands-on

手順Steps

  1. Git とアカウント条件を確認するCheck Git and account requirements

    ターミナルで Git のバージョンを確認します。組織アカウントの場合は、管理者が GitHub Copilot App ポリシーを有効にしていることも確認します。Verify Git from a terminal. If your account is organization-managed, also confirm that an administrator has enabled the GitHub Copilot app policy.

    Git の確認Verify Git 
    git --version
    期待される結果Expected result: Git のバージョンが表示され、アプリ利用を妨げる組織ポリシーがない状態です。A Git version is shown and no organization policy blocks app access.

  2. 公式ビルドをインストールするInstall an official build

    公式ダウンロードページから Windows、macOS、または Linux 用のビルドを選びます。GitHub 以外の配布元からインストーラーを取得しないでください。Choose the Windows, macOS, or Linux build from the official download page. Do not obtain the installer from a third-party distribution site.

    期待される結果Expected result: GitHub Copilot App がアプリケーション一覧に追加され、起動できます。The GitHub Copilot app appears in your applications and starts successfully.

  3. GitHub にサインインするSign in to GitHub

    アプリで「Sign in to GitHub」を選び、ブラウザーの認証フローを完了します。GHES を使う場合は「Use GitHub Enterprise」を選んでサーバー URL を入力します。Choose “Sign in to GitHub” in the app and complete the browser authentication flow. For GHES, choose “Use GitHub Enterprise” and enter the server URL.

    Copilot プランがない場合は、独自モデルプロバイダーを設定して続行できます。API キーはプロンプトに貼らず、Model providers の資格情報欄だけに入力します。If you do not have a Copilot plan, you can continue by configuring your own model provider. Enter API keys only in the Model providers credential field, never in a prompt.

    期待される結果Expected result: アカウント名が表示され、オンボーディングのプロジェクト選択に進みます。Your account is shown and onboarding advances to project selection.

  4. 最初のプロジェクトを接続するConnect your first project

    最近使った GitHub リポジトリを選ぶか、ローカルフォルダー、GitHub リポジトリ、Repository URL のいずれかを追加します。まずは変更してよい小さなプロジェクトを選びます。Choose a recent GitHub repository or add a Local folder or repository, GitHub repository, or Repository URL. Start with a small project you are allowed to change.

    期待される結果Expected result: サイドバーにプロジェクトが表示され、「Sessions」の + ボタンから選択できます。The project appears in the sidebar and can be selected from the + button next to Sessions.

  5. 読み取り専用の探索セッションを始めるStart a read-only exploration session

    接続したプロジェクトで新しいセッションを作成し、最初はファイル変更を禁止する探索プロンプトを送ります。実装を始める前に、エージェントがリポジトリ境界とビルド方法を正しく理解しているか確認します。Create a session in the connected project and begin with a prompt that forbids file changes. Confirm that the agent understands repository boundaries and build commands before asking it to implement anything.

    最初の低リスクプロンプトFirst low-risk prompt 
    Inspect this repository without changing files. Explain its purpose, primary languages, build commands, and the smallest safe task I could try in a new session.
    最初の低リスクプロンプト（日本語）First low-risk prompt (Japanese) 
    ファイルを変更せずにこのリポジトリを調査してください。目的、主な言語、ビルドコマンド、新しいセッションで試せる最小かつ安全なタスクを説明してください。
    期待される結果Expected result: 会話にリポジトリの概要と候補タスクが表示され、Changes には変更がありません。The conversation shows a repository summary and candidate task, while Changes remains empty.

  6. プロジェクト境界を確認するConfirm the project boundary

    Files でルートを確認し、意図したリポジトリまたはフォルダーだけが見えていることを確認します。次のガイドに進む前に、Settings でテーマやモデルプロバイダーの場所も確認します。Inspect the root in Files and confirm that only the intended repository or folder is visible. Before continuing, also locate theme and Model providers settings.

    期待される結果Expected result: 意図したプロジェクトだけがセッションに接続され、モデル構成へ進める状態です。Only the intended project is attached to the session and you are ready to configure models.

Verify

完了時の確認Completion checks

  • 公式 v1.1.2 ビルドが起動し、GitHub アカウントで認証されている。The official v1.1.2 build starts and is authenticated with your GitHub account.
  • サイドバーに少なくとも 1 つのプロジェクトが表示される。At least one project appears in the sidebar.
  • 最初の探索セッションがファイル変更なしで完了する。The first exploration session completes without file changes.

Recover

トラブルシューティングTroubleshooting

Business、Enterprise、または GHES でサインインできないBusiness, Enterprise, or GHES sign-in is blocked

管理者に GitHub Copilot App ポリシーを確認してもらいます。v1.1.1 以降は Copilot CLI ポリシーではなく App ポリシーでアクセスを判定します。Ask an administrator to check the GitHub Copilot app policy. Since v1.1.1, access is based on the app policy rather than the Copilot CLI policy.

アプリのアイコンは表示されるがウィンドウが開かないThe app icon appears but no window opens

まず v1.1.2 へ更新してアプリを再起動します。v1.1.0 と v1.1.2 に起動不能やオンボーディング再表示の修正が含まれます。改善しない場合は公式 Issue に OS、バージョン、再現手順、デバッグログの扱いに注意した情報を添えて報告します。Update to v1.1.2 and restart the app first. v1.1.0 and v1.1.2 include fixes for missing windows and repeated onboarding. If the issue remains, report it in the official repository with OS, version, reproduction steps, and carefully handled debug-log details.

ローカルフォルダーを追加できないA local folder cannot be added

フォルダーの読み書き権限と Git のインストールを確認します。ドラッグ&ドロップではファイルではなくフォルダー自体をサイドバーへ渡してください。Check read/write permission on the folder and verify Git is installed. When using drag and drop, drop the folder itself on the sidebar, not an individual file.

Reset

クリーンアップとリセットCleanup and reset

  1. サンプルを今後使わない場合は、サイドバーのプロジェクトメニューから接続を削除します。元の GitHub リポジトリは削除されません。If you will not use the sample again, remove its connection from the project menu in the sidebar. This does not delete the GitHub repository.
  2. 探索セッションをアーカイブまたは削除します。削除前に必要な会話や変更がないことを確認してください。Archive or delete the exploration session after confirming that it contains no conversation or changes you need to keep.
  3. 共有端末ではアプリからサインアウトし、BYOK 資格情報を追加した場合はシステム資格情報ストアからも不要なエントリを削除します。On a shared machine, sign out of the app. If you added BYOK credentials, also remove unneeded entries from the system credential store.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

x64 と ARM64 のセットアップ実行ファイルが提供されます。WSL 内のコードを扱う場合でも、デスクトップアプリ自体は Windows 側にインストールします。Setup executables are available for x64 and ARM64. Install the desktop app on Windows even when the code lives inside WSL.

macOS

Apple Silicon と Intel 用の DMG が別々に提供されます。初回起動時に macOS のアプリ実行確認が表示される場合があります。Separate DMGs are available for Apple Silicon and Intel. macOS may ask you to confirm the app on first launch.

Linux

AppImage の公式ビルドを選び、必要に応じて実行権限を付与します。配布形式とアーキテクチャが端末に合うことを確認します。Choose the official AppImage build and grant execute permission if needed. Confirm that the package format and architecture match your machine.

WSL

v1.1.2 の WSL リモート環境には GitHub のプルリクエストと Issue ワークフロースキル、および接続信頼性の改善が含まれます。WSL 固有のハンドオフはガイド 08 で扱います。In v1.1.2, WSL remote environments include GitHub pull request and issue workflow skills plus connection reliability improvements. Guide 08 covers WSL-specific handoff.
