Memory・Chronicle・InsightsMemory, Chronicle, and Insights

Copilot Memory の永続的な事実と好み、CLI 由来の Chronicle セッション履歴、そして Insights タブと公式の使用状況最適化ガイダンスを、混同せずに使い分けます。Use Copilot Memory's durable facts and preferences, the CLI-native Chronicle session history, and the Insights tab plus official usage-optimization guidance without conflating the three.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

複数のリポジトリを行き来するエンジニアが、朝会の前に直近のセッションから状況をまとめ、トークンの使い方に無駄がないかを点検し、Copilot Memory がどの情報をどの範囲まで再利用しているのかを正確に確認したいと考えています。An engineer who moves between several repositories wants to summarize recent session activity before a standup, check for costly usage patterns, and confirm exactly what Copilot Memory does and does not reuse across sessions.

機能の境界Feature boundary

このガイドは Copilot Memory、（Copilot CLI の機能である）Chronicle、そして Insights タブと使用状況最適化という 3 つの別々の仕組みを扱います。Memory は特定のリポジトリまたは自分のアカウントに紐づいた事実や好みを保存するものであり、あなたのセッション履歴全体が他のユーザーとグローバルに共有されるわけではありません。Chronicle は GitHub Copilot CLI のセッション履歴機能で、App が CLI の上に構築されているために App のセッションからも隣接的に利用できますが、App 専用の機能ではありません。Files タブやワークツリーに保存されるローカルなプロジェクトファイルの永続化とは区別してください。This guide covers three separate systems: Copilot Memory, Chronicle (a GitHub Copilot CLI capability), and the Insights tab together with official usage-optimization guidance. Memory stores facts and preferences tied to a specific repository or to your own account—it does not mean your entire session history is shared globally with other users. Chronicle is a Copilot CLI session-history feature that is usable from app sessions only because the app is built on the CLI; it is not an app-exclusive feature. Neither should be confused with local project-file persistence in Files or in a session's git worktree.

安全上の注意Safety note: Chronicle のスラッシュコマンドや自然言語の質問は、セッション履歴の内容をモデルに送って処理します。標準アウトプットや Chronicle の回答を外部に共有する前に、社外秘の情報が含まれていないか確認してください。また Memory のリポジトリレベルの事実は、そのリポジトリで Memory を利用できる全員に見える点にも注意してください。Chronicle slash commands and free-form questions send the content of your session history to a model for processing, so check standup output or Chronicle answers for confidential details before sharing them outside your team. Also remember that Memory's repository-level facts are visible to everyone who has Memory access to that repository, not just to you.

Prepare

前提条件Prerequisites

  • GitHub Copilot App v1.1.2 にサインイン済みで、Copilot Memory を利用できる有償の個人プラン、または Memory の利用を許可した組織・Enterprise 管理下のプランであること。BYOK のみのアカウントでは Memory の項目が表示されない場合があります。You are signed in to the GitHub Copilot app v1.1.2 with a paid individual Copilot plan, or an organization/enterprise-managed plan that allows Copilot Memory. BYOK-only accounts may not see the Memory section at all.
  • 接続済みのプロジェクトで、少なくとも 1 つの完了済みまたは進行中のセッションがあり、Chronicle と Insights タブに表示できるデータがあること。At least one completed or in-progress session exists in a connected project, so Chronicle and the Insights tab have data to show.
  • Copilot Business または Copilot Enterprise を利用している場合、管理者が「Store local sessions in the Cloud」ポリシーを少なくとも「View from cloud」に設定していること。無効なままだとセッションはローカルのみに保存され、他のクライアントからの Chronicle 検索が制限されます。If you use Copilot Business or Copilot Enterprise, an administrator has set the “Store local sessions in the Cloud” policy to at least “View from cloud.” If it is left disabled, sessions stay local-only and Chronicle queries from other clients are limited.
  • ブラウザーで github.com の Copilot 設定と請求ページ（Settings > Copilot、Settings > Billing）を開ける状態であること。You can open github.com's Copilot settings and billing pages (Settings > Copilot, Settings > Billing) in a browser.

Hands-on

手順Steps

  1. Memory と利用状況確認の前提を整えるCheck Memory and usage-review prerequisites

    Copilot 設定を開き、自分のプランで Copilot Memory が利用可能かどうかを確認します。組織管理下のアカウントでは、管理者が Memory とクラウド保存ポリシーを許可しているかも確認します。Open Copilot settings and confirm whether Copilot Memory is available for your plan. For an organization-managed account, also confirm that an administrator allows Memory and cloud session storage.

    期待される結果Expected result: Memory のトグルが表示され、有効・無効のいずれかであることが分かります。組織ポリシーが不足している場合は、その旨が明確になります。The Memory toggle is visible and clearly shows Enabled or Disabled. If an organization policy is missing, that gap is clearly identified.

  2. Copilot Memory の保存範囲を確認するReview what Copilot Memory stores

    Memory にはリポジトリレベルの事実（コーディング規約やビルドコマンドなど、そのリポジトリで Memory を使える全員が参照可能）と、ユーザーレベルの好み（自分のアカウントに紐づき、他のリポジトリでも使われるが他人には見えない）の 2 種類があります。所有しているリポジトリで保存済みの事実を確認し、必要であれば削除します。Memory stores two kinds of entries: repository-level facts (coding conventions, build commands, and similar details visible to anyone with Memory access to that repository) and user-level preferences (tied to your account, reused across repositories, but not visible to anyone else). In a repository you own, review the stored facts and delete any that look wrong.

    期待される結果Expected result: 少なくとも 1 つのリポジトリについて、リポジトリレベルの事実が存在するかどうかを説明でき、自分のユーザーレベルの好みの一覧（空の場合も含む）を確認できています。You can state, for at least one repository, whether repository-level facts exist, and you have viewed your own list of user-level preferences, even if it is empty.

  3. App のセッションでスタンドアップを生成するGenerate a standup from an app session

    接続済みプロジェクトのアクティブなセッションのプロンプト欄で /chronicle standup を実行します。これは GitHub Copilot CLI のセッション履歴機能であり、App が CLI 上に構築されているために App のセッションからも隣接的に利用できます。App 専用の機能として説明されているわけではない点に注意してください。既定では直近 24 時間が対象です。In the prompt box of an active session in a connected project, run /chronicle standup. This is a GitHub Copilot CLI session-history capability, usable from app sessions only because the app is built on the CLI—it is not documented as an app-exclusive feature. By default it covers the last 24 hours.

    スタンドアップ要約を生成Generate a standup summary 
    /chronicle standup
    期待される結果Expected result: 完了 (Done) と進行中 (In Progress) に分類されたレポートが表示され、作業したブランチや関連する Issue・プルリクエストが含まれます。A report grouped into Done and In Progress sections appears, referencing the branches you worked on and any related issues or pull requests.

  4. 期間を広げてもう一度確認するBroaden the reporting window

    既定の 24 時間では情報が少ない場合は、コマンドの後ろに期間の指定を追加します。日本語の自然言語プロンプトでも未完了タスクを尋ねられることを確認します。If the default 24-hour window feels too narrow, append a custom period after the command. Also confirm you can ask about unfinished tasks with a natural-language prompt in Japanese.

    期間を指定したスタンドアップStandup for a custom period 
    /chronicle standup for the last 3 days
    未完了タスクを尋ねる（日本語プロンプト）Ask about unfinished tasks (Japanese prompt) 
    過去1週間のセッションを振り返り、まだ完了していない作業と、関連する Issue や プルリクエストを日本語で要約してください。
    期待される結果Expected result: 指定した期間のレポートが表示され、日本語プロンプトへの回答でも同じセッション履歴を根拠にした要約が返ってきます。A report for the requested period appears, and the Japanese-language prompt returns a summary grounded in the same session history.

  5. コストのヒントを確認するCheck cost tips

    /chronicle cost tips を実行します。これはプロンプトの長さ、ツール呼び出しの頻度、継続的なやり取りの回数といったパターンを分析し、トークン使用を効率化するための具体的な提案を返します。Run /chronicle cost tips. It analyzes patterns like prompt length, tool-call frequency, and continuation steps, and returns concrete suggestions for making token usage more efficient.

    コスト削減のヒントCost-reduction tips 
    /chronicle cost tips
    期待される結果Expected result: 少なくとも 1 つの具体的なコスト削減の提案が表示されます。At least one concrete cost-reduction suggestion is shown.

  6. セッションの Insights タブを開くOpen a session's Insights tab

    アクティブなセッションのパネルで「+」の追加メニューから Insights タブを開きます（既定では非表示です）。ツール呼び出しやサブエージェントの活動を含むタイムラインと、コンテキストウィンドウの使用量グラフを確認します。In the active session's panel, open the Insights tab from the “+” add-to-panel menu (it is hidden by default). Review the timeline of tool calls and sub-agent activity, along with the context-window usage graph.

    期待される結果Expected result: ツールごとの所要時間の内訳と、時間経過に伴うコンテキストウィンドウ使用量のグラフが表示されます。A breakdown of time spent per tool and a graph of context-window usage over time are both visible.

  7. 公式の最適化ガイダンスと利用状況ページで裏付けを取るCross-check official optimization guidance and the usage page

    docs.github.com の「Optimizing your AI usage」チュートリアルにあるモデル選択、推論レベルの調整、Auto モデル選択の割引、明確なプロンプト設計といった推奨事項を確認します。次に AI 利用状況ページを開き、実際のクレジット消費とモデルごとの内訳を確認します。Review the recommendations in the “Optimizing your AI usage” tutorial on docs.github.com—model selection, adjusting reasoning level, the Auto model-selection discount, and clear prompt design. Then open the AI usage page and review your actual credit consumption and its per-model breakdown.

    期待される結果Expected result: 次のセッションで実践する具体的な最適化を 1 つ以上挙げられ、現在の AI クレジット消費量を確認できています。You can name at least one concrete optimization to apply in your next session, and you have reviewed your current AI credit consumption.

Verify

完了時の確認Completion checks

  • Memory（永続的な事実・好み）、Chronicle（CLI 由来のセッション履歴検索）、Insights（セッション単位のタイムラインと公式の使用状況最適化）を混同せずに説明できる。You can explain Memory (durable facts and preferences), Chronicle (CLI-native session-history search), and Insights (per-session timeline plus official usage optimization) without conflating them.
  • App のセッションから /chronicle standup を実行し、完了・進行中に分類されたレポートを生成できた。A /chronicle standup report, grouped by completion status, was generated from an app session.
  • セッションの Insights タブでツール呼び出しのタイムラインとコンテキストウィンドウ使用量グラフを確認できた。The session's Insights tab showed the tool-call timeline and the context-window usage graph.
  • /chronicle cost tips または公式の最適化チュートリアルから、具体的なコストまたはモデル選択の改善策を 1 つ以上特定できた。At least one concrete cost or model-selection improvement was identified from /chronicle cost tips or the official optimization tutorial.

Recover

トラブルシューティングTroubleshooting

/chronicle standup が「セッションが見つかりません」または極端に短いレポートを返す/chronicle standup returns “no sessions found” or an unusually short report

Business/Enterprise では「Store local sessions in the Cloud」ポリシーを確認し、個人設定ではセッション同期（remoteExport）が無効になっていないか確認します。それでも情報が少ない場合は「for the last 3 days」のように期間を広げます。For Business/Enterprise, check the “Store local sessions in the Cloud” policy; for personal settings, confirm session syncing (remoteExport) hasn't been disabled. If the report is still thin, broaden the window with something like “for the last 3 days.”

Copilot 設定に Memory の項目が表示されないThe Copilot Memory section doesn't appear in settings

有償の個人プランか、Memory を許可した組織・Enterprise 管理下のプランであることを確認します。BYOK のみのアカウントには Memory の項目自体が表示されないことがあります。Confirm you're on a paid individual plan, or an organization/enterprise-managed plan that allows Memory. BYOK-only accounts may not see the Memory section at all.

セッションパネルに Insights タブが見当たらないThe Insights tab isn't visible in the session panel

v1.0.17 以降、Insights タブは既定で閉じています。「+」の追加メニューから明示的に開いてください。Since v1.0.17, the Insights tab is closed by default. Reopen it explicitly from the “+” add-to-panel menu.

リポジトリレベルの Memory の事実が古い、または誤っているように見えるA repository-level Memory fact looks outdated or wrong

リポジトリの所有者であれば、Memory の管理画面から誤った事実を確認して削除できます。Copilot は事実を再利用する前に、引用元のコードを現在のブランチと突き合わせて検証しますが、明らかに誤っている場合は手動での削除が確実です。As the repository owner, review and delete the incorrect fact from the Memory management screen. Copilot re-validates a fact's citation against the current branch before reusing it, but manual deletion is the reliable fix when a fact is clearly wrong.

Reset

クリーンアップとリセットCleanup and reset

  1. この手順のためだけに Memory を有効にした場合は、Copilot 設定で再び無効に戻します。無効化は新しい事実の生成を止めるだけで、既存の事実は削除するまで残る点に注意してください。If you enabled Memory only for this exercise, disable it again in Copilot settings. Disabling only stops new facts from being created; existing facts remain until you delete them.
  2. この手順のために作成したユーザーレベルの好みが残っていれば削除し、今後のセッションに影響しないようにします。Delete any user-level preferences you created for this exercise so they don't influence future sessions.
  3. スタンドアップやコストのヒントを生成するために使った探索用セッションをアーカイブまたは削除します（ガイド 07 のアーカイブ・削除の手順を参照）。Archive or delete the exploration sessions used to generate the standup and cost-tips output (see guide 07 for the archive-versus-delete process).
  4. スタンドアップのレポートを外部（チャットや Issue など）に共有した場合、リポジトリや作業内容の詳細が含まれていないか見直し、必要であれば取り下げます。If you shared a standup report externally (chat, an issue, and so on), review it for repository or task details and retract it if necessary.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Memory、Chronicle、Insights はいずれもアカウントまたはセッションストアに紐づく機能であり、Windows 版 App でも同じ挙動です。/chronicle は App に組み込まれた CLI 相当の機能として動作します。Memory, Chronicle, and Insights are all tied to your account or session store, and behave the same way in the Windows app. /chronicle runs as the CLI-equivalent capability embedded in the app.

macOS

Copilot Memory 機能と、アプリ自体が使う RAM（メモリ）を混同しないでください。v1.1.0 では、チャット応答のストリーミング中に macOS 版アプリの RAM 使用量が過大になる不具合が修正されています。これは Copilot Memory とは無関係です。Don't confuse the Copilot Memory feature with the app's own RAM usage. v1.1.0 fixed an issue where the macOS app's RAM usage could grow excessively while a chat response was streaming—that fix is unrelated to Copilot Memory.

Linux

セッションデータは Linux でも ~/.copilot/session-state/ 配下に保存され、Chronicle と Insights は同じ仕組みで動作します。AppImage の実行権限設定はこれらの機能に影響しません。Session data is stored under ~/.copilot/session-state/ on Linux as well, and Chronicle and Insights work the same way. AppImage execute-permission settings don't affect these features.

WSL

WSL 内で copilot を直接実行している場合、そのセッションストアは Windows 側で動く App のセッションストアとは別のローカル領域です。両方でセッション同期を有効にしていれば、同じ GitHub アカウントの下で両方の履歴を Chronicle や質問応答から参照できますが、既定では別々のローカルストアである点に注意してください。If you also run copilot directly inside WSL, that session store is a separate local store from the one used by the Windows-hosted app. With session syncing enabled on both, you can query history from either through Chronicle or free-form questions under the same GitHub account, but by default they remain separate local stores.
