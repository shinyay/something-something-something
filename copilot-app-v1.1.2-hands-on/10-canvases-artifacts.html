Canvasとアーティファクトで人とエージェントが協働するCollaborate with canvases and artifacts

/create-canvasでCanvas拡張を作成し、ユーザースコープとプロジェクトスコープの違いを理解しながら、人とエージェントが同じ成果物を双方向に編集する方法を学びます。Use /create-canvas to build a canvas extension, understand the difference between user and project scope, and collaborate bidirectionally with the agent on the same artifact.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

サンプルリポジトリのIssueをトリアージするための簡単なカンバンCanvasを/create-canvasで作成し、add_cardやmove_cardのようなエージェント呼び出し可能な機能を追加します。まずユーザースコープで個人用に試し、その後プロジェクトスコープに変更してチームと共有できるようにします。Use /create-canvas to build a simple kanban canvas for triaging issues in a sample repository, adding agent-callable capabilities such as add_card and move_card. Try it first in user scope for yourself, then move it to project scope so it can be shared with your team.

機能の境界Feature boundary

このガイドは GitHub Copilot App のセッション内で/create-canvasを使ってCanvas拡張を作成・反復する操作を扱います。Canvas拡張の内部実装（extension.mjsなどのコード）を直接書き換える一般的な拡張機能開発は、より広いプラグイン/MCP/スキル開発の話題（ガイド19）であり、ここではエージェントに作成・修正を依頼する使い方に絞ります。This guide covers creating and iterating on a canvas extension using /create-canvas inside a GitHub Copilot app session. Directly hand-editing a canvas extension's internals (such as extension.mjs) is part of the broader plugin/MCP/skill development topic (guide 19); this guide focuses on asking the agent to build and revise it for you.

安全上の注意Safety note: Canvasをプロジェクトスコープにするとリポジトリにコミットされ、チーム全員に共有されます。共有前に、Issueのタイトルや内容に含まれる可能性のある機密情報をCanvasの成果物に含めていないか確認してください。A project-scope canvas is committed to the repository and shared with your whole team. Before sharing it, confirm the canvas artifact doesn't include any sensitive information that might appear in issue titles or bodies.

Prepare

前提条件Prerequisites

  • いくつかのオープンなIssueがあるサンプルリポジトリがプロジェクトとして接続済みであること。A sample repository with a few open issues is already connected as a project.
  • エージェントセッション内でスラッシュコマンドを使った経験があること。You've used slash commands inside an agent session before.
  • .github/extensions（プロジェクトスコープ）と~/.copilot/extensions（ユーザースコープ）の違いを大まかに理解していること。You roughly understand the difference between .github/extensions (project scope) and ~/.copilot/extensions (user scope).

Hands-on

手順Steps

  1. オープンなIssueがあることを確認するConfirm open issues exist

    接続済みリポジトリのオープンなIssueを確認します。Browse the connected repository's open issues.

    期待される結果Expected result: トリアージ対象となるオープンなIssueが少なくとも数件見えます。At least a few open issues are visible to triage.

  2. /create-canvasを実行するRun /create-canvas

    セッション内でカンバンCanvas作成コマンドを送ります。Send the kanban canvas creation command inside the session.

    カンバンCanvasを作成するCreate the kanban canvas 
    /create-canvas Create an agentic kanban canvas for triaging this repository's open issues, with actions to create, assign, and move cards between To do, In progress, and Done.
    カンバンCanvasを作成する（日本語）Create the kanban canvas (Japanese) 
    /create-canvas このリポジトリのオープンなIssueをトリアージするためのエージェント操作可能なカンバンCanvasを作成してください。To do、In progress、Doneの間でカードを作成・割り当て・移動できるアクションを含めてください。
    期待される結果Expected result: エージェントが、列とadd_card/move_cardのような機能を含むCanvasの計画を提示してから構築します。The agent proposes a canvas plan (board columns and capabilities like add_card/move_card) before building it.

  3. まずユーザースコープを選ぶChoose user scope first

    スコープを尋ねられたら、個人用（~/.copilot/extensions）を選びます。When asked, select the personal/user scope option (~/.copilot/extensions).

    期待される結果Expected result: Canvasが構築されてアプリの右側パネルに開き、あなたのマシンでのみ利用可能です。The canvas builds and opens in the app's right side panel, available only on your machine.

  4. Canvasを試すTry the canvas

    UIの操作でIssueカードを別の列に移動させます。Move an issue card between columns using the UI controls.

    期待される結果Expected result: ボードが即座に更新され、その変更はエージェントから見える共有状態になります。The board updates immediately, and the change is visible to the agent as shared state.

  5. エージェントに機能追加を依頼するAsk the agent to add a capability

    iterate-canvas-promptを送り、get_board機能を追加してもらいます。Send the iterate-canvas-prompt to add a get_board capability.

    Canvasに機能を追加するプロンプトPrompt to add a capability to the canvas 
    On the canvas you just created, add a get_board capability the agent can call to read the current board state before moving any card.
    期待される結果Expected result: エージェントがCanvas拡張を改修し、新しい機能が同じセッション内で呼び出せるようになります。The agent revises the canvas extension, and the new capability becomes callable in the same session.

  6. 新しい機能を呼び出してもらうAsk the agent to call the new capability

    「get_boardを呼び出して、Progressの列にあるカード数を教えてください」と依頼します。Ask the agent to "call get_board and tell me how many cards are In progress."

    期待される結果Expected result: エージェントがget_boardを呼び出し、ボードに表示されている数と一致する件数を報告します。The agent calls get_board and reports a count that matches what you see on the board.

  7. Canvasをプロジェクトスコープへ移すMove the canvas to project scope

    Canvasをプロジェクトスコープ（.github/extensions）に作り直す、または移すようエージェントに依頼し、チームと共有できるようにします。Ask the agent to recreate or move the canvas to project scope (.github/extensions) so it's committed and shared.

    期待される結果Expected result: Canvas拡張のファイルがリポジトリのworking tree内の.github/extensions配下に置かれ、コミットしてチームと共有できる状態になります。The canvas extension's files appear under .github/extensions in your repository's working tree, ready to be committed and shared with your team.

Verify

完了時の確認Completion checks

  • /create-canvasでカンバンCanvasを作成し、右側パネルで開けた。You created a kanban canvas with /create-canvas and it opened in the right side panel.
  • UIでカードを動かした変更と、エージェントが呼び出したget_boardの結果が一致した。A card move you made through the UI matched what get_board reported when the agent called it.
  • ユーザースコープからプロジェクトスコープへCanvasを移し、.github/extensions配下にファイルが置かれることを確認した。You moved the canvas from user scope to project scope and confirmed its files landed under .github/extensions.

Recover

トラブルシューティングTroubleshooting

/create-canvasを実行しても何も起きないRunning /create-canvas doesn't seem to do anything

アクティブなエージェントセッション内でコマンドを実行しているか確認してください。ブランチやworkspaceのないQuick chatでは動作が異なる場合があります。Confirm you're running the command inside an active agent session. Behavior can differ in a Quick chat that has no dedicated branch or workspace.

カードを動かしてもエージェントのget_board結果に反映されないMoving a card doesn't show up when the agent calls get_board

Canvasを保存またはリロードしてから再度尋ねてください。それでも一致しない場合は、エージェントにCanvasの状態管理コードを確認してもらいます。Save or reload the canvas, then ask again. If it still doesn't match, ask the agent to check the canvas's state-management code.

プロジェクトスコープに移動したはずのCanvasファイルが見当たらないCanvas files you moved to project scope are nowhere to be found

リポジトリの.github/extensionsディレクトリをFilesタブで確認してください。まだコミットされていない場合はChangesタブの未コミットスコープに表示されます。Check the repository's .github/extensions directory in the Files tab. If it isn't committed yet, it will show up under the Uncommitted scope in the Changes tab.

Reset

クリーンアップとリセットCleanup and reset

  1. 演習用に作成したユーザースコープのCanvasが不要であれば、~/.copilot/extensionsから削除します。Delete the user-scope canvas you created for this exercise from ~/.copilot/extensions if you don't need it.
  2. プロジェクトスコープに移した場合は、コミットするかどうかを判断し、不要ならブランチごと破棄します。If you moved it to project scope, decide whether to commit it, or discard the whole branch if you don't need it.
  3. Canvasを開いたセッションをアーカイブまたは削除して片付けます。Archive or delete the session where you opened the canvas to clean up.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windowsではユーザースコープのファイルはユーザープロファイル配下の.copilot\extensionsに保存されます。On Windows, user-scope files are stored under .copilot\extensions in your user profile.

macOS

macOSでは~/.copilot/extensionsがユーザースコープの標準的な場所です。On macOS, ~/.copilot/extensions is the standard location for user scope.

Linux

LinuxのAppImageビルドでも同じく~/.copilot/extensionsがユーザースコープに使われます。The Linux AppImage build also uses ~/.copilot/extensions for user scope.

WSL

WSL内のリポジトリを扱う場合、プロジェクトスコープの.github/extensionsはWSL側のチェックアウトに作成されます。When working with a repository inside WSL, the project-scope .github/extensions directory is created inside the WSL-side checkout.
