ファイル・差分・ブラウザプレビュー・プレゼンテーションモードFiles, diffs, browser preview, and Present mode

隠しファイル表示、コミット/ファイル/未コミットのスコープ切り替え、GitHub形式の行アンカー、ブラウザプレビュー、フルスクリーンのPresent modeを使い、シークレットを露出させずにレビューする方法を学びます。Learn to toggle hidden files, switch between commit/file/uncommitted diff scopes, use GitHub-style line anchors, preview a running app in the browser tab, and present with full-screen Present mode — all without exposing secrets.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

あるセッションの変更内容を、Filesタブで隠しファイル表示をオンにして.env.exampleのようなテンプレートファイルの有無だけを確認し（実際の.envは絶対に開かない）、Changesタブでコミット別・ファイル別・未コミットのスコープを切り替え、GitHub形式の行アンカーで特定行を共有し、ブラウザプレビューで動作を確認したうえで、Present modeでチームに画面共有します。For a session's changes, turn on the hidden-file toggle in the Files tab only to confirm whether a template file like .env.example exists (never opening a real .env), switch between commit, file, and uncommitted scopes in the Changes tab, share a specific line with a GitHub-style line anchor, check behavior in the browser preview tab, and finally present the result to your team in full-screen Present mode.

機能の境界Feature boundary

このガイドは GitHub Copilot App のFiles/Changesタブ、ブラウザプレビュータブ、Present modeというUI機能を扱います。Copilot CLIのサンドボックス化されたファイルアクセス制御（/sandbox enable）は隣接する機能であり、ここでのファイル閲覧設定とは別物です。This guide covers the GitHub Copilot app's Files/Changes tabs, the browser preview tab, and Present mode UI features. Copilot CLI's sandboxed file-access controls (/sandbox enable) are an adjacent capability, distinct from the file-viewing settings covered here.

安全上の注意Safety note: 隠しファイル表示をオンにしても、.envや資格情報を含むファイルの内容を開いたり、スクリーンショットやPresent modeの画面共有に映したりしないでください。存在確認だけにとどめ、必要ならファイル名をマスクして共有します。Even with hidden files shown, do not open the contents of .env or any file holding credentials, and don't let it appear in a screenshot or a Present-mode screen share. Limit yourself to confirming existence, and mask filenames if you need to share them.

Prepare

前提条件Prerequisites

  • .env.exampleのような無害なテンプレートファイルを含み、実際の秘密情報を含まないサンプルリポジトリが接続済みであること。A sample repository connected that has a harmless template file like .env.example and contains no real secrets.
  • そのリポジトリに複数コミットの変更履歴と、ローカルで起動できる簡単な開発サーバーがあること（任意）。The repository has a multi-commit change history and, optionally, a simple local dev server you can start.
  • PresentモードやFilesタブの操作に慣れるため、既に1つ以上のセッションで変更を作成していること。You've already made changes in at least one session, so you're familiar with basic Files/Changes navigation.

Hands-on

手順Steps

  1. 隠しファイル表示を切り替えるToggle hidden files

    Filesタブで、v1.1.1で追加された隠しファイル表示トグルを使い、通常は.gitignoreで除外されているファイルを表示します。In the Files tab, use the hidden-file toggle added in v1.1.1 to show files normally excluded by .gitignore.

    期待される結果Expected result: .env.exampleのようなファイルが（存在すれば）表示されます。実際の.envファイルの中身は絶対に開かないでください。Files like .env.example (if present) become visible. Confirm you do NOT open any real .env file's contents.

  2. Changesのスコープを切り替えるSwitch diff scopes in Changes

    Files、Commits、Uncommittedのスコープを切り替えます。Toggle between the Files, Commits, and Uncommitted scopes.

    期待される結果Expected result: 選択したスコープに応じて差分の表示範囲が変わり、ツールバーのラベルと一致します。The diff view updates to show only the selected scope, matching the toolbar label.

  3. 差分の安全性について質問するAsk about the diff's safety

    diff-explain-promptを送り、共有前に機密情報がないか確認させます。Send the diff-explain-prompt to check for sensitive content before you share anything.

    差分の安全性を確認するプロンプトPrompt to check diff safety 
    In the Changes tab, explain which of my uncommitted changes are safe to commit as-is, and flag any file that looks like it might contain secrets before I share a line anchor link.
    差分の安全性を確認するプロンプト（日本語）Prompt to check diff safety (Japanese) 
    Changesタブにある未コミットの変更のうち、そのままコミットしても安全なものを教えてください。行アンカーのリンクを共有する前に、秘密情報を含んでいそうなファイルがあれば指摘してください。
    期待される結果Expected result: エージェントが機密情報らしきファイルを指摘し、どの未コミット変更が安全かを教えてくれます。The agent flags files that look sensitive and confirms which uncommitted changes are safe.

  4. 特定のコミットを選択するSelect a specific commit

    差分ツールバーのコミットナビゲーションを使います。Use the commit navigation control in the diff toolbar.

    期待される結果Expected result: コミットバナーがそのコミットの追加/削除行数と差分だけを表示します。The commit banner shows that commit's addition/deletion counts and diff only.

  5. GitHub形式の行アンカーを作成するCreate a GitHub-style line anchor

    ファイルビューアーでコードポインター（行範囲）をクリックし、そのリンクをコピーします。Click a code pointer/line range in the file viewer and copy its link.

    期待される結果Expected result: 参照した行がファイルビューアーでハイライトされ、リンクがGitHub形式の行アンカー構文になります。The referenced lines are highlighted in the file viewer, and the link uses GitHub-style line-anchor syntax.

  6. ブラウザプレビューを開くOpen the browser preview

    ローカルの開発サーバーを起動し、そのブラウザプレビュータブを開きます。Start a local dev server task and open its browser preview tab.

    期待される結果Expected result: プレビュータブに実行中のアプリが表示され、他のタブに切り替えて戻っても重複タブが増えません。A preview tab shows the running app; switching away and back doesn't duplicate the tab.

  7. Present modeで結果を提示するPresent the result

    差分パネルまたはファイルパネルで「Enter full screen」（Present mode）をクリックします。Click "Enter full screen" (Present mode) on the diff or file panel.

    期待される結果Expected result: アプリのクロームとウィンドウヘッダーが隠れ、フルブリードの表示になります。Escで元に戻せます。App chrome and window header hide for a clean, full-bleed view; pressing Esc exits Present mode.

Verify

完了時の確認Completion checks

  • 隠しファイル表示をオンにしても、実際の秘密情報を開いたり画面に映したりしなかった。You toggled hidden files on without ever opening or displaying real secrets.
  • Files/Commits/Uncommittedのスコープを切り替えて、それぞれ正しい範囲の差分が表示されることを確認した。You switched between Files/Commits/Uncommitted scopes and confirmed each showed the correct range of the diff.
  • GitHub形式の行アンカーで特定行を共有し、Present modeでフルスクリーン表示を確認した。You shared a specific line with a GitHub-style line anchor and confirmed full-screen Present mode.

Recover

トラブルシューティングTroubleshooting

隠しファイルトグルをオンにしても.envらしきファイルが見えないTurning on the hidden-file toggle still doesn't show a file that looks like .env

.gitignoreの記述内容を確認してください。トグルは.gitignoreで除外されたファイルを表示しますが、リポジトリ自体にファイルが存在しない場合は表示されません。Check the .gitignore rules. The toggle reveals files excluded by .gitignore, but it can't show a file that doesn't exist in the repository at all.

コミットスコープを切り替えても差分が空のままSwitching to a commit scope still shows an empty diff

そのブランチにまだコミットがない場合があります。未コミットの変更しかない場合はUncommittedスコープを選んでください。The branch may not have any commits yet. If there are only uncommitted changes, choose the Uncommitted scope instead.

ブラウザプレビュータブを閉じても音声やリソースが使われ続けるAudio or resources keep running after closing the browser preview tab

Appを最新版に更新してください。閉じた後もプレビュータブがリソースを使い続ける問題は修正されています。Update the app to the latest version — issues where a closed preview tab keeps using resources have been fixed.

Reset

クリーンアップとリセットCleanup and reset

  1. 隠しファイル表示トグルを元のオフの状態に戻します。Turn the hidden-file toggle back off when you're done.
  2. 起動した開発サーバーとブラウザプレビュータブを閉じます。Stop the dev server you started and close its browser preview tab.
  3. 演習用に共有した行アンカーのリンクを、不要であれば破棄します。Discard the line-anchor link you shared for this exercise if you don't need to keep it.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windowsでも隠しファイル表示、スコープ切り替え、行アンカー、Present modeはすべて同じUIで動作します。Hidden-file display, scope switching, line anchors, and Present mode all work the same way on Windows.

macOS

macOSのPresent modeは通常のOSフルスクリーン機能とは別の、アプリ内の操作です。Present mode on macOS is an in-app action distinct from the OS's regular full-screen feature.

Linux

LinuxのAppImageビルドでも同じ機能が使えます。ウィンドウマネージャーによってはEsc以外のフルスクリーン解除操作が必要な場合があります。The same features work on the Linux AppImage build; depending on your window manager, exiting full screen may need something besides Esc.

WSL

WSL内のリポジトリでも隠しファイル表示やブラウザプレビューは同じように動作しますが、開発サーバーのポート転送設定を確認してください。Hidden-file display and browser preview work the same way for repositories inside WSL, but check your dev server's port-forwarding setup.
