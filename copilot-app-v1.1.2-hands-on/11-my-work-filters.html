My Work のセクションとフィルターを使いこなすMaster My Work sections and filters

My Work のデフォルトセクションを理解し、has:/no: 修飾子を使って issue とプルリクエストを素早く絞り込みます。Understand My Work's default sections and use the has:/no: qualifiers to quickly narrow down issues and pull requests.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

複数リポジトリにまたがる担当 issue が積み上がっている状態で、スプリント開始前にラベルやマイルストーンが未設定の issue だけを洗い出し、My Work の独自セクションとして保存します。With assigned issues piling up across multiple repositories, you need to surface only the issues missing a label or milestone before sprint planning, then save that view as a custom My Work section.

機能の境界Feature boundary

このガイドは My Work のセクションと検索修飾子によるフィルタリングを扱います。issue から新しいセッションを開始する手順はガイド 12 で、プルリクエストのレビューはガイド 13 で扱うため、ここでは対象外です。This guide covers filtering with My Work sections and search qualifiers. Starting a session from an issue is covered in guide 12, and reviewing pull requests is covered in guide 13, so both are out of scope here.

安全上の注意Safety note: 保存したフィルターやセクション名に、非公開プロジェクトのコードネームや機密情報を含めないでください。共有端末では、機密性の高いフィルタークエリを含むセクションをサインアウト前に削除してください。Do not put confidential project codenames or sensitive information in saved filters or section names. On shared machines, remove sections containing sensitive filter queries before signing out.

Prepare

前提条件Prerequisites

  • ガイド 01 を完了し、GitHub Copilot App にサインインして少なくとも 1 つのプロジェクトを接続済みであること。Guide 01 is complete: you are signed in to the GitHub Copilot app with at least one project connected.
  • 接続したリポジトリに、ラベル、担当者、マイルストーンの設定状況が異なる複数の issue またはプルリクエストが存在すること。The connected repository has several issues or pull requests with varying label, assignee, and milestone states.
  • 組織アカウントの場合、GitHub Copilot App ポリシーが有効になっていること。My Work の可視性はこのポリシーに従います。For organization-managed accounts, the GitHub Copilot app policy is enabled. My Work visibility follows this policy.

Hands-on

手順Steps

  1. My Work を開くOpen My Work

    サイドバーの My Work をクリックするか、安全なランチャーを使って開きます。Click My Work in the sidebar, or use the safe launcher to open it.

    期待される結果Expected result: My Work が開き、All、Active、Review requests、Done のデフォルトセクションが表示されます。My Work opens and shows the default All, Active, Review requests, and Done sections.

  2. デフォルトセクションの用途を確認するReview what each default section is for

    各セクションにどの issue や PR が入っているかを確認し、Active と Review requests の違いを把握します。Check which issues and PRs appear in each section, and note the difference between Active and Review requests.

    期待される結果Expected result: 各セクションの目的が理解でき、どのセクションを基点にフィルタリングするか判断できます。You understand each section's purpose and can decide which one to filter from.

  3. 検索バーで has:/no: 修飾子を試すTry the has:/no: qualifiers in the search bar

    セクション内の検索バーに修飾子を入力し、ラベルはあるが担当者がいない issue だけに絞り込みます。Type the qualifiers into the section's search bar to narrow the list to issues that have a label but no assignee.

    担当者未設定の issue を検索Find issues without an assignee 
    is:issue no:assignee has:label
    期待される結果Expected result: 担当者未設定でラベル付きの issue だけが一覧に表示されます。Only unassigned, labeled issues remain in the list.

  4. 複数の修飾子を組み合わせるCombine multiple qualifiers

    is:pr と has:milestone、no:project を組み合わせて、マイルストーンはあるがプロジェクト未設定の PR を探します。Combine is:pr with has:milestone and no:project to find pull requests that have a milestone but no project set.

    マイルストーンはあるがプロジェクト未設定の PR を検索Find pull requests with a milestone but no project 
    is:pr has:milestone no:project
    期待される結果Expected result: 条件に一致する PR だけに一覧が絞り込まれます。The list narrows to only the pull requests matching all the conditions.

  5. フィルターを独自セクションとして保存するSave the filter as a custom section

    デフォルトセクションを編集するか、新しいセクションを追加して、今作成したフィルタークエリを保存します。Edit a default section, or add a new one, and save the filter query you just built.

    期待される結果Expected result: サイドバーの My Work に、保存したフィルターを持つ独自セクションが追加されます。A custom section with your saved filter appears in My Work's sidebar.

  6. セクションの永続性を確認するConfirm the section persists

    アプリを再起動するか、別のプロジェクトへ切り替えてから My Work へ戻り、独自セクションとフィルターが残っていることを確認します。Restart the app, or switch to another project and back, and confirm the custom section and its filter are still there.

    期待される結果Expected result: 独自セクションとフィルターがアプリ再起動後も保持されています。The custom section and its filter survive the app restart.

Verify

完了時の確認Completion checks

  • My Work にデフォルトの 4 セクションが表示され、少なくとも 1 つの独自セクションを保存できた。My Work shows the four default sections and at least one custom section has been saved.
  • has:/no: 修飾子を使った検索が、意図した issue/PR の部分集合だけを返す。A search using has:/no: qualifiers returns only the intended subset of issues or pull requests.
  • アプリを再起動しても保存したセクションとフィルターが失われない。The saved section and its filter survive an app restart.

Recover

トラブルシューティングTroubleshooting

検索しても結果が 0 件になるThe search returns zero results

修飾子のスペルと大文字小文字を確認し、対象セクションのリポジトリ選択が絞られすぎていないか確認します。Check the qualifier spelling and case, and confirm the section's repository selection isn't scoped too narrowly.

has:/no: を入力しても補完されないhas:/no: does not autocomplete

この修飾子は v1.1.0 で追加されました。Settings でアプリのバージョンを確認し、v1.1.0 以降に更新してください。These qualifiers were added in v1.1.0. Check the app version in Settings and update to v1.1.0 or later.

リポジトリ名を変更した後にセクションが消えたA section disappeared after renaming a repository

この問題は v1.0.26 で修正済みです。v1.1.2 に更新し、それでも解決しない場合はセクションを作り直してください。This was fixed in v1.0.26. Update to v1.1.2, and if the section still doesn't reappear, recreate it.

Reset

クリーンアップとリセットCleanup and reset

  1. 演習用に作成した独自セクションが不要であれば、セクションメニューから削除します。Remove the custom section you created for this exercise from the section menu if you no longer need it.
  2. 検索バーに残ったテスト用のクエリをクリアします。Clear any leftover test query from the search bar.
  3. 共有端末では、機密情報を含むフィルターを削除してからサインアウトします。On a shared machine, remove filters containing sensitive information before signing out.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows では My Work の検索バーにサイドバーから直接アクセスできます。WSL 内のリポジトリでも、フィルタリング自体は Windows 側のアプリ UI で行います。On Windows, the My Work search bar is reachable directly from the sidebar. Even for repositories inside WSL, filtering happens in the Windows-side app UI.

macOS

macOS ではキーボードショートカットでセクション内検索にフォーカスを移せます。On macOS, a keyboard shortcut can move focus directly to the in-section search field.

Linux

Linux の AppImage ビルドでも My Work の挙動は同一です。ウィンドウマネージャーによってはショートカットが競合する場合があります。Behavior is identical on the Linux AppImage build. Some window managers may conflict with shortcuts.

WSL

WSL のリモート環境からでも My Work は Windows 側アプリで表示されます。リポジトリ接続はガイド 08 のハンドオフ手順に従ってください。My Work is displayed in the Windows-side app even for WSL remote environments. Follow the handoff steps in guide 08 to connect the repository.
