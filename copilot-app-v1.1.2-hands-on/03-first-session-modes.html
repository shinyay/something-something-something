セッションを開始してモードを選ぶStart a session and choose a mode

新しいワーキングツリー、ローカルリポジトリ、クラウドサンドボックスからセッションの実行場所を選び、Interactive、Plan、Autopilot のモードを使い分けて、安全な最初の実装を Changes で確認します。Choose where a session runs—new working tree, local repository, or cloud sandbox—use Interactive, Plan, and Autopilot modes, and review a safe first implementation in Changes.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

Guide 01 で接続し Guide 02 でモデルを確認したサンプルリポジトリで、まず Plan モードで小さな低リスクの改善を提案させ、Shift+Tab で Autopilot に切り替えて実装させます。実装後は Changes で差分を確認し、プルリクエストを作る前に立ち止まって判断します。In the sample repository connected in Guide 01 and reviewed for models in Guide 02, first have Plan mode propose a small low-risk improvement, switch to Autopilot with Shift+Tab to implement it, then review the diff in Changes and stop before deciding to create a pull request.

機能の境界Feature boundary

このガイドは GitHub Copilot App v1.1.2 におけるセッションの実行場所（新しいワーキングツリー、ローカルリポジトリ、クラウドサンドボックス）の選択、Interactive/Plan/Autopilot モード、Shift+Tab によるモード切り替え、#/@ による参照、そして Changes での差分確認までを扱います。プルリクエストの作成そのもの、レビュー、CI、マージは学習パス 3（GitHub ライフサイクル、特に Guide 13）で扱うため、このガイドは Create PR をクリックする手前で意図的に終わります。Copilot CLI や SDK を使ったヘッドレスな自動化、Issue から起動するバックグラウンドのクラウドエージェントは、それぞれ独自のセッションモデルを持つ隣接機能であり、本ガイドの対象外です。This guide covers choosing where a session runs in GitHub Copilot App v1.1.2—new working tree, local repository, or cloud sandbox—the Interactive, Plan, and Autopilot modes, Shift+Tab mode cycling, #/@ references, and reviewing the diff in Changes. Creating, reviewing, running CI on, and merging the pull request itself belongs to learning path 3 (the GitHub lifecycle, especially Guide 13), so this guide intentionally stops just before clicking Create PR. Headless automation through Copilot CLI or the SDK, and background cloud agents launched from issues, are adjacent capabilities with their own session models and are out of scope here.

安全上の注意Safety note: Autopilot は変更してよいプロジェクトでのみ使ってください。ユーザーの入力を待たずにコードを書き、コマンドを実行し、反復する可能性があります。Changes の差分は Create PR を押す前に必ず確認し、実際の Issue 番号や本番リポジトリへの参照は、この流れに慣れるまで避けてください。Only use Autopilot on a project you are allowed to change, since it can write code, run commands, and iterate without waiting for your input. Always review the diff in Changes before clicking Create PR, and avoid referencing real issue numbers or production repositories until you are comfortable with this workflow.

Prepare

前提条件Prerequisites

  • Guide 01 と Guide 02 を完了し、プロジェクトが接続され、モデルと Auto の基本を確認済みであること。Guides 01 and 02 are complete: a project is connected, and you have reviewed the basics of models and Auto.
  • 変更しても問題のない小さな安全な箇所（サンプルリポジトリなど）が接続済みプロジェクト内にあること。The connected project contains a small, safe area you are allowed to change, such as the sample repository.
  • 新しいワーキングツリーやセッションがブランチを作成することを理解しており、git branch -a や git worktree list で後から確認できること。You understand that a new working tree or session creates a branch, and can inspect it afterward with git branch -a or git worktree list.
  • Autopilot がユーザーの入力を待たずにコードを書きコマンドを実行できることを理解していること。You understand that Autopilot can write code and run commands without waiting for your input.

Hands-on

手順Steps

  1. セッションの実行場所を選ぶChoose where the session runs

    サイドバーの Sessions の + をクリックし、接続済みプロジェクトを選びます。プロンプト欄下のドロップダウンで、新しいワーキングツリー、ローカルリポジトリ、クラウドサンドボックス（パブリックプレビュー）のいずれかを選びます。Click + next to Sessions in the sidebar and choose a connected project. In the dropdown below the prompt field, choose new working tree, your local repository, or a cloud sandbox (public preview).

    既存のワーキングツリーを確認Check existing worktrees 
    git worktree list
    期待される結果Expected result: 選んだ実行場所でセッションが作成され、新しいワーキングツリーを選んだ場合は既存の作業ブランチに影響しない独立したブランチが使われる。The session is created in the chosen environment; if you chose a new working tree, it uses an isolated branch that does not affect your existing work branch.

  2. Plan モードを選び、参照付きプロンプトを送るChoose Plan mode and send a prompt with references

    モードのドロップダウンで Plan を選びます。@ でファイルを、# で関連 Issue があれば参照しながら、低リスクな改善のプランを求めるプロンプトを送ります。Select Plan from the mode dropdown. Send a prompt that asks for a plan for a low-risk improvement, referencing a file with @ and any related issue with #.

    Plan モード用の参照付きプロンプトPlan mode prompt with references 
    In Plan mode, using @ to reference the relevant file and # to reference any related open issue, propose a plan for a small low-risk improvement before writing any code.
    Plan モード用の参照付きプロンプト（日本語）Plan mode prompt with references (Japanese) 
    Plan モードで、@ を使って対象のファイルを、# を使って関連する未解決の Issue があれば参照しながら、コードを書く前に小さく低リスクな改善のプランを提案してください。
    期待される結果Expected result: エージェントがまずプランを提示し、承認するまでコードは変更されない。The agent presents a plan first, and no code is changed until you approve it.

  3. Shift+Tab でモードを切り替えるCycle modes with Shift+Tab

    プロンプト欄にフォーカスがある状態で Shift+Tab を数回押し、Plan、Autopilot、Interactive の順にモード表示が切り替わることを確認します。With focus in the prompt field, press Shift+Tab a few times and confirm the mode indicator cycles through Plan, Autopilot, and Interactive.

    期待される結果Expected result: Shift+Tab を押すたびにモード表示が Plan → Autopilot → Interactive の順に切り替わる。Each press of Shift+Tab advances the mode indicator through Plan, Autopilot, and Interactive.

  4. Autopilot で低リスクな変更を実装させるImplement the low-risk change with Autopilot

    Shift+Tab で Autopilot を選び、公式の低リスク変更プロンプトを送ります。エージェントは入力を待たずにコードを書き、可能であればテストも実行します。Use Shift+Tab to select Autopilot and send the official low-risk change prompt. The agent writes code without waiting for input and runs tests where possible.

    公式の低リスク変更プロンプトOfficial low-risk change prompt 
    Suggest a small low-risk code change in this repository, implement it, and explain the diff.
    公式の低リスク変更プロンプト（日本語）Official low-risk change prompt (Japanese) 
    このリポジトリに小さく低リスクなコード変更を提案し、実装したうえで、その差分を説明してください。
    期待される結果Expected result: エージェントが変更を実装し、実行結果や差分の説明を会話に表示する。The agent implements the change and shows the result or an explanation of the diff in the conversation.

  5. タスク完了後も Autopilot が維持されることを確認するConfirm Autopilot stays selected after the task finishes

    エージェントがタスクを終えた後、モードの表示が Autopilot のままであり、自動的に Interactive へ戻っていないことを確認します（v1.1.1 で修正）。After the agent finishes the task, confirm the mode indicator still shows Autopilot instead of automatically switching back to Interactive (fixed in v1.1.1).

    期待される結果Expected result: タスク完了後もモード表示が Autopilot のままである。The mode indicator still shows Autopilot after the task completes.

  6. Changes で差分を確認するReview the diff in Changes

    プロンプト欄の上にある Changes をクリックし、変更されたファイルと差分を確認します。意図した低リスクな変更以外に触れられたファイルがないかを確認します。Click Changes above the prompt box and review the changed files and diff. Confirm no files were touched beyond the intended low-risk change.

    期待される結果Expected result: Changes に、依頼した低リスクな変更に対応する差分だけが表示される。Changes shows only the diff corresponding to the low-risk change you requested.

  7. プルリクエストを作る前に立ち止まるStop before creating a pull request

    差分に問題がなければ、次のアクションが Create PR であることを確認したうえで、あえてまだクリックしません。必要であれば同じセッションで反復を続けます。If the diff looks correct, confirm that Create PR is the next available action, but deliberately do not click it yet. Continue iterating in the same session if needed.

    期待される結果Expected result: セッションは開いたままで、変更はまだプルリクエストになっておらず、レビューを続けられる状態になっている。The session remains open, the change has not become a pull request yet, and it is still available for further review.

Verify

完了時の確認Completion checks

  • 新しいワーキングツリー、ローカルリポジトリ、クラウドサンドボックスのいずれかでセッションを開始できた。A session was started in one of new working tree, local repository, or cloud sandbox.
  • Shift+Tab で Plan、Autopilot、Interactive を切り替えられ、Autopilot がタスク完了後も選択されたままだった。Shift+Tab cycled through Plan, Autopilot, and Interactive, and Autopilot remained selected after the task completed.
  • Changes に期待どおりの低リスクな差分が表示され、Create PR はまだクリックしていない。Changes shows the expected low-risk diff, and Create PR has not been clicked yet.

Recover

トラブルシューティングTroubleshooting

Shift+Tab を押してもモードが切り替わらないShift+Tab does not change the mode

プロンプト欄（コンポーザー）にフォーカスがあることを確認し、v1.1.1 以降を使っていることを確認します。この切り替えは v1.1.1 で追加された機能です。Confirm focus is in the message composer and that you are on v1.1.1 or later. This shortcut was added in v1.1.1.

Autopilot でのタスク完了後、モードが Interactive に戻ってしまうThe mode reverts to Interactive after Autopilot finishes a task

v1.1.1 でこの問題は修正済みです。最新版に更新しても再現する場合は、セッション ID と再現手順を添えて公式リポジトリの Issue に報告してください。This was fixed in v1.1.1. If it still reproduces on the latest version, report it in the official repository with the session ID and reproduction steps.

実行場所のドロップダウンにクラウドサンドボックスの選択肢が出ないCloud sandbox does not appear in the environment dropdown

クラウドサンドボックスはパブリックプレビューであり、アカウントや組織の設定によって利用できない場合があります。代わりに新しいワーキングツリーまたはローカルリポジトリを選び、必要であれば利用条件をアカウント設定で確認してください。Cloud sandbox is in public preview and may not be available depending on your account or organization settings. Choose new working tree or your local repository instead, and check eligibility in your account settings if needed.

Reset

クリーンアップとリセットCleanup and reset

  1. 変更を残さない場合は、セッションのメニューからワーキングツリーやブランチを破棄します。If you do not want to keep the change, discard the working tree or branch from the session's menu.
  2. クラウドサンドボックスを使った場合は、使い終わったセッションを停止またはアーカイブし、プレビュー中の実行枠を占有したままにしないようにします。If you used a cloud sandbox, stop or archive the session when finished so it does not keep occupying preview capacity.
  3. 差分を確認し終えた練習用セッションは、Guide 04 や Guide 13 に進む前にアーカイブまたは削除して整理します。Archive or delete the practice session once you have reviewed its diff, before moving on to Guide 04 or Guide 13.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Shift+Tab は標準の Windows キー入力として機能します。ローカルリポジトリで作業する場合は、core.autocrlf の設定によって Changes の差分に無関係な改行コードの変更が含まれないよう確認してください。Shift+Tab works as a standard Windows key combination. When working in your local repository, check your core.autocrlf setting so Changes does not show unrelated line-ending noise.

macOS

Shift+Tab は同様に機能しますが、まれにシステム設定側のキーボードショートカットと競合することがあります。反応しない場合は システム設定 > キーボード のショートカット割り当てを確認してください。Shift+Tab works the same way, though it can occasionally conflict with a system-level keyboard shortcut. If it does not respond, check shortcut assignments in System Settings > Keyboard.

Linux

一部のウィンドウマネージャーは Shift+Tab をワークスペース切り替えなどに割り当てていることがあります。反応しない場合はウィンドウマネージャー側のキーバインド設定を確認してください。Some window managers bind Shift+Tab to actions like workspace switching. If it does not respond, check your window manager's keybinding settings.

WSL

WSL 内のリポジトリをローカルリポジトリとして扱う場合、モードのドロップダウンや Shift+Tab の動作自体は Windows / macOS / Linux と同じアプリ側の機能です。v1.1.2 で強化された WSL リモート接続の信頼性についてはガイド 08 を参照してください。When treating a repository inside WSL as your local repository, the mode dropdown and Shift+Tab behavior are the same app-level feature as on Windows, macOS, and Linux. See Guide 08 for the WSL remote connection reliability improvements added in v1.1.2.
