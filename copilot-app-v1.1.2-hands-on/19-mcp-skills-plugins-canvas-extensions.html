MCP・スキル・プラグイン・Canvas 拡張を使い分けるUse MCP, skills, plugins, and Canvas extensions together

外部ツールを繋ぐ MCP サーバー、タスク別の指示であるスキル、まとめて配布するプラグイン、共同編集できる Canvas 拡張の違いを理解し、それぞれを安全に有効化します。Understand the differences between MCP servers that connect external tools, task-specific skills, bundled plugins, and collaborative Canvas extensions, and enable each of them safely.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

サンプルリポジトリで、OAuth 認証が必要な MCP サーバーを1つ接続し、デフォルトのマーケットプレイスからプラグインを1つ入れ、プロジェクト共有の小さな Canvas 拡張を1つ作る、という一連の作業を扱います。You connect one OAuth-based MCP server, install one plugin from a default marketplace, and build one small project-shared Canvas extension in a sample repository.

機能の境界Feature boundary

このガイドは GitHub Copilot App の Settings 画面（MCP Servers、Skills、Plugins）とセッション内 /create-canvas から行う、MCP サーバー・スキル・プラグイン・Canvas 拡張の4つの拡張機構を扱います。これらの設定の元になる Copilot CLI 側のファイルやコマンド（~/.copilot/mcp-config.json、copilot plugin install、.github/copilot/settings.json など）は、同じ設定を別のクライアントから操作する隣接領域として触れるに留め、CLI での操作手順そのものは対象外です。This guide covers the four extension mechanisms available from the GitHub Copilot app's Settings screens (MCP Servers, Skills, Plugins) and in-session /create-canvas: MCP servers, skills, plugins, and Canvas extensions. The underlying Copilot CLI files and commands that back the same configuration (~/.copilot/mcp-config.json, copilot plugin install, .github/copilot/settings.json, and similar) are mentioned only as an adjacent surface that edits the same configuration from a different client; CLI operating steps themselves are out of scope.

安全上の注意Safety note: MCP サーバーの API キーやトークンは、チャットのプロンプトに貼り付けないでください。OAuth のサインインフロー、または MCP サーバーの資格情報・ヘッダー入力欄だけに入力します。既定以外のマーケットプレイスやリポジトリ定義の MCP サーバー・スキルを有効化する前に、そのリポジトリが信頼できることを確認してください。Never paste MCP server API keys or tokens into a chat prompt. Enter them only through the OAuth sign-in flow, or an MCP server's own credential or header fields. Before enabling a non-default marketplace, or a repository-defined MCP server or skill, confirm that the repository is one you trust.

Prepare

前提条件Prerequisites

  • GitHub Copilot App v1.1.2 でサインイン済みで、書き込み権限のあるプロジェクトが1つ接続されていること。You are signed in to GitHub Copilot app v1.1.2 with one project connected that you have write access to.
  • リポジトリの「信頼」がどのような意味を持つか理解しており、信頼していないリポジトリのエージェント定義や MCP 設定を有効化しないこと。You understand what trusting a repository means, and that you should not enable agent definitions or MCP configuration from a repository you do not trust.
  • 少なくとも1つの OAuth 対応 MCP サーバーのアカウントを持っているか、パブリックなテスト用サーバーで代用できること。You have an account with at least one OAuth-capable MCP server, or can substitute a public test server.
  • プロジェクト共有の Canvas 拡張やプラグイン設定をコミットする場合に備え、.github/ 配下への書き込み権限があること。You have write access under .github/ in case you commit a project-shared Canvas extension or plugin configuration.

Hands-on

手順Steps

  1. MCP サーバーを追加し OAuth でサインインするAdd an MCP server and sign in with OAuth

    Settings → MCP Servers を開き、カタログから選ぶかカスタムサーバーを追加します。OAuth が必要なサーバーはアプリ内のサインインフローを使い、トークンをチャットに貼り付けないでください。Open Settings → MCP Servers, and choose one from the catalog or add a custom server. For servers that require OAuth, use the in-app sign-in flow, and never paste a token into chat.

    期待される結果Expected result: サーバーのステータスが Connected になり、利用可能なツールが一覧に表示されます。The server's status shows Connected, and its available tools are listed.

  2. リポジトリ定義の MCP サーバーの信頼と有効/無効を確認するConfirm trust and enable/disable for repository-defined MCP servers

    プロジェクトの MCP 設定セクションを開き、信頼済みリポジトリで定義された MCP サーバーの接続状況を確認します。ここから個々のサーバーを有効/無効にできます。信頼していないリポジトリのサーバーは有効化しないでください。Open the project's MCP settings section and review the connection status of MCP servers defined in the trusted repository. You can enable or disable individual servers from here. Do not enable a server from a repository you do not trust.

    期待される結果Expected result: 信頼済みリポジトリのサーバーだけが一覧に表示され、必要に応じて有効/無効を切り替えられます。Only servers from the trusted repository appear, and you can toggle each one on or off as needed.

  3. Skills 設定を確認するReview the Skills settings

    Settings → Skills を開き、リポジトリまたは Copilot CLI 側の設定から自動的に一覧に出ているスキルを確認します。必要であればカスタムのスキルディレクトリを追加します。Open Settings → Skills and review the skills already listed automatically from the repository or Copilot CLI configuration. Add a custom skill directory if you need one.

    期待される結果Expected result: 既存のスキルが一覧に表示され、追加したカスタムディレクトリも認識されます。Existing skills are listed, and any custom directory you add is recognized.

  4. デフォルトのマーケットプレイスからプラグインをインストールするInstall a plugin from a default marketplace

    Settings → Plugins を開き、Editor's Picks または Browse by Category から、awesome-copilot に含まれる Impeccable のようなプラグインをインストールします。下のランチャーでインストールフォームを直接開くこともできます。Open Settings → Plugins, then install a plugin such as Impeccable from awesome-copilot, either from Editor's Picks or Browse by Category. You can also open the install form directly using the launcher below.

    リポジトリのプラグイン設定（.github/copilot/settings.json）Repository plugin configuration (.github/copilot/settings.json) 
    {
  "enabledPlugins": ["impeccable@awesome-copilot"],
  "extraKnownMarketplaces": {
    "acme-plugins": "https://github.com/acme/plugins"
  }
}
    期待される結果Expected result: プラグインが Installed として表示され、それが提供するエージェントやスキルが利用可能になります。The plugin shows as Installed, and the agents or skills it provides become available.

  5. 非デフォルトのマーケットプレイスを追加する（必要な場合のみ）Add a non-default marketplace (only if needed)

    社内や個人のマーケットプレイスを使いたい場合だけ、Settings → Plugins からマーケットプレイスを追加します。追加前に、そのリポジトリまたは URL を信頼できるかどうかを確認してください。Only if you need an internal or personal marketplace, add it from Settings → Plugins. Before adding it, confirm you trust the source repository or URL.

    期待される結果Expected result: 追加したマーケットプレイスのプラグイン一覧が表示され、信頼できないものは追加していません。The added marketplace's plugin list appears, and you have not added anything you do not trust.

  6. セッション内で Canvas 拡張を作成するCreate a canvas extension inside a session

    セッションを開き、下のプロンプトのように /create-canvas を使ってボードを作らせます。チーム共有にするならプロジェクトスコープ（.github/extensions）を、個人用ならユーザースコープ（~/.copilot/extensions）を選びます。Open a session and use /create-canvas as in the prompt below to have the agent build the board. Choose project scope (.github/extensions) to share it with the team, or user scope (~/.copilot/extensions) to keep it personal.

    Canvas 拡張を作成するプロンプトPrompt that creates a canvas extension 
    /create-canvas Create a small triage board canvas with columns for New, Investigating, and Done, plus agent-callable capabilities to add and move cards.
    期待される結果Expected result: 右側パネルに Canvas が開き、選んだスコープのディレクトリにファイルが作成されます。The canvas opens in the right side panel, and files are created under the directory matching the scope you chose.

  7. Canvas を操作し、URL からのインストールも確認するInteract with the canvas and confirm installing from a URL

    作成した Canvas のボタンやカードを直接操作し、続けてエージェントにもカードの追加や移動を依頼します。プロジェクトスコープを選んだ場合は、下のコマンドでファイルの配置を確認します。別のマシンでは、Extensions の Canvas タブの「Install from URL…」を使って gist や GitHub フォルダーの URL からインストールできることも確認します（v1.0.24 以降）。Interact with the canvas's buttons or cards directly, then also ask the agent to add or move a card. If you chose project scope, use the command below to confirm the file layout. On another machine, also confirm you can use “Install from URL…” in the Extensions Canvas tab to install from a gist or GitHub folder URL, since v1.0.24.

    プロジェクト共有 Canvas 拡張の一覧List project-shared canvas extensions 
    ls .github/extensions
    期待される結果Expected result: UI 操作とエージェントの呼び出しの両方でボードの状態が更新され、プロジェクトスコープのファイルが .github/extensions 配下に存在します。The board's state updates from both UI actions and agent calls, and the project-scoped files exist under .github/extensions.

Verify

完了時の確認Completion checks

  • MCP サーバーが Connected と表示され、トークンをチャットのプロンプトに貼り付けていない。The MCP server shows Connected, and no token was pasted into a chat prompt.
  • インストールしたプラグインが Settings → Plugins に表示され、それが提供するエージェントやスキルが使える。The installed plugin appears in Settings → Plugins, and the agents or skills it provides work.
  • 作成した Canvas 拡張が選んだスコープ（.github/extensions または ~/.copilot/extensions）のディレクトリに存在し、右側パネルで正しく開く。The created canvas extension exists under the directory matching the scope you chose (.github/extensions or ~/.copilot/extensions), and opens correctly in the right side panel.
  • 信頼していないリポジトリ由来の MCP サーバー、スキル、マーケットプレイスを有効化していない。You have not enabled an MCP server, skill, or marketplace from a repository you do not trust.

Recover

トラブルシューティングTroubleshooting

サードパーティ OAuth の MCP サーバーが「authenticating」のまま止まるA third-party OAuth MCP server stays stuck on “authenticating”

この不具合は v1.0.16 と v1.1.0 でそれぞれ修正されています。v1.1.2 に更新し、サインインをやり直してください。This bug was fixed separately in v1.0.16 and v1.1.0. Update to v1.1.2 and retry the sign-in.

Windows でプラグインのマーケットプレイス追加やインストールが失敗するAdding a plugin marketplace or installing a plugin fails on Windows

アプリ同梱の Git で資格情報ヘルパーのサイドカーが起動できず失敗する不具合が v1.0.17 で修正されています。プライベートリポジトリのクローンに失敗する不具合も同じバージョンで修正済みです。v1.1.2 に更新してください。A bug where the bundled Git's credential helper sidecar failed to launch, causing this to fail, was fixed in v1.0.17. A separate bug where cloning private repositories failed was also fixed in the same version. Update to v1.1.2.

設定したカスタムスキルディレクトリが無視されるA configured custom skill directory is ignored

Settings で設定したカスタムスキルディレクトリがスキル実行時に無視される不具合が v1.0.17 で修正されています。v1.1.2 に更新し、パスが正しいか再確認してください。A bug where custom skill directories configured in Settings were ignored when running skills was fixed in v1.0.17. Update to v1.1.2 and double-check the path is correct.

プロジェクトスコープの Canvas で New session が汎用の Canvas ピッカーを開いてしまうNew session on a project-scoped canvas opens the generic canvas picker instead

Extensions の Canvas タブでプロジェクトスコープの Canvas から New session を選んだときに、直接セッションを開始せず汎用ピッカーが開いてしまう不具合が v1.0.19 で修正されています。v1.1.2 に更新してください。A bug where choosing New session on a project-scoped canvas in the Extensions Canvas tab opened the generic canvas picker instead of starting the session directly was fixed in v1.0.19. Update to v1.1.2.

Reset

クリーンアップとリセットCleanup and reset

  1. テストのために接続した MCP サーバーは無効化するか削除し、必要であれば OAuth 側のアプリ連携も取り消します。Disable or remove the MCP server you connected for testing, and revoke the OAuth app authorization on the provider's side if needed.
  2. テストでインストールしたプラグインをアンインストールし、テストのためだけに追加したマーケットプレイスも削除します。Uninstall the plugin you installed for testing, and remove any marketplace you added only for the test.
  3. 追加したカスタムスキルディレクトリが不要であれば設定から外します。Remove the custom skill directory from settings if it is no longer needed.
  4. テスト用の Canvas 拡張ディレクトリ（.github/extensions または ~/.copilot/extensions 配下）を削除し、プロジェクトスコープでコミットしていた場合はそのプルリクエストも閉じます。Delete the test canvas extension directory under .github/extensions or ~/.copilot/extensions, and close the pull request if you committed a project-scoped copy.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows ではアプリ同梱の Git を使う場合、プラグインのマーケットプレイス追加やプライベートリポジトリのクローンに関する既知の不具合が v1.0.17 で修正されています。パス区切りは .github\extensions のようにバックスラッシュでも、Git Bash 経由のフォワードスラッシュでも動作します。On Windows, using the app's bundled Git, known issues with adding plugin marketplaces and cloning private repositories were fixed in v1.0.17. Path separators work either as backslashes, like .github\extensions, or as forward slashes through Git Bash.

macOS

macOS では Canvas 拡張や MCP サーバーの設定ファイルは通常のホームディレクトリ配下に置かれ、Finder の「隠しフォルダを表示」で ~/.copilot/extensions を確認できます。On macOS, canvas extension and MCP server configuration files live under your normal home directory; enable “Show hidden files” in Finder to inspect ~/.copilot/extensions.

Linux

Linux では、ログインシェルのプロファイルで設定した PATH エントリなど、カスタム PATH 経由のツールが拡張機能から見つからない不具合が v1.0.26 で修正されています。スキルやプラグインが外部コマンドを呼び出す場合は、この修正を含む v1.1.2 を使ってください。On Linux, a bug where tools installed via the login shell profile, such as custom PATH entries, were not found by extensions was fixed in v1.0.26. Use v1.1.2, which includes this fix, if your skills or plugins call external commands.

WSL

WSL リモート環境では、v1.1.2 で GitHub の Issue/PR ワークフロースキルが標準搭載され、リモートセッション接続の信頼性も向上しています。Canvas やプラグインの拡張機能ファイルは、開いているプロジェクトがホスト側か WSL ディストリビューション内かに応じて置き場所が変わります。In WSL remote environments, v1.1.2 bundles GitHub pull request and issue workflow skills by default and improves remote session connection reliability. Where canvas and plugin extension files live depends on whether the open project is on the host or inside the WSL distribution.
