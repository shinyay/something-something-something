カスタムエージェントを作成して使うCreate and use custom agents

リポジトリまたはユーザーレベルでカスタムエージェントを定義し、エージェントピッカーと /agent からブランチ・worktree 単位でも正しく呼び出せることを確認します。Define a custom agent at the repository or user level, then confirm it can be selected from the agent picker and /agent even when it is scoped to a single branch or worktree.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

サンプルリポジトリの1つのブランチだけに、ドキュメントレビュー専門のカスタムエージェントを定義し、そのセッションのピッカーと /agent から選べることを確認します。You define a documentation-review custom agent on a single branch of a sample repository, and confirm it can be selected from that session's picker and /agent.

機能の境界Feature boundary

このガイドは GitHub Copilot App 内でのカスタムエージェントの定義（プロジェクトまたはユーザーレベル、ブランチ/worktree 限定を含む）と、エージェントピッカーおよび /agent からの選択を扱います。同じエージェントプロファイル形式は VS Code、JetBrains、Eclipse、Xcode、素の Copilot CLI でも動作しますが、それらのクライアントでの作成手順は隣接領域として深く扱いません。This guide covers defining custom agents inside the GitHub Copilot app, at the project or user level, including branch- or worktree-only definitions, and selecting them from the agent picker and /agent. The same agent-profile format also works in VS Code, JetBrains IDEs, Eclipse, Xcode, and plain Copilot CLI, but this guide treats creation in those other clients as an adjacent surface it does not cover in depth.

安全上の注意Safety note: エージェントプロファイルの指示欄にシークレットや資格情報を書かないでください。tools を制限しないカスタムエージェントは既定で全ツールにアクセスできるため、リポジトリを信頼する前に、共有プロジェクトへ追加するエージェントの権限は明示的に絞ってください。Do not put secrets or credentials in an agent profile's instructions. A custom agent without a tools restriction has access to all tools by default, so explicitly scope the permissions of any agent you add to a shared project before you trust the repository.

Prepare

前提条件Prerequisites

  • GitHub Copilot App が v1.1.2 に更新されており、書き込み権限のあるプロジェクトが1つ接続されていること。The GitHub Copilot app is updated to v1.1.2 and one project you have write access to is connected.
  • YAML フロントマター付き Markdown ファイルの基本的な書き方を理解していること。You understand the basics of writing a Markdown file with YAML frontmatter.
  • プロジェクト（.github/agents/）とユーザー（~/.copilot/agents/）のどちらにエージェントを置くか、チームで共有するか個人用に留めるかを決めていること。You have decided whether the agent belongs in the project (.github/agents/) or user (~/.copilot/agents/) location, and whether it should be shared with the team or kept personal.
  • テストに使う一時的なブランチまたは worktree を作成できること。You can create a temporary branch or worktree to use for testing.

Hands-on

手順Steps

  1. 配置場所とスコープを決めるDecide the location and scope

    チームで共有するなら .github/agents/（プロジェクト）に、自分専用にするなら ~/.copilot/agents/（ユーザー）に置きます。同名のエージェントがある場合はユーザー側が優先されます。今回はブランチ/worktree 限定の挙動を確認するため、テスト用ブランチの .github/agents/ に作成します。Place it under .github/agents/ (project) to share it with the team, or under ~/.copilot/agents/ (user) to keep it personal. If both locations define an agent with the same name, the user-level one wins. To verify branch/worktree-only behavior here, create it under .github/agents/ on a test branch.

    期待される結果Expected result: テスト用ブランチが作成され、そのブランチにだけエージェントファイルを追加する準備ができています。A test branch exists and you are ready to add the agent file only on that branch.

  2. エージェントプロファイルを作成するCreate the agent profile

    下のひな形を参考に、name・description・任意の tools を含む YAML フロントマターと、指示本文を書いた docs-reviewer.agent.md を作成します。読み取り専用に近い動作にしたいので、tools を view/grep/glob に絞ります。Using the template below, create docs-reviewer.agent.md with YAML frontmatter for name, description, and optional tools, followed by the instruction body. Restrict tools to view/grep/glob to keep this close to read-only behavior.

    エージェントプロファイルのひな形Agent profile template 
    ---
name: docs-reviewer
description: Reviews README and CONTRIBUTING files for outdated setup steps and unclear instructions. Use for documentation-only review requests.
tools: ["view", "grep", "glob"]
---
You are a documentation reviewer. Your scope is limited to README, CONTRIBUTING, and other documentation files.
Focus on the following:
- Flag outdated install or setup steps
- Flag unclear or ambiguous instructions
- Suggest concrete rewrites, but do not modify code files
    期待される結果Expected result: ブランチにファイルが追加され、tools が明示的に制限されています。The file is added on the branch, with tools explicitly restricted.

  3. そのブランチ/worktree のセッションを開き直すReopen the session for that branch or worktree

    新しいセッションを開くか、既存セッションを開き直して、追加したエージェントファイルを認識させます。Open a new session, or reopen an existing one, so the newly added agent file is picked up.

    期待される結果Expected result: セッションがそのブランチ/worktree のコンテキストで開いています。The session is open in the context of that branch or worktree.

  4. エージェントピッカーと /agent オートコンプリートで確認するConfirm it in the agent picker and /agent autocomplete

    エージェントピッカーを開くか、プロンプト欄で /agent と入力し、docs-reviewer がブランチ限定であっても正しく一覧に表示されることを確認します（v1.1.2 での修正点）。Open the agent picker, or type /agent in the prompt box, and confirm docs-reviewer appears correctly in the list even though it is branch-scoped — this is the fix delivered in v1.1.2.

    期待される結果Expected result: docs-reviewer がピッカーと /agent の候補の両方に表示されます。docs-reviewer appears in both the picker and the /agent suggestions.

  5. 明示的な指示でエージェントを呼び出すInvoke the agent with an explicit instruction

    下のプロンプトのように、エージェント名を明示してタスクを依頼します。Ask for the task while explicitly naming the agent, as in the prompt below.

    エージェントを明示的に呼び出すプロンプトPrompt that explicitly invokes the agent 
    Use the docs-reviewer agent to check README.md and CONTRIBUTING.md for outdated setup instructions.
    エージェントを明示的に呼び出すプロンプト（日本語）Prompt that explicitly invokes the agent (Japanese) 
    docs-reviewer エージェントを使って、README.md と CONTRIBUTING.md に古いセットアップ手順がないか確認してください。
    期待される結果Expected result: サブエージェントとして docs-reviewer が起動し、指定したファイルだけを対象にレビュー結果を返します。docs-reviewer runs as a subagent and returns review results scoped only to the files you specified.

  6. ツール制限が実際に効いているか確認するConfirm the tool restriction actually applies

    エージェントにファイル変更やコマンド実行を依頼してみて、tools で許可していない操作は拒否されるか、実行されないことを確認します。Ask the agent to modify a file or run a command, and confirm actions not permitted by its tools list are refused or simply do not happen.

    期待される結果Expected result: 許可されていない操作は実行されず、制限が意図どおりに機能しています。The disallowed action does not run, confirming the restriction works as intended.

  7. 共有するかどうかを最終決定するDecide whether to share it

    チームで使いたい場合は、.github/agents/docs-reviewer.agent.md をコミットして通常のプルリクエストとしてレビューに出します。個人用に留めたい場合は、代わりに ~/.copilot/agents/ にコピーし、ブランチ上のファイルは削除します。必要であれば Settings → Sessions の Default agent に設定します（v1.0.18 以降）。If you want the team to use it, commit .github/agents/docs-reviewer.agent.md and send it through a normal pull request review. If you want to keep it personal, copy it to ~/.copilot/agents/ instead and remove the branch copy. Optionally set it as the Default agent in Settings → Sessions, available since v1.0.18.

    期待される結果Expected result: エージェントが意図した範囲（チーム共有かユーザー個人か）だけに存在しています。The agent exists only in the scope you intended — shared with the team or kept personal.

Verify

完了時の確認Completion checks

  • ブランチ/worktree 限定で追加した docs-reviewer が、そのセッションのエージェントピッカーと /agent の両方に表示される。The branch/worktree-only docs-reviewer agent appears in both the agent picker and /agent for that session.
  • 明示的にエージェント名を指定した依頼が、指定したファイルだけを対象にサブエージェントとして完了する。A request that explicitly names the agent completes as a subagent scoped only to the files you specified.
  • tools で許可していない操作は拒否されるか実行されず、制限が有効に機能している。Actions not permitted by the tools list are refused or do not run, confirming the restriction is effective.
  • 共有を選んだ場合は .github/agents/ に、個人用を選んだ場合は ~/.copilot/agents/ にのみエージェントファイルが存在する。The agent file exists only in .github/agents/ if you chose to share it, or only in ~/.copilot/agents/ if you chose to keep it personal.

Recover

トラブルシューティングTroubleshooting

ブランチ限定のエージェントがピッカーや /agent に出てこないA branch-only agent does not appear in the picker or /agent

この不具合は v1.1.2 で修正されています。アプリを v1.1.2 に更新し、対象のブランチ/worktree のセッションであることを確認してください。This bug was fixed in v1.1.2. Update the app to v1.1.2 and confirm the session is actually scoped to that branch or worktree.

プロジェクトとユーザーの両方に同名のエージェントがあり、意図と違う方が使われるBoth project and user locations define an agent with the same name, and the wrong one is used

同名の場合はユーザーレベル（~/.copilot/agents/）が優先されます。プロジェクト側を使わせたい場合は名前を変えるか、ユーザー側のファイルを削除・リネームしてください。When names collide, the user-level file (~/.copilot/agents/) takes precedence. Rename one of them, or remove the user-level file, if you want the project-level agent to be used instead.

カスタムエージェントが想定より多くのツールにアクセスできるThe custom agent has access to more tools than expected

tools フィールドを省略すると既定ですべてのツールにアクセスできます。プロファイルに明示的な tools 一覧を追加し、セッションを開き直してください。Omitting the tools field grants access to all tools by default. Add an explicit tools list to the profile and reopen the session.

エージェントを追加した直後、一覧に反映されないThe agent list does not reflect a file you just added

エージェントファイルの追加や変更は新しいセッションまたは開き直しで反映されます。既存セッションを開いたままにせず、一度セッションを開き直してください。Adding or editing an agent file is picked up by a new session or a reopened one. Reopen the session instead of relying on one left open from before the change.

Reset

クリーンアップとリセットCleanup and reset

  1. テストに使った docs-reviewer.agent.md はブランチにコミットする予定がなければ削除します。Delete the test docs-reviewer.agent.md file if you do not plan to commit it on the branch.
  2. テストのために作成したブランチや worktree を削除します。Delete the branch or worktree created only for this test.
  3. テストのために設定した Default agent を、通常使うエージェントに戻します。Reset the Default agent setting back to whatever you normally use, if you changed it only for this test.
  4. チーム共有として追加した場合は、レビューされていない一時的な変更が残っていないか、そのプルリクエストを確認します。If you added the agent for team sharing, review the pull request to confirm it does not include leftover temporary changes.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

Windows でもエージェントファイルの配置場所は同じです。~/.copilot/agents/ は %USERPROFILE%\.copilot\agents\ に対応します。Agent file locations are the same on Windows. ~/.copilot/agents/ corresponds to %USERPROFILE%\.copilot\agents\.

macOS

macOS では ~/.copilot/agents/ がホームディレクトリ配下にそのまま作成されます。Finder で隠しフォルダーを表示すると内容を確認できます。On macOS, ~/.copilot/agents/ is created directly under your home directory. Show hidden folders in Finder to inspect its contents.

Linux

Linux でも ~/.copilot/agents/ が使われます。複数ユーザーで共有する端末では、パーミッションが自分のホームディレクトリに閉じていることを確認してください。Linux also uses ~/.copilot/agents/. On a machine shared by multiple users, confirm the permissions keep it scoped to your own home directory.

WSL

WSL リモート環境のプロジェクトを開いている場合、.github/agents/ はそのディストリビューション内のリポジトリに存在し、~/.copilot/agents/ はホスト側かディストリビューション内かが設定によって変わります。作成後は該当セッションの一覧に出るか必ず確認してください。When you open a project in a WSL remote environment, .github/agents/ lives in the repository inside that distribution, while ~/.copilot/agents/ resolves to the host or the distribution depending on your setup. Always confirm the agent appears in that session's list after creating it.
