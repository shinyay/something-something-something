モデル、Auto、BYOK を構成するConfigure models, Auto, and BYOK

GitHub ホスト型モデルと Auto の切り替え、reasoning effort の永続化、そしてローカル BYOK によるモデルプロバイダーの追加方法を確認します。Review GitHub-hosted models and the Auto switch, reasoning effort persistence, and how to add a local BYOK model provider.

Scenario & scope

シナリオと対象範囲Scenario and scope

具体的なシナリオConcrete scenario

Guide 01 で接続したサンプルリポジトリを使い、まず GitHub ホスト型モデルで Auto と reasoning effort の挙動を確認し、そのあと OpenAI 互換のエンドポイントなど任意の1つのプロバイダーをローカル BYOK として追加して、同じセッションでモデルを切り替えて比較します。Using the sample repository connected in Guide 01, first observe how Auto and reasoning effort behave with GitHub-hosted models, then add one local BYOK provider, such as an OpenAI-compatible endpoint, and compare it against GitHub-hosted models in the same session.

機能の境界Feature boundary

このガイドは GitHub Copilot App v1.1.2 の Model Providers 設定内で完結するモデル構成（GitHub ホスト型モデル、Auto、reasoning effort、ローカル BYOK プロバイダーの追加）を扱います。Copilot CLI、VS Code や JetBrains などの IDE 拡張、Copilot SDK にも同様の BYOK 機構がありますが、これらは資格情報もモデル一覧もアプリとは別に管理される隣接サーフェスであり、本ガイドの対象外です。組織や Enterprise 管理者が設定するサーバー側の Enterprise BYOK（Enable custom models ポリシー）も、ユーザー個別のローカル BYOK とは別の仕組みであり、ここでは扱いません。This guide covers model configuration that lives entirely inside GitHub Copilot App v1.1.2's Model Providers settings: GitHub-hosted models, Auto, reasoning effort, and adding a local BYOK provider. Copilot CLI, IDE extensions such as VS Code and JetBrains, and the Copilot SDK have their own equivalent BYOK mechanisms, but each manages its own credentials and model list separately from the app, so they are out of scope here. Server-side Enterprise BYOK, configured by organization or enterprise administrators through the Enable custom models policy, is a separate mechanism from per-user local BYOK and is not covered in this guide.

安全上の注意Safety note: API キーなどの資格情報は Model Providers の資格情報欄にのみ入力し、プロンプト、コマンド例、ファイル名、コミットメッセージには絶対に貼り付けないでください。practice 用に追加したプロバイダーは検証が終わったら削除し、共有端末では特に、システム資格情報ストアに残さないようにしてください。Enter credentials such as API keys only in the Model providers credential field, never in prompts, command examples, filenames, or commit messages. Remove any provider you added for practice once you are done verifying it, and take extra care on shared machines to avoid leaving entries behind in the system credential store.

Prepare

前提条件Prerequisites

  • Guide 01 を完了し、GitHub Copilot App にサインイン済みで、少なくとも 1 つのプロジェクトが接続されていること。Guide 01 is complete: the GitHub Copilot app is signed in and at least one project is connected.
  • ローカル BYOK を試す場合は、サポートされているプロバイダー（OpenAI、Azure OpenAI、Microsoft Foundry、Anthropic、Ollama、Foundry Local、LM Studio、または任意の OpenAI 互換 HTTP エンドポイント）のいずれかについて、有効な API キーまたは接続情報を用意していること。If you plan to try local BYOK, you have valid credentials or connection details for one supported provider: OpenAI, Azure OpenAI, Microsoft Foundry, Anthropic, Ollama, Foundry Local, LM Studio, or any OpenAI-compatible HTTP endpoint.
  • 自分のアカウントが Copilot プランを持っているか、それとも独自のモデルプロバイダーだけで利用しているかを把握していること。これにより GitHub Copilot が自動的に読み取り専用プロバイダーとして表示されるかどうかを判断できます。You know whether your account has a Copilot plan or relies only on your own model provider, since this determines whether GitHub Copilot appears automatically as a read-only provider.
  • OS のシステム資格情報ストア（Windows Credential Manager、macOS キーチェーン、または Linux のキーリング）を後で確認できる状態であること。You are able to open your OS system credential store later—Windows Credential Manager, macOS Keychain, or a Linux keyring.

Hands-on

手順Steps

  1. Model Providers 設定を開き、自動表示を確認するOpen Model Providers settings and check the automatic entry

    アプリの設定を開き、Model Providers を選びます。有効な Copilot シートでサインインしている場合、GitHub Copilot が読み取り専用のプロバイダーとして自動的に一覧に表示されます。Open app settings and choose Model providers. If you are signed in with an active Copilot seat, GitHub Copilot appears automatically in the list as a read-only provider.

    期待される結果Expected result: GitHub Copilot エントリが一覧に表示され（Copilot シートがある場合）、編集や削除ができない読み取り専用として示されている。The GitHub Copilot entry appears in the list (if you have a Copilot seat) and is shown as read-only, without edit or delete controls.

  2. モデルピッカーで Auto と Previous models を確認するReview Auto and Previous models in the model picker

    プロンプト欄下のモデルピッカーを開きます。上部に専用の説明が付いた Auto のスイッチがあり、古いモデルバージョンは Previous models セクションにまとめられています。Open the model picker below the prompt field. Auto appears as a switch at the top with its own summary, and older model versions are grouped into a Previous models section.

    期待される結果Expected result: Auto のスイッチとその説明、および Previous models セクションが表示され、現行モデルと区別できる。The Auto switch with its summary, plus a Previous models section, are visible and clearly separated from current models.

  3. Auto でプロンプトを送り、応答したモデルを確認するSend a prompt with Auto and check which model responded

    モデルピッカーで Auto を選び、確認用プロンプトを送ります。応答が返ったら、Auto の隣に表示されるモデル名を確認します。Select Auto in the model picker and send the check prompt. After the response arrives, look at the model name shown next to Auto.

    Auto のモデル確認プロンプトAuto model-check prompt 
    Which model handled this response? Summarize this repository's primary language and one low-risk improvement idea in three bullet points.
    Auto のモデル確認プロンプト（日本語）Auto model-check prompt (Japanese) 
    この応答を処理したモデルはどれですか。このリポジトリの主な言語と、低リスクな改善案を1つ、3つの箇条書きで要約してください。
    期待される結果Expected result: Auto の隣に、実際に応答を処理したモデル名が表示され、アカウントで利用可能なモデルと一致している。The model name that actually handled the response is shown next to Auto, and it matches a model available to your account.

  4. reasoning effort を変更し、永続化を確認するChange reasoning effort and confirm it persists

    reasoning effort のドロップダウンを Medium から High などに変更します。セッションを一度閉じて再度開くか、アプリを再起動して、選択した reasoning effort が Medium に戻らず維持されていることを確認します（v1.1.2 で修正済み）。Change the reasoning effort dropdown from Medium to, for example, High. Close and reopen the session, or restart the app, and confirm the reasoning effort you chose stays instead of reverting to Medium (fixed in v1.1.2).

    期待される結果Expected result: セッションを再開またはアプリを再起動しても、選択した reasoning effort がそのまま維持されている。The reasoning effort you selected remains after resuming the session or restarting the app.

  5. ローカル BYOK プロバイダーを追加するAdd a local BYOK provider

    Model Providers で Add provider をクリックし、サポートされているプロバイダーを1つ選び、表示名、ベース URL、API キーなど必要な情報を入力します。API キーは資格情報欄にのみ入力します。In Model providers, click Add provider, choose one supported provider, and enter the required details such as display name, base URL, and API key. Enter the API key only in the credential field.

    BYOK プロバイダー入力欄のテンプレート（実際のキーは書かない）BYOK provider field template (do not put a real key here) 
    Provider: OpenAI-compatible HTTP endpoint
Display name: local-test-provider
Base URL: https://api.example.com/v1
API key: <enter only in the Model providers field, never here>
    期待される結果Expected result: プロバイダーが一覧に追加され、そのモデルがモデルピッカーに GitHub ホスト型モデルと並んで表示される。The provider is added to the list, and its models appear in the model picker alongside GitHub-hosted models.

  6. BYOK モデルでセッションを実行するRun a session with the BYOK model

    新しいセッションでモデルピッカーからその BYOK モデルを選び、確認用プロンプトを送ります。Copilot プランがない場合でも、GitHub アカウントでサインインしていればセッションが開始できることを確認します。In a new session, select that BYOK model from the picker and send the check prompt. Confirm the session starts even without a Copilot plan, as long as you are signed in with a GitHub account.

    Auto のモデル確認プロンプトAuto model-check prompt 
    Which model handled this response? Summarize this repository's primary language and one low-risk improvement idea in three bullet points.
    期待される結果Expected result: BYOK モデルでセッションが正常に開始され、応答が返ってくる。Copilot プランの有無に関わらず動作する。The session starts successfully with the BYOK model and returns a response, regardless of whether you have a Copilot plan.

  7. 資格情報の保存場所を確認するConfirm where credentials are stored

    Model Providers に戻り、追加したプロバイダーの API キーが UI に表示されないことを確認します。OS のシステム資格情報ストアを開き、対応するエントリが作成されていることも確認します。Return to Model providers and confirm the API key for the provider you added is never shown in the UI. Also open your OS system credential store and confirm a corresponding entry was created.

    期待される結果Expected result: API キーが UI 上ではマスクまたは非表示になっており、システム資格情報ストアにエントリが存在する。The API key is masked or hidden in the UI, and a matching entry exists in the system credential store.

Verify

完了時の確認Completion checks

  • Copilot シートがある場合、GitHub Copilot が Model Providers に読み取り専用で自動表示されている。If you have a Copilot seat, GitHub Copilot appears automatically as a read-only entry in Model providers.
  • Auto を選んだセッションで、実際に応答したモデル名が表示され、reasoning effort がセッション再開後も維持される。In a session using Auto, the model that actually responded is shown, and reasoning effort persists after resuming the session.
  • 少なくとも1つのローカル BYOK プロバイダーを追加し、そのモデルでセッションが動作し、API キーは UI に表示されずシステム資格情報ストアに保存されている。At least one local BYOK provider is added, a session runs successfully with its model, and the API key is stored in the system credential store rather than shown in the UI.

Recover

トラブルシューティングTroubleshooting

有効な Copilot シートがあるのに GitHub Copilot が Model Providers に自動表示されないGitHub Copilot does not appear automatically in Model providers despite having an active seat

v1.1.2 以降であることを確認し、シートを保有するアカウントでサインインし直してからアプリを再起動します。この自動表示は v1.1.2 で追加された変更です。Confirm you are on v1.1.2 or later, sign in again with the account that holds the seat, then restart the app. This automatic entry was added in v1.1.2.

reasoning effort が resume や再起動のたびに Medium に戻ってしまうReasoning effort keeps reverting to Medium after resuming or restarting

v1.1.2 でこの問題は修正されています。アプリを最新版に更新しても解消しない場合は、セッション ID と再現手順を添えて公式リポジトリの Issue に報告してください。This was fixed in v1.1.2. If updating to the latest version does not resolve it, report it in the official repository with the session ID and reproduction steps.

プロバイダーを追加してもそのモデルがモデルピッカーに表示されないA model does not appear in the picker after adding its provider

以前のバージョンではプロジェクトやワークスペースのセッションで BYOK モデルが動作しないエラーがありました（v1.0.14 で修正済み）。最新版に更新したうえで、Model Providers に戻ってベース URL と API キーが正しく保存されているかを確認してください。Earlier versions had an error that could prevent BYOK models from working in project or workspace sessions (fixed in v1.0.14). Update to the latest version, then return to Model providers and confirm the base URL and API key were saved correctly.

Reset

クリーンアップとリセットCleanup and reset

  1. practice のために追加した BYOK プロバイダーを Model Providers から削除します。特に共有端末では削除を忘れないでください。Remove the BYOK provider you added for practice from Model providers, especially on a shared machine.
  2. 実験のために変更した reasoning effort やモデル選択を、普段使うデフォルト（Auto、Medium など）に戻します。Reset reasoning effort and model selection back to your usual defaults, such as Auto and Medium, after experimenting.
  3. プロバイダーを削除した後、OS のシステム資格情報ストアに古いエントリが残っていないかを確認し、不要であれば削除します。After removing a provider, check your OS system credential store for leftover entries and delete them if they are no longer needed.

Platforms

プラットフォーム別の注意Platform-specific notes

Windows

資格情報は Windows Credential Manager に保存されます。x64 と ARM64 のどちらのビルドでも Model Providers の操作は同じです。Credentials are stored in Windows Credential Manager. Model providers behave the same on both the x64 and ARM64 builds.

macOS

資格情報は macOS のキーチェーンに保存されます。初めてプロバイダーを追加する際、キーチェーンへのアクセス許可を求められることがあります。Credentials are stored in the macOS Keychain. You may be prompted to allow keychain access the first time you add a provider.

Linux

資格情報はディストリビューションのキーリング（例: GNOME Keyring）に保存されます。キーリングサービスが実行されていることを確認してください。Credentials are stored in your distribution's keyring service, such as GNOME Keyring. Confirm the keyring service is running.

WSL

デスクトップアプリ自体は Windows 側で動作するため、資格情報も Windows 側のシステム資格情報ストアに保存されます。WSL 内のリポジトリを扱う場合の接続そのものはガイド 08 を参照してください。Because the desktop app itself runs on the Windows side, credentials are stored in the Windows system credential store. See Guide 08 for the connection itself when working with a repository inside WSL.
