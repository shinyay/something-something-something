Copilotは、場所ごとに役割が変わる

同じCopilotでも、IDEでは実装、GitHub.comでは理解やレビュー、CLIではターミナル作業を支援します。 [2]

中心にあるのは、依頼 → 提案 → 人の検証という一つのループです。

Copilotは専門知識の代わりではありません。コードを理解し、テストし、採用する責任は利用者に残ります。 [4]

  • 書きながらIDEの補完・Inline Chat
  • まとまった変更Edit・Agent mode
  • GitHub上でChat・PR・Code review
  • 任せて追跡Cloud agent・App

最初は3つ、次に4つ

すべてを一度に覚える必要はありません。提案を受ける機能から始め、変更範囲と権限が大きい機能へ進みます。 [2]

GA / 一般提供 Preview / 変更可能性あり 利用可能・クライアント差あり 発表済み・未施行

まず使う

人が主導し、提案をその場で確認する。

  • Code completions GA

    書く。入力中にコード候補を受け取り、必要な部分だけ採用します。

  • Copilot Chat GA

    理解する。コードの説明、デバッグ、テスト案などを自然言語で相談します。

  • Inline Chat Client差

    その場で直す。選択したコードを説明・修正し、差分を小さく保ちます。

作業を広げる

複数ファイルやコマンドを扱う。必ず差分と実行内容を確認する。

  • Edit mode Client差

    まとめて編集。選んだ複数ファイルへ、関連する変更を一度に提案します。

  • Agent mode GA

    反復する。IDE内でファイル編集やコマンドを繰り返し、完了条件へ近づけます。

  • Code review GA*

    見直す。選択コードやPRへレビュー提案を返します。*GitHub.comとVS CodeでGA。クライアント差があります。[7]

  • Copilot CLI GA

    端末で進める。調査、修正、テスト、PR作成までをターミナルから支援します。[10]

委任と文脈

非同期作業や外部ツール連携。初心者は仕組みを理解してから。

  • Cloud agent GA

    Issueを任せる。クラウドで調査・実装し、ブランチとPRを作ります。旧称はcoding agentです。[8]

  • Copilot Spaces GA

    文脈を束ねる。コード、仕様、ドキュメントをまとめ、特定の仕事に沿った回答を得ます。[9]

  • Custom instructions GA

    ルールを共有。言語、テスト、命名などの期待を個人・リポジトリ・組織の指示として伝えます。

  • MCP / Skills Advanced

    能力を拡張。外部ツールや専門手順を接続します。アクセス権と送信データを理解してから使います。

モデル名は暗記しなくて大丈夫です。

対応モデルと価格は頻繁に変わります。最初はAuto model selectionを使い、複雑さ・速度・AI Credits消費を見ながら選択を学びます。

最初の15分は、小さな差分で

公式Quickstartとベストプラクティスを、失敗しにくい一連の流れへ組み直しました。 [3] [4]

00–05 min

説明させる

GitHub.comまたはIDEで小さなHTMLを開き、「この構造を初心者向けに説明して」と尋ねます。

05–10 min

補完を試す

追加したい要素をコメントで書き、提案を読みます。理解できる候補だけを採用します。

10–13 min

一箇所直す

短い範囲を選択し、Inline Chatでアクセシビリティ改善を依頼します。

13–15 min

差分を検証

変更前後を比較し、ブラウザ表示とテストを確認します。理解できなければ採用しません。

Agent modeやCloud agentは二回目以降で。

コマンド実行、複数ファイル変更、権限の意味を説明できるようになってから、任せる範囲を広げます。

良い依頼は、4つの部品でできている

複雑な仕事を分け、要件を具体化し、例と完了条件を渡すほど、提案を評価しやすくなります。 [4]

  1. 文脈対象ファイル、現在の状態、関係する仕様
  2. 目的誰の、どんな問題を解決するか
  3. 制約変えてはいけないもの、技術・品質の条件
  4. 完了条件テスト可能な結果と確認方法

「うまくいかない」時に最初に変えること

タスクを小さくし、関係するファイルだけを開き、期待する入力と出力の例を一つ渡します。長い会話で文脈が混ざったら、新しい会話からやり直します。

結果が長すぎる時の頼み方

「まず計画だけ」「変更対象を3ファイル以内」「差分を小さく」「判断が必要なら実装前に列挙」など、進め方そのものを制約にします。

Custom instructionsを使うタイミング

同じ命名、テスト、言語、レビュー基準を繰り返し伝えているなら、個人・リポジトリ・組織の指示へ移します。指示が実際のツールやポリシーと矛盾しないことも確認します。

GitHub Enterprise Server（GHES）で使えますか？ Technical Preview例外

通常のGitHub CopilotプランはGHESでは一般提供されていません。例外として、GHES 3.22 Release Candidateには、管理者がモデルプロバイダーを設定するCopilot CLI限定のTechnical Previewがあります。これはCopilot全体のGHES対応ではありません。 [20]

採用の前に、人のゲートを置く

Copilotの提案には誤り、脆弱性、保守しにくいコード、公開コードとの類似が含まれる可能性があります。 [4]

  1. 秘密を入力しない鍵、トークン、個人情報、許可されていない未公開コードをプロンプトへ含めません。
  2. 差分を一行ずつ読むCopilotが変更した意図と、変更していない範囲を自分で説明できる状態にします。
  3. 実行して確かめるテスト、lint、code scanningなど、既存の品質ゲートを省略しません。
  4. 公開コードとの一致を確認するCode referencesや組織のポリシーを確認し、必要なライセンス判断を行います。[17][18]
  5. Content exclusionを過信しない機能やクライアントによって適用範囲が異なります。秘密管理の唯一の防御にはしません。[16]
  6. 組織のルールを優先する利用可能なモデル、機能、送信先、保持条件は契約と管理者設定で確認します。[19]
「生成されたから安全」でも、「フィルターがあるから安全」でもありません。

GitHubも、提案を理解し、レビューし、自動テストやセキュリティ検査を使って確認することを推奨しています。[4]

迷った時の用語集

似た言葉は「どこで、どこまで動くか」で区別します。

Copilot Chat

コードやリポジトリについて会話する機能。IDE、GitHub.com、Mobileなどで利用します。

Agent mode

IDE内でファイル編集とコマンド実行を反復するモード。実行前の確認や権限設定が重要です。

Copilot cloud agent

GitHubのクラウドでリポジトリを調査・変更し、ブランチやPRを作るAgent。旧称coding agent。

Copilot Spaces

コード、仕様、文書などを集め、特定の仕事に必要な文脈として再利用する場所。

MCP

Model Context Protocol。Copilotから外部ツールやデータへ接続する仕組み。接続先と権限を確認します。

Custom instructions

言語、スタイル、テストなど、応答へ反映してほしい継続的なルール。

GitHub AI Credits

2026年の利用量ベース課金で使う単位。モデルとトークン量により消費量が変わり、1 Creditは$0.01 USDです。

GA / Public Preview / Technical Preview

GAは一般提供。Public Previewは公開試用、Technical Previewは技術検証段階で、後二者は仕様変更の可能性があります。
